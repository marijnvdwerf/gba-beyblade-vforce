# agbcc matching bible

Core truth: **recover the C the original programmer wrote.** Equivalent C is not equivalent code: types, live ranges, expression trees, control flow, and address materialization all steer deterministic agbcc output. Fix the first divergent instruction; later branches, pools, and addresses are usually downstream noise.

## Off limits and C90

- No `goto`/labels, register pinning, or inline assembly; a match forced with them is not recovered source.
- Bare compound scopes, multiple named aliases of one value, and pointer-domain rewrites of integer zero tests are prohibited matching levers. A match that requires one is a failure to park, never source to ship; ordinary `if`/`switch`/loop compound statements and aliases with genuinely distinct semantic roles remain valid.
- Declarations precede statements; normally prototype calls, cast pointer↔integer conversions, never dereference `void *`, and keep unused parameters. Preserve a measured legacy cross-TU declaration view when forcing one shared prototype changes bytes. Break header cycles with forward declarations; keep a ROM-table `extern` in the sole consuming `.c` when possible, and never hide a prototype behind a conditional include guard.

## Types, widths, and signedness

- Read expression type from loads, shifts, and branches together; one mnemonic proves the operation there, not necessarily the declaration.
- `asr`, `ldsh`/`ldsb`, and `bge`/`blt`/`bgt`/`ble` → signed; `lsr`, `ldrh`/`ldrb`, and `bhs`/`blo`/`bhi`/`bls` → unsigned.
- When consumers of one halfword field include both `ldrsh` and `ldrh`, the signed load is positive evidence for a signed declaration even if other contexts zero-extend it; do not decide by majority opcode alone. Byte-required mixed access can occur in one function: a decrement or arithmetic source may use `ldrh`, then a signed nonzero/order test of the updated field may reload it with `ldrsh`.
- `lsl #16; asr #16` versus `lsl #16; lsr #16` → signed versus unsigned halfword normalization; `#24` pairs do the same for bytes. Keep a per-use cast when removing it deletes a measured normalization pair.
- Preserve exact casts when compare proves the operation: an unsigned word view can keep `lsr #31` or `lsr #30` instead of `asr`, a signed-halfword cast can keep `lsl #16; asr #16`, and an unsigned-halfword cast can keep `lsl #16; lsr #16`.
- For a signed value checked against one contiguous range, try `(unk32)(value + K) > L`; the cast after the add preserves signed arithmetic but selects the target unsigned range branch. An explicit pair of signed bounds can compile identically, so retain the clearer exact form.
- Default to `unk8/16/32`; use signed types only on evidence, because one wrong sign produces one wrong branch or shift opcode.
- Narrow locals insert normalization pairs; wide locals remove them. A plain `int` index often matches where `u8`/`u16` adds masking.
- Narrow locals are HImode/QImode pseudos that re-extend on every read. For a loaded signed halfword, an `s16` local lets combine fold the extension back into one `ldrsh` placed at the value's first use (the loads sink toward the consumer), while an `s32` local keeps each `ldrsh` at its assignment; choose by where the target's loads sit.
- A dedicated `unk16` conversion temporary can preserve zero-extension and keep a narrowed compare value separate from its wide source; a wider temporary may coalesce them and change saved-register allocation.
- Cast placement is conversion placement: keep a producer wide and cast or assign narrow only where the target performs the conversion. A narrowing cast in a comparison adds normalization before `cmp`; if the target has only arithmetic plus `cmp`, keep the count/index wide there.
- Staging a narrow field in a signed `s32` temporary can keep arithmetic wide and delay normalization until the result is narrowed; using the field directly may reorder the add or conversion.
- Entry normalization proves narrowing at entry, not a narrow formal parameter; try a wide ABI parameter assigned or cast to a narrow local. Conversely, a genuinely narrow formal tested for truth can emit the low-byte shift/test at entry without explicit source shifts. Caller-side `lsl #24; cmp` can be the truth test generated by an `unk8` return prototype, and a discarded `s16` result can leave a dead `lsl #16`; declare the measured return width and never transcribe either shift. One `s16` formal can serve both views: its single entry `lsl #16` feeds `lsr #16` for halfword stores and `asr #16` for a promoted compare.
- Promotion chooses shifts: an unsigned intermediate yields `lsr`, while a signed intermediate yields `asr`, even with identical stored width.
- Keep a measured `(unk8)` conversion on a derived table index. In particular, `(unk8)((wide >> K) * SCALE)` can preserve a second truncation/scale shift sequence that an explicit mask or wider index changes, even when the decoded index is equivalent.
- For direct tests of an inverted 16-bit hardware register, keep a measured `(unk16)` on each expression when it preserves separate mask materialization and a register copy before comparison; removing it or caching one narrow local can reshape the branch, loop, pool, and function size.
- Lvalue type normally selects `ldr`/`str`, `ldrh`/`strh`, or byte access, but agbcc can narrow a wider field load when assigning directly to a truncating local. A word field read into an `s16` can emit `ldrh` while retaining the word-style base-plus-offset address tree; test the declared field width separately from the emitted load width.
- A cast that changes a field read from zero-extension to sign-extension (or vice versa) proves the view needed by that consumer, not automatically the canonical declaration. Prefer the declaration proven by established users; retain a per-use cast only when a controlled comparison proves the alternate signedness access.
- Byte-required: for a halfword all-ones initialization whose target is `ldrh; orr; strh`, write `field |= -1`, even when the established field is `unk16`. A plain store or positive `|= 0xFFFF` can optimize away that read-modify-write, while explicit signed read casts can become the wrong source shape.
- Do not retain a dead assignment from a field merely to steer signedness; correct the field type and remove redundant read casts when the rebuilt users remain exact. Replacing repeated per-read signed casts with a proven signed declaration can also change fold association and make a different, more natural parenthesization match, so re-test expression trees after a safe retype.
- agbcc can emit `ldrsb`: a signed `*ptr++` directly in a loop condition or call argument may select `mov #0; ldrsb`, while staging the read and increment separately can select `ldrb` plus sign-extension shifts. Preserve the dereference context instead of assuming signed-byte loads always lower one way. For an array tested against a negative byte sentinel, a target `ldrsb` versus the measured unsigned trial's `ldrb`/`#255` is positive evidence that the elements are `s8`.
- A return prototype drives caller normalization, while the definition's declared return type shapes the callee. A byte local returned through `unk8` can truncate for free with no callee normalization; a byte-returning inner call can also leave `lsl/lsr #24` inside a wrapper whose own return is widened. When the body must stay wide, an `unk32` return plus a block-local `unk8` at each testing caller can instead be byte-required. Return width can even choose operand order in a later commutative `add`; diagnose caller and callee diffs separately.
- Decide parameter widths from matched callers as well as the definition. A caller-side `lsl #16; lsr #16` immediately before a call is positive evidence for an `unk16` prototype. Conversely, passing one wide `unk32` parameter directly to several `u8`-parameter callees can generate the target retained `lsl #24` plus per-call `lsr #24`; explicit source shifts or narrowing the caller formal can both diverge.
- Byte-required: when `x >> 8` is passed to an `s16` parameter, let the call conversion supply the halfword normalization; it can be byte-identical to source `(x << 8) >> 16` and emit the required `asr #16`. Do not transcribe the compensating shifts before testing the narrow prototype.
- Pointer→integer conversion and an integer identity cast can create different RTL despite both being 32-bit; preserve the proven type. For a pointer known to be `NULL`, `(unk32)ptr` as a call argument can change allocation even though plain `0` is byte-identical to the target in another call; use the simplest measured form for that site.
- Soft-float conversions follow the integer type: an `s32` operand calls `__floatsisf` directly, an `unk32` operand adds the unsigned `cmp #0; blt` correction path around it, and a float assigned to an unsigned integer calls `__fixunssfsi`. To convert a zero-extended halfword on the signed path, assign `(unk16)x` into an `s32` local; `unk16` and `unk32` locals each selected a different conversion.

## Locals and register pressure

- Read the prologue, push mask, frame size, and which value is spilled first. If the draft saves more registers or has a larger frame, suspect an unintended cached alias or extra live pseudo; if the target saves more or has a larger frame, recover the missing long-lived value or explicit stack lifetime before chasing downstream instructions.
- Values live across calls prefer callee-saved registers or spills; one extra live value across one call can change the push mask or spill slot. Keep a derived address in a callee-saved register only when it is reused across the call; a single post-call use can be recomputed ephemerally. A target that retains a value where the draft reloads it points to a missing source lifetime.
- Keep explicit cursor/count/end temporaries when the target keeps distinct values, including separate count and loop-limit copies when the bound occupies a different register; remove them when the target reloads or coalesces instead.
- A separate successor temporary can keep a moving cursor and freshly loaded pointer in distinct registers: `candidate = cur->next; next = candidate;`.
- A scalar temporary can force one field/byte load that is reused by multiple tests, or place that load before a later initialization; removing it may duplicate or reorder instructions. Reloading the same temporary from a global before each phase can also be byte-required to recover each phase's allocation; do not hoist one earlier value across the phases. Conversely, repeating the same shifted or narrowed expression at each call site can be byte-required when caching it changes normalization or instruction order.
- Open problem: reading a byte field once into a temporary can produce one signed load and reuse, while rereading the field can produce an unsigned load plus later normalization; if natural lifetime variants do not match, do not turn this observation into a field-typing rule.
- A separate result or magnitude temporary can preserve the original argument for a later sign test while the transformed value occupies the return-value path; an in-place rewrite changes that dataflow.
- Assignment and initialization order set live-range boundaries and address-materialization order; spell them in target order. An incoming-parameter alias can leave the characteristic `mov sl, r6`; keep that alias when folding it changes the prologue.
- Parameters are ordinary pseudos. Updating one in place (`x &= 7; … x <<= 2;`) writes each result back into its register and can be byte-required where a fresh local adds a spill; conversely, stepping a parameter as a loop variable gives it a fresh pseudo, while `for (cur = param; …)` lets the parameter coalesce with its incoming register. When the target spills an incoming parameter in the entry block, the source used the parameter itself — any typed copy moves the spill.
- In `.greg`, `global_alloc` sorts allocnos by the truncated integer `floor_log2(n_refs) * n_refs * size / live_length * 10000` (references weighted by loop depth) and hands out registers in that order; measured orders follow it exactly. `uv run tools/asm-annotated.py src/<tu>.c <func>` prints each pseudo's `used R times across L insns` and the sorted allocno list; `--all-passes` adds `.rtl`/`.cse`/`.loop`/`.combine` dumps. Declaration order does not change priority (hundreds of permutations measured byte-identical); it only breaks exact ties — pseudos are numbered in declaration order, so the first-declared of two equal-priority values takes the lower high register — and can order spill slots.
- For a pure register-role swap, compare `.greg` first. Scopes, signedness sweeps, and spellings that leave the insn stream unchanged cannot move refs or live lengths. Measured levers that do: (a) write a statement in both arms of an `if/else` or `else if` chain (a store, an increment, an assignment) — the extra weighted references can cross a `floor_log2` step, and cross-jumping after reload merges the copies back into one instruction, so only the allocation changes; (b) move an assignment earlier or later to shorten one value's live range (e.g. compute both loop counts before the first loop); (c) a real CFG difference such as separate early returns versus one combined positive guard, which changes the allocno set. If the same swap survives those natural probes, park it rather than churning permutations.
- A switch/if-arm-local pointer or arithmetic temporary defers pseudo creation and lets local allocation reuse that arm's load register; hoisting one shared local can change dispatch allocation or turn an in-place `add` into a three-register form. Use only scopes belonging to real source control flow; standalone bare lifetime scopes are prohibited.
- Reuse one compatible local across similar loops when the target preserves one pseudo/register history; separate locals may reshuffle both loops.
- Conversely, keep initial-pointer and mutable-cursor locals separate when the target keeps both roles live in different registers; the same applies to table-base pointers and their indexed row pointers when the target retains distinct address-calculation roles.
- A redundant-looking temporary — including a local alias of a global pointer or a separate `size`/count local — can add the exact pseudo pressure needed, or an unwanted save; keep it only when the target proves the distinct lifetime, and judge it by the prologue and first divergence.
- Fold-test every temporary and alias, including single-use call results, direct field values, successor pointers, and cached subobject addresses; remove it only when the build is byte-identical. Multiple aliases that merely snapshot the same state are a failure signal, not a matching technique. A single-use alias can still reorder address materialization, and alias removals interact, so one failed simplification may match after another alias is removed.
- Early `result = 0` or a real 0/1 flag can reproduce early return-register setup and later separate tests; do not fold proven source state away. A flag set only on an exit arm can look never-set in final asm: CSE jump-following may thread `done = 1` directly to the exit and delete the assignment while leaving the initialized flag and loop test. Keep a measured predicate-result temporary plus a later copy into the output flag when direct assignment changes the prologue, frame, or duplicated-arm allocation. Initialize such a flag before any guard that dominates the loop: moved inside the guarded block, agbcc proved it constant and folded the loop into an infinite one.
- Byte-required dead-store signature: an assignment of a selected value to a variable that is overwritten before any source-level read can still make each arm produce the value in `r0` and add a join `mov` into a saved register; removing it lets the arms load directly into that saved register.
- Byte-required dead-load signature: recomputing a loop bound immediately before a later loop can move the loop's zero initialization after the bound loads and prevent entry/bottom-test cross-jumping; removing the unused load can leave `mov #0` followed by a branch to the shared bottom test. Preserve only when the compare proves this schedule.
- Retain staged coordinate/extrema values when folding changes allocation: measured byte-required classes include signed wide coordinates loaded before delta math, endpoint coordinate snapshots, root and nested min/max/midpoint locals, a separate tree-walk cursor alias, and width/height shift temporaries that preserve prologue or stack-argument offsets.
- In collision-response families, preserve measured endpoint-coordinate locals, a restitution temporary, duplicated response arms, a final dead-looking completion-flag assignment, and distinct broad-bound versus rectangle-bound stack slots; folding or sharing these can change the frame at the prologue or allocation late in the function.
- Keep duplicated branch/case-local calculations or stores when hoisting changes dispatch liveness, branch layout, or address lifetimes; identical semantics do not imply a shared source block. This includes paired overlap tests or depth-order arms whose factored predicate changes allocation even when every calculation is equivalent. A value assigned once before an `if/else` can be CSE'd onto an existing pseudo, whereas the same assignment written in both arms creates a real join copy; an explicit `else` repeating a store likewise stopped global CSE from keeping a sign-extended copy alive across the function (one fewer saved register).
- Byte-required local state can be more compact in source than separate scalars: a local struct of byte-based one-bit flags can preserve a smaller frame and repeated mask/store sequences where ordinary flag locals enlarge the frame.

## Expressions and store shape

- Stage pointer arithmetic when asm stages base, displacement, and scaled index separately; a folded expression invites reassociation or indexed loads. Write `base + (offset + constant)` when the target computes one displacement before adding the base; unparenthesized left-to-right addition emits incremental adds. A bumped cursor can also differ from `base[0]`/`base[1]`: CSE may retain `(plus P const)` for direct stores but a cursor's register equivalence can make `find_best_addr` recover the frame-relative address and change allocation.
- Typed-pointer addition scales by the pointed-to type; a `base + i * SIZE` walk is an array of SIZE-byte structs — declare it and index, never `(unk8 *)` arithmetic in final code. A row-typed pointer can replace explicit `i << K` addressing byte-identically, including transfer lengths written as `n * sizeof(Row)`.
- When allocation code must keep a byte product live, typed `nodes + count` can introduce another stride multiplication and alter stack-argument allocation. Retain a byte-addressed allocation base plus the computed byte-count local and cast only at typed assignments when that is the measured match.
- Runtime offset tables into packed or variable-size blobs legitimately use `(unk8 *)base + offset`; do not force them into fixed-stride arrays. Under `agbcc -O1`, a staged typed pointer followed by byte stepping through GNU lvalue casts can be byte-required: `(unk8 *)ptr += offset; ((unk8 *)ptr)++;` preserves pointer-first address-tree and `add` operand order where typed addition or a direct casted initializer does not.
- Commutative operand order is visible in load and `add` order; write the target's expression-tree order. In OR chains, agbcc's `associate` pass can pair a constant with a different variable depending on which operand subtree splits, so lexical order and parentheses can change load order and allocation.
- agbcc's front-end `fold` reassociates within one expression tree, never across statements. Measured rewrites: `(A + C) - B` → `A - (B - C)`; `a - (b - 1)` → `(a + 1) - b`; `A - (B + K)` → `(A - K) - B` for any constant `K`, even as `x -= B + K` — the negated constant can leave the `imm8 << n` range and come from the literal pool; `(x & C) & y` → `x & (y & C)`, which hoists `y & C` as a second invariant; `t[i + K]` folds the scaled `K` into the displacement; `(x * 2) / 2` cancels. When the target keeps the written order, split the step into its own statement, use a compound assignment (`b += 8 - r` keeps `(b + 8) - r`), or hold the subexpression in a variable (`c = B + K; a -= c;`).
- `field += expr`, compute-then-assign, and read-modify-write through an explicit accumulator are distinct source shapes. Keep the direct compound assignment when staging `expr` reverses a post-call object reload and scalar-global address load.
- To force store-base evaluation before a value expression, use `target->field = expr; local = target->field`; the measured store-then-readback shape loads the target base first, unlike precomputing a local and then storing it.
- Preserve constant placement around masking: adding `0xC8` before `& 0xF` can lower differently from adding the congruent `8`; do not reduce constants modulo the later mask unless compare proves it neutral.
- Precomputing one branch's value, conditionally overwriting it, then storing once produces a different CFG and store shape from an `if/else` with a store in each arm. A direct conditional expression `x = condition ? a : b` often folds temporary selection byte-identically; prefer it only after compare, because final store placement can still require a staged local.
- Keep a measured assignment inside a call argument, such as `call(..., frame = x - 1)`: moving it to a preceding statement can shift address materialization and normalization far earlier in the arm.
- A pre-decrement embedded in an array subscript can reuse the wide subtraction result for both the field store and index, forcing byte normalization before scaling; a separate decrement followed by a byte reload may collapse to a simple scaled index.
- Byte-required: keep a postfix increment embedded in a narrow array subscript when the target normalizes and uses the old index before storing the increment; splitting the read, increment, and store can remove the normalization and change register roles.
- Straight-line struct initialization preserves lexical store order. Even a two-target chain `a = b = 0`, and especially a longer chain, can stage every lvalue address first and then store right-to-left while keeping the value live; splitting it changes the address/store schedule or adds moves. Likewise, keep a measured nested allocation assignment such as `(p = alloc())->field = value` when splitting it changes the result register.
- `*out++ = value` can select `stmia`; a separated store and increment selects `str` plus `add`. Keep postfix cursor increments inside multi-byte shift/or expressions when measured: separating the byte loads and increments changes address lifetimes, operand registers, and store order.
- A target induction initialized to `-stride` may be strength-reduced `array[i - 1]`; try the indexed source before preserving a negative cursor.
- Constant spelling matters only when measured: staged forms such as `mask = 1; mask = -mask;` can force `mov`/`neg`, and a named multiplicative constant can preserve a real `mul` where the same literal strength-reduces into shifts/adds. An unsigned `% 2` test can retain an SImode mask and materialize a fresh `#1` where `& 1` reuses a neighbouring HImode constant; keep the odd spelling only for that measured mode/CSE signature. Fixed-point-equivalent forms can also differ: `(table[i] * 0x20) >> 8` may preserve a signed load plus `asr #3` shape that direct `table[i] >> 3` does not. Conversely, shift-spelled constants such as `(0xC0 << 5)` have compiled identically to the plain literal; use the readable literal when compare proves it byte-neutral. Byte complements differ too: `(unk8)~x` → `mvn; lsl #24; lsr #24`, `~x & 0xFF` → `mvn` plus a mask, `x ^ 0xFF` → `eor`.
- Preserve add-versus-subtract spelling for constants: `frameCount + 0xFFFF` is not interchangeable with `frameCount - 1`; old agbcc can materialize and combine them differently. Keep a measured trailing `& 0xFFFF` around a halfword-valued expression when it forces HImode, blocks full-word OR reassociation, and preserves allocation or pool alignment.
- Signed `a * b / 256` truncates toward zero: agbcc can lower it as `mul`, copy/test the product, add `255` only when negative, then arithmetic-shift by eight. To retain the copy, assign the quotient back to the same source object in a separate statement (`p = a * b; p /= 256;`); a distinct quotient pseudo or division in the return expression can coalesce it away. With an `s16` result, the divide and narrowing may combine into `lsl #8; asr #16`.
- Treat extraction shifts as evidence to test a bitfield declaration, not proof that the source spelled shifts. Measured reads are: bit-0 `u8 : 4` → `ldrb; lsl #28; lsr #28`; bit-4 `u8 : 4` → `ldrb; lsr #4`; bit-0 `unk16 : 10` → `ldrh; lsl #22; lsr #22`; bit-10 `unk16 : 6` → next-byte `ldrb; lsr #2`; and `s16 : 4; s16 field : 12` → `ldrh; lsl #16; asr #20`. Splitting a wider byte bitfield into individual one-bit fields can turn extraction into the target raw `ldrb; and` bit test. Keep whichever declaration compare proves. A 1-bit field at bit 1 reads as `ldrb; lsl #30; lsr #31`, which no mask/shift spelling of a plain byte reproduces (`(x >> 1) & 1` gives `lsr; mov #1; and`). `optimize_bit_field_compare` lowers a bitfield compared against a constant back to `ldrb` plus a mask test, so rewriting existing mask tests as bitfield tests is byte-neutral.
- For bitfield writes, expect allocation-width read-modify-write: mask the input, preserve other bits, merge, and `strb`/`strh`. A halfword preserve mask may appear as `mov #16; neg`. Compound `|=`/`&=` first extracts the field, applies `orrs`/`bics`, remasks, preserves, merges, and stores; it is not equivalent codegen to assignment or a whole-unit operation. On an ordinary byte field, a constant clear such as `x &= ~1` narrows to QImode `#254`; a tree-level variable mask or a one-bit insert stays SImode and can emit `mov #2; neg; and`. Do not replace a proven one-bit field with a whole byte merely because its reads match: whole-byte `store_bit_field` uses insert mask `0`, which CSE can donate to a neighbouring `= 0` byte store and thereby change zero placement and allocation, while one-bit masks are `-2`/`-3`. An exhaustive measured spelling/interleaving sweep found no plain-integer reproduction for this case. For an ordinary packed flag word, split `x &= ~mask; x |= bits;` can be byte-required even when the first store disappears: its intermediate pseudo can leave a callee-saved high register pushed but unused. The field assignment masks the value itself; an explicit source mask before it changes the mask construction (`mov #4; neg` became `sub #7`).
- Declare proven bitfields directly in the containing struct and name unknown fields `unk<BYTE_OFFSET>_<START_BIT>`. agbcc's `STRUCTURE_SIZE_BOUNDARY` is 32: every non-packed struct is a multiple of four bytes, so a nested struct of byte bitfields (even with a `u8` base) or a two-byte struct array element (stride 4) is four bytes; inline the fields into the containing allocation unit when one byte is required. Verify `sizeof` and following offsets. When every bitfield in one byte is assigned zero through one chain, agbcc can collapse the chain to one `mov #0; strb` whole-byte clear.
- If a high-register value is compared with an immediate, Thumb may materialize the constant in a low register for register-to-register `cmp`.
- agbcc CSEs loads, merges shifts/blocks, and reuses related constants. Preserve statement boundaries when the target does: `value *= 10; value += digit - '0';` can avoid reassociation and CSE reuse that every equivalent one-expression digit accumulator triggers. Signed `s32` arithmetic can keep `a * 2 + b * 2` as two shifts where unsigned `unk32` permits `(a + b) * 2`; use the measured signedness when the target stays unfolded.
- Array decay produces an address while `array[0]` produces a scalar load; choose the shape shown by the target.
- Let typed indexing expose cancellation between an explicit element-size division and the compiler's implicit scale; manually replacing it with shifts and masks can prevent simplification and add instructions. Natural subtraction between typed pointers already divides by the element stride and can lower with `asr`; when the target needs unsigned `lsr #N`, subtract `(unk8 *)` addresses, convert the byte difference to `unk32`, then shift once.
- With a non-constant index, `a[i]` expands as `*(&a[0] + i)`: the base plus any member offset is formed first, so for an embedded array member the offset becomes a loop induction variable's initial value (`add rN, #off` in the preheader, then `[rN, #0]`), whereas `*(p->arr + i)` or `ptr[i + k]` on a pointer variable goes through `fold`, keeping constants in the load displacement. Tables split the same way: a global array subscript forms base and index in written order, while `*(tableLocal + expr)` lets fold collapse index arithmetic (`((a >> 1) & 0xFF) * 2` → `a & 0x1FE`). Repeating an index expression at each subscript lets expansion load the table base before the index and CSE merge the normalization; caching the index in a statement moves the pool load after it.
- Bit extraction and mask tests are not interchangeable: `(x >> 4) & 1` preserves a shift-plus-`and` shape (with `asr`/`lsr` selected by type), while `(x & 0x10) != 0` favors a direct mask/test and can change the CFG. Mask-before-shift `(c & 0x3E0) >> 5` keeps the masks as loop-invariant constants agbcc hoists into registers; shift-then-mask does not.
- Open problem: a target full-width nonzero test may use branchless `neg; orr; lsr #31`, while natural `!= 0` and Boolean forms emit `cmp`/branch/constant selection. The arithmetic identity `((0 - value) | value) >> 31` reproduces the bytes but is an approved fakematch, not a general source-recovery recipe.

## Loops

- `while (n-- != 0)`, decrement-before-test, `do/while`, and top-tested `while` are distinct and can be byte-required even when they visit the same elements; a separate entry guard must remain when present and can make a following `do/while` semantically correct while changing prologue allocation.
- Byte-required: signed and unsigned post-decrement can differ even when both end in `bne`. An `s32` count parameter or local in `while (count-- != 0)` can preserve `old = count; count--; cmp old, #0`, while an unsigned count becomes decrement-then-compare-against-`-1`. Test both, retain any separate entry decrement/guard shown by the target, and use explicit `previous = count; count--;` only when the old-value comparison is separately required. Compare can require the `s32` form even when no signed mnemonic survives; treat that as measured lowering/allocation evidence, not semantic signedness proof.
- `u32 n = count; while (n--)` naturally yields a compare-against-`-1` countdown and fits counted list walks; do not hand-write the sentinel unless the diff requires it.
- Variable-size record walks should advance by the current record's runtime size, e.g. `ptr = (Record *)((unk8 *)ptr + ptr->size)`; array indexing falsely implies a fixed stride and changes liveness.
- Loop reversal accepts signed `<`/`<=` forms and can turn an ascending clear loop into a pointer countdown; unsigned `<` and `!=` generally remain ascending. Recover the ascending source when its reversed pointer compare matches instead of transcribing the countdown.
- Do not assume an eligible ascending loop actually reverses; if experiments stay ascending, retain the explicit matching countdown source. Likewise, keep a proven descending index with a forward-moving cursor when indexed or ascending rewrites produce a different loop.
- A target rotated search CFG may not come from plain `while` or `for (;;)`; spell the entry test and bottom break explicitly when proven. Keep a terminal `if (next != END) advance; else break;` rather than an early `if (next == END) break;`: the positive arm lets agbcc share the initial and successor address calculations.
- Byte-required: when a search tests the current element before its bound, preserve that operand order as `while (element != wanted && index < count)`; putting the bound first changes the loop CFG and load order.
- If the target reloads a global loop limit each iteration, keep the global expression in the condition instead of caching a local bound. A hoisted bound still shows its spelling: a member expression `i < p->q->count` in `for`/`while` is loaded by LICM after the copied entry test (its spill store follows the guard), a cached local is loaded before the guard, and a guarded `do/while` keeps the reload inside the loop. An inline `i < start + n` is duplicated for the entry guard, hoisted, and CSE'd into a register copy (an extra `mov`), while a precomputed end local is two bytes shorter; an inner loop's inline bound is hoisted only to the top of the outer body.
- The loop preheader emits source statements in order first, then hoisted invariants in order of first use (`move_movables` inserts them just before the loop start), so no source spelling places a hoisted constant ahead of a preheader statement. agbcc hoists mask constants by itself; literal-valued mask locals are unnecessary. An inline invariant subexpression is hoisted separately into each loop's preheader, where a local computes it once; a variable assigned several times inside a loop is not hoistable, while distinct variables are.
- `for (init; cond; step)` is byte-identical to a top-tested `while` with a trailing step, and `i < N` to `i <= N - 1`; a project-wide `do/while` → `for`/`while` flattening pass was free for most loops. Byte-required exceptions from that pass: a duplicated or explicit entry guard in front of a loop, a dead `i = 0` before a loop, a staged `count--` before a loop, and indexed rewrites of an offset/pointer walk (a down-counting `&p[total - count]` was two instructions off in init order). Moving body increments into a comma update (`i++, p++`) reorders them; nested `do` loops and nested top-tested `while` loops can allocate differently.
- When an outer cursor must die across an inner callback loop, keep path-specific increments on each lookup exit. One shared bottom increment can become a `ldmia`-adjacent biv update and keep the cursor live in a saved register; separate increments can force the target spill and still cross-jump failed exits.
- When a fixed small sequence appears as individual calls or stores, write it unrolled; a source loop can introduce induction registers or `stmia`/`ldmia` combining that the target lacks.
- Open problem: a target may reload a non-volatile struct field every iteration despite no call or aliasing store, while plain C hoists it. `volatile` can reproduce the reload but is not canonical; treat this as unresolved rather than a general typing rule.
- Moving an increment or decrement into or out of a branch changes the CFG even when semantics agree. In particular, keep a countdown update after an early-return arm inside the branch that continues the loop rather than hoisting it before the branch. Duplicating an increment on an early-`continue` path or in each arm is the allocation lever described under locals.

## Switches and branches

- Condition spelling picks branch polarity, fall-through, and tail merging: early return, nested `if`, nested `?:`, an equivalent combined Boolean, and result-variable forms are not interchangeable. Keep a measured nested-ternary condition when flattening it changes bytes. `if ((x = global) != 0)` creates a copy pseudo and can emit `mov` before `cmp`, unlike separate assignment and test. When the target has a branch ladder feeding one shared body, preserve that nesting and shared-body placement. Keep separately written null guards or nested conditions when short-circuiting or combining them changes branch layout or merges duplicated call arms. A redundant null guard around a terminal call can be byte-required even when jump threading removes its test: the surviving RTL `use` can lengthen one pointer lifetime by one instruction and flip allocator priority. The same copy appears when a cached count is assigned inside a guard or clamp condition rather than before it. Early returns for each failure (invalid index, missing record) recover a backward-shared return tail; nesting the success path under guards duplicates the tail.
- In old GCC, a value-less `return;` in a non-void function can reproduce fall-through to the epilogue with `r0` still holding the just-tested value; use it only when that undefined return path is proven by the target.
- Preserve redundant-looking compares when present; identical function size alone does not validate branch targets.
- Switch case count controls lowering and block layout. Treat a sparse literal compare chain as a source-level `switch` candidate; agbcc may emit `cmp; beq; cmp; bcc` rather than a table, and the `bcc` proves the compared dispatch operand is unsigned. For a jump-table switch, agbcc sorts table entries by selector value but emits case bodies in source order, so order the source cases to match the target's body layout. An otherwise empty high case plus `default` can cross a threshold where agbcc pivots on a middle value and uses an unsigned range branch for lower cases. An explicit `case 0:` beside `default` changes the comparison tree; without it the remaining cases formed a balanced tree.
- Identical case bodies may merge; an unsigned normalized dispatch expression can sometimes restore the expected table form. Conversely, write measured identical tails in the separate case arms and let agbcc cross-jump them naturally; factoring the tail or adding a source `goto` can change allocation and layout. Grouped case labels sharing one body collapse to a range compare, while separate arms with identical bodies can keep a jump table with duplicate entries. An unreachable `return` after an exhaustive switch folds away; turning terminal returns into `break` can merge cases too early.
- If each switch arm loads a global only after dispatch, use case-local aliases or direct global access; a shared pre-switch alias changes dispatch liveness and load order.
- Register-only divergences repeated across several cases usually point to lifetime or ordering: a temporary is scoped per case instead of hoisted (or vice versa), or two independent statements are lexically swapped.
- A search whose success/return block is hoisted above the loop usually comes from a plain top-tested `for` with an early `return` inside (and any `NULL` guard as an early return before it); try that before a `found` flag + `break`. Elsewhere, retain a measured `if (i < n) do { ... } while (...)` entry guard when plain `while` changes block layout; do not choose either form by style alone.

## Pointers, globals, and aliasing

- Direct global access can still leave `&global` live in a saved/high register; do not invent a pointer-to-global alias merely to explain reuse. A dead assignment of a global pointer value to an unused local can lose the memory load during flow while leaving its early symbol-address pseudo available to later direct global accesses; retain that debugging leftover only when removal changes the measured address schedule.
- A proven struct-pointer type can change alias analysis enough to reload a global's address where `void *` caches it across calls or loops; preserve the strongest justified pointee type before adding lifetime tricks.
- For a byte cursor over variable-size records, fold-test a loop-top typed-record alias: it can add a saved register where repeated typed views of the cursor match. Byte-required payload indexing may instead need a typed pointer local created only in the success arm.
- Keep `base = global` when the target loads it before clamps/branches or keeps derived addresses live; otherwise test direct global access first.
- Decisive test: a global pointer's *value* still in a register after a `bl` (no reload) ⇒ the source copied it into a local before the call (the compiler may not keep a global live across calls). A fresh `ldr` of the global after each call ⇒ direct `global->` access.
- Cache only the expression whose lifetime is proven; mixing a scoped local with direct accesses can preserve both a distinct value and target reloads.
- If the target reads a scalar field directly before later taking its address, preserve that order; taking the address first can hoist the derived pointer into a loop preheader.
- If one aggregate supplies several nested subobject addresses across calls, cache its pointer and any proven embedded-record pointer; folding a record alias back into its parent can change the prologue even without calls. A cached pointer to an embedded global subobject can also be required solely to preserve separate `global + memberOffset` base formation plus a later field displacement instead of one folded interior literal.
- A `strb` through a typed object may force later global-pointer reloads because agbcc treats byte stores as broadly aliasing; do not use `volatile` to fake it.
- Long-lived global addresses consume callee-saved registers and can push incoming arguments into higher registers; preserve the source access pattern.
- Global addresses may be loaded separately or derived from a nearby loaded address with `add`/`sub`; mirror whichever shape the target shows.
- Taking `&global.member` can fold the symbol plus member offset into one literal-pool relocation. Loading a member at a large offset instead typically materializes the global base and a second offset literal before the load; small encodable offsets hide this distinction.
- A direct literal for an interior address is therefore not evidence of a separate global. Typed record/subobject aliases such as `T *record = &table[i]` or `T *part = &aggregate.member` are legitimate source when the target keeps that address live; do not generalize this into a pointer alias to a scalar global merely to force callee-saved retention.

## Stack and frame shape

- Thumb has no `strb`/`ldrb [sp, #imm]`; a byte local that spills uses `add rN, sp, #off` followed by `strb`/`ldrb`. Do not infer that the source took its address from this sequence alone.
- BLKmode local arrays/structs force a real `frame-pointer + offset` base register for each access; CSE can share that base across branch paths. Keep measured per-arm stores even when their elements are never read: removing them or replacing the arms with one ternary can change the frame, base lifetime, and join allocation.
- Byte-required: agbcc accepts GNU VLAs even with a local `const` bound; they can fold the byte count yet retain a second, late stack adjustment that a fixed array merges into the main frame. Keep the local `const` plus VLA when the measured fixed array changes the frame or body.
- A `const` bound can also eliminate a live maximum or turn a register comparison into an immediate one; compare the whole frame and loop setup.
- A variadic definition saves `r0`–`r3` and emits the ABI frame even with an empty body; wrong arity or prototype changes stack arguments and frame size.

## Structs and fixed layout

- Struct members and raw byte offsets can produce different address temporaries; if a typed field doesn't match, the field's type/width or the struct nesting is wrong — fix the layout, don't fall back to byte arithmetic.
- Overlay only proven fields and preserve all padding; a correct offset with the wrong type still gives the wrong access width.
- Declaration width also imposes alignment: a halfword or word global cannot model storage proven at an odd byte address without shifting later fixed-layout symbols. Use byte storage for byte-addressed globals at odd offsets, even if some consumers combine bytes.
- A field that is both compared/stored as a word and dereferenced is a pointer — type it so.
- Do not infer a field's declaration width merely from later shifts, masks, division, or one truncating load: direct assignment to a narrow local can narrow a wider memory read. If independent accesses prove the same storage is read as a word, read as signed halves, and written as a halfword, model one documented whole/parts union. Use analogous typed-pointer or named payload members for other proven overlays, and extend an existing canonical union instead of creating duplicate view structs.
- Under old agbcc, `union __attribute__((packed)) { u16 word; u8 b[2]; }` is a byte-neutral two-byte whole/parts overlay; the unpacked union is not. A nested two-byte struct arm also makes the union four bytes, so use a byte-array arm for proven two-byte storage and verify `sizeof` plus every following offset. Reading the high byte of a `u16` field with `>> 8`, `& 0xFF00`, or `/ 256` always stays `ldrh`; only a byte view (8+8 bitfield or packed union byte arm) yields `ldrb` at `+1`.
- For adjacent `s8` fields both tested against zero, first write `a == 0 && b == 0`: agbcc can fuse the short-circuit pair into one `ldrh`/zero test without a union or cast. Use a documented halfword pointer cast only when compare proves the natural fused condition does not recover a required spanning read and a named union would disturb fixed layout.
- One shared declaration may be unable to reproduce both signed and unsigned consumers. Preserve the type proven by established matched users, and keep a per-use cast only when a controlled comparison reproduces the alternate load; otherwise park the incompatible function rather than breaking a match.
- An embedded header whose address is passed to list helpers must be an embedded struct field, not a pointer; the pointer spelling changes layout and cleanup codegen.
- An opaque region only passed by address is naturally `unk8 region[N]`; a scalar member there introduces an unwanted load.
- Allocation/resource handles with repeatedly accessed address, size, or owner slots should be typed structs; returning or passing the usable address often means accessing the first pointer member.
- Out-parameter bundles of related pointers, tables, and counts should use one typed address-table struct; field offsets and pointee types determine loads and liveness.
- Repeated fixed-stride records are naturally an array of structs; this gives honest field widths and pointer/index arithmetic.
- Treat a single-element wrapper such as `{ T slots[1]; }` as a view, not a proven layout. When storage and users prove a direct `T *`, remove the wrapper and verify the pointer walk and cleanup bytes remain exact.
- Byte-required: model a proven one-word bitset as `unk32 bits[1]` and keep the ordinary access `bits[i >> 5] & (1 << (i & 31))`, even when bounds prove `i >> 5` is always zero. Collapsing it to a scalar can change base allocation and address formation.
- After splitting or nesting a fixed-layout struct, verify `sizeof` and every later offset; natural tail padding can shift unrelated code and pools.
- Retyping fixed globals must preserve both accessed width and total byte extent, especially in address-pinned RAM layouts.

## Calls and ABI

- Prototypes affect both sides: parameter widths select call-site conversions, while definition widths control entry normalization and allocation. Preserve measured cross-TU width splits, including a wide `s32` declaration with an `s16` definition or a caller-visible `unk32` view feeding a definition that narrows through a `u16` local. Forcing one narrow prototype everywhere can swap argument setup; keep the residual call-site cast when removing it changes bytes.
- Calls without a prototype use default promotions; arguments after r0–r3 go on the stack, so wrong arity changes the frame. An old-C caller with no narrow prototype in scope can therefore legitimately need a different argument view from the definition. Retain unused formal parameters when later arguments must keep their target ABI positions, including a sixth argument that must remain in its original stack slot. In callers with more than four parameters, long-lived values destined for stack arguments 4–5 can remain in callee-saved registers until the stores; preserve those locals rather than rematerializing the arguments.
- Direct calls emit `bl`; function-pointer lvalues emit a load plus `_call_via_rN`; match the indirection level.
- For small constant-size copies, pointee type and alignment decide builtin expansion: typed word pointers can inline 12 bytes as `ldmia/stmia`, while a `void *` source or destination lowers alignment enough to force a real `bl memcpy`. Keep the measured `void *` call boundary when the target calls.
- Byte-required: use the SDK `DmaCopy` macro when the target performs its register setup and mandatory DMA readback; a hand-written transfer sequence can omit the readback or schedule operands differently. Keep a measured assignment inside the size argument when it makes agbcc materialize the DMA base before loading other size inputs. The macro divides the byte size by `bits / 8`: an inline `x * 2` (16-bit) or `x * 4` (32-bit) size cancels in `fold` and drops the target shift pair — stage the byte count in a variable or spell it as a shift (`(n >> 5) << 2`). The macro's first statement materializes the DMA base, so source and destination read into locals before the call, in target order, load ahead of it; a signed `s32` size local keeps `asr` where `unk32` let combine merge `* 10 / 4` into one shift.
- Pass direct function names before adding explicit Thumb-bit arithmetic; relocation handling may already encode the callable address.
- Passing a call result directly versus storing it in a local can differ by a `mov` and by how long surrounding addresses remain live. In particular, `tmp = call(); global = tmp;` can materialize `&global` after the call, while `global = call();` may preload the address into a callee-saved register. Likewise, stage a call result used to index a global table when the target materializes the table only after the call; folding the call into the index can keep the table address live across it and add a saved register.
- A call result forwarded into an argument register for the next `bl` proves that source dataflow; preserve it rather than substituting `NULL` or a reload.
- An argument identical to a value just produced or stored may be reused directly from its current argument register; preserve the exact value flow instead of independently rematerializing the argument.
- Mixed pointer types in `?:` can warn or lower differently under old agbcc; a `void *` temporary can preserve a common call after an explicit branch.
- Replacing `void *` with a proven typed pointer can remove casts without changing bytes, but verify pointee width and conversion placement.
- The epilogue shows the return type: a `void` function returns through `pop {r0}; bx r0`, a non-void one through `pop {r1}; bx r1`, even with no `return` statement. For callbacks whose epilogue preserves `r0`, test a narrow non-void definition that falls off the end; changing it to `void` selects the other pop register even when the body is identical.
- A block repeated verbatim in two functions can be a `static inline` helper: agbcc inlines it at both sites without emitting a standalone copy and keeps the helper's Boolean-result join.
- Keep dead-looking calls, arithmetic, divisions, readbacks, and copies that asm shows; a dead result may still expose original order or constant construction. Byte-required producers can survive because an ordinary absolute-value test or pairwise compare made them live during `flow`, after which the compare/branch/negation vanished but a narrowing `lsl #16` or endpoint loads remained. A dead clamp is another measured source: `flow` can delete the store in its body while the compare keeps the producer and limit constant live, then a later jump pass removes the now-empty branch and leaves only those setup instructions. Test such natural chains before declaring a target-only dead block irrecoverable; if every natural spelling disappears, park rather than use `volatile`, fake guards, or register hacks.

## Literals, data layout, and relocation noise

- Pool reach and placement follow preceding code size and block layout; never chase pool offsets before fixing the first code difference.
- Inline strings can be emitted in a function's trailing literal pool; use inline literals when address order supports that shape.
- The `asm/data*.s` blobs at the head of `.rodata` are the original TUs' `.data` sections in link order (the same order as `.text` and `.rodata`). A non-const C table lands in `.data`: define it non-const in its owning TU and insert `src/<tu>.c.o(.data)` into `ld_script.ld` at the blob position it replaces, splitting the blob. `const` tables go to `.rodata`.
- String emission is deterministic: an initializer's literals are emitted in reverse first-occurrence order, duplicates are pooled once per object, and a table's strings precede the literals of functions defined after it. Simulate the pool from source order before building; the simulation also settles variable boundaries (two adjacent labels may be one initializer, and one label may be several variables — a single array first differed at the element where the next variable began).
- The same string in two pools proves two translation units, because pooling is per object; one string shared by two nominal TUs is evidence they are one.
- The build uses `-Wunused -Werror`: a table not referenced inside its TU cannot be `static`; keep it a non-static global. agbcc aligns `s16` arrays only to 2; when the original section start was 4-aligned, add `. = ALIGN(4)` before that object's section in `ld_script.ld`.
- `.word` number-versus-symbol differences can be relocation-display noise; compare resolved bytes and use the full-ROM SHA1 as authority.
- agbcc safely folds floating constants in file-scope initializers: a fixed-point macro such as `(u32)((x) * 65536.0)` can reproduce exact 16.16 table bytes without precomputing integer literals.
- Give hand-written assembly data tables `.size sym, . - sym`; this leaves bytes unchanged while exposing the table extent to ELF-aware tools.
- Replace an assembly inclusion in its original source position; moving a C definition within the translation unit shifts everything after it.
- Mid-TU alignment directives may be no-ops because functions are already aligned. When a translation unit's ROM tail is `00 00` but the assembler emits Thumb NOP padding (`C0 46`), place `ASM_ZEROPAD` at EOF.

## Zeroing and volatile

- Fold-away: write literals directly instead of keeping literal-valued temporaries such as `zero` or fixed destination addresses when compare shows the locals disappear without changing store order or bytes. A shared zero register does not by itself prove a source local; direct `= 0` assignments can CSE to one register. When separate direct or chained stores do change the literal/store sequence, retain one measured `zero` temporary shared by those stores.
- When the target keeps one typed zero value live across two pointer-field clears, reusing a local such as `T *zero = NULL;` can preserve the required pseudo and allocation where two direct `NULL` stores do not.
- A fresh `mov #0` immediately before pointer clears favors direct `NULL` stores; a shared zero local may suppress that materialization.
- CSE donates one const-0 pseudo to every later literal zero store once any `= 0` pseudo exists; reload then decides whether it stays in one register or is rematerialized. When the target has a fresh `mov #0` per phase instead, no natural spelling was found (zero locals of every width, typed constants, split chains, explicit returns all stayed shared); the only reproduction, a zero local reassigned before each phase, is a flagged fakematch.
- `= {0}` or `memset` may become a library call; explicit fields or a plain `int` loop can produce inline stores or a pointer walk.
- `volatile` preserves only the marked hardware access or readback; it does not order ordinary work and is not a register-allocation tool. On ARM, when a struct-held cursor must be written back after intervening volatile accesses, copy it to a local, use `*cursor++`, then store it back explicitly; direct `*object->cursor++` can write the pointer early and even select a different signedness load. Match hardware access width and volatility at the site: a word `ldr`/`str` on a halfword register is `*(vu32 *)REG_…`, narrowed with `(unk16)` (`lsl/lsr #16`; `& 0xFFFF` loads a literal mask instead). A volatile read is emitted before a neighbouring constant materialization that a plain load would follow. Declaring a shared struct/union member `vu16` added a readback `ldrh` before plain stores elsewhere; take a `vu16 *` to the member at the reading site instead.

## Matching process

- Start with dump, hosting translation unit, declarations, and every caller; use mechanical decompilation only as a semantic draft.
- For a signedness sweep, establish an all-unsigned (width-only `unk*`) baseline, then re-sign one field, local, or parameter at a time only where `asr`, `ldrsh`/`ldrsb`, or a signed branch supplies evidence; compare the complete function after each change because signedness can also reshape allocation.
- After correcting a shared field type, rebuild and diff every active reader and writer, not just the function that supplied the evidence; declaration fixes can change access, conversion, and allocation in distant users.
- Change one source-shape variable at a time and inspect the prologue plus first divergent instruction before interpreting later noise.
- For rapid shape probes, compile a scratch translation unit straight through `tools/agbcc` with the build's exact flags and place several candidate bodies in one compile; use this to narrow variants, then confirm the retained form in its real translation unit and with the full ROM compare.
- Treat compiler diagnostics only as prompts for another source experiment, never as evidence for retaining a cast; justify the final cast with target instructions and measured alternatives.
- Prefer correcting types, casts, scopes, and expression shape over compiler-flag workarounds: a pass toggle that fixes one register allocation often changes another loop or load. Use flags diagnostically unless the original build settings justify them. Treat a distinctive whole-TU signature as build-setting evidence: a prebuilt, version-tagged Nintendo EEPROM library TU with duplicated loop-exit tests and tied `orrs` operand roles matched only with pret `agbcc -O1 -fprologue-bugfix`, not the game's old `-O2`; apply such proven exceptions as per-file compile options.
- Verify every instruction and branch target, then run the full-ROM SHA1 compare; a local function match is insufficient when layout changed.
- Treat raw-decomp and reviewer claims about types, layout, or "natural" source as hypotheses; verify them against assembly, controlled experiments, and ROM bytes.
- A semantic draft parked under `#if 0` is absent from the object but still visible to source-based callgraph tooling, so its callees can appear reachable. Distinguish compiled reachability from callgraph-parser reachability before selecting work.
- If natural C is semantically and structurally correct but a stable residual is only register allocation after justified type, lifetime, and ordering experiments, preserve the assembly rather than add volatile qualifiers, artificial temporaries, or forced control flow.
- ARM (`.iwram_code`) functions: `adc` with a shifted operand (`adc rX, rX, rY, lsr #28`) has no C spelling — no `arm.md` pattern takes a shifted carry-in, and carry-only C loops ended at register-only diffs — so a whole-loop `__asm__` kernel is the accepted boundary, flagged as a fakematch. Named fields of a complete hardware block type produced direct halfword stores where indexed struct elements kept separate offset registers.
