# sub_80594FC

Matched 0x080594FC in src/layer.c using SDK DmaCopy for the three transfer
sites. Reachable via the callback selected by sub_8059310, whose matched C
supplies the layer, coordinates, width and height. No header/layout changes.

The width is s32: target +0x8E..+0x94 uses lsr #31, add, asr #1 for signed
width / 2. firstWidth remains unk32, so both split-copy sizes divide with
logical shifts. The local LayerCopyFunc, __sub_8756FC0 declaration and
sub_80594FC prototype now agree on s32 width; sub_8059310 still diffs exactly.

The disabled draft omitted the readback after the first split DMA. DmaCopy
supplies each required readback and named SDK register access. Assigning
firstWidth within the first DmaCopy size argument recovers DMA-base
materialization before the loop-invariant size calculation. Moving that
assignment to the preceding statement first differs at +0x72: the target
loads the DMA base into r2 before loading horizontalStride from sp+0xC.

## Temporary reduction

All trials compiled independently and were checked against the ROM SHA1.
Rejected trials were restored. Results below describe valid compile probes.

- yValue and the initial stride temporary folded byte-identically; removed.
- alignmentMask: folding first differs at +0x10, y goes into r8 rather than r9.
- horizontalMask: folding first differs at +0x10, same register change.
- columnCount and rowMask: folding reduces the frame from 20 to 16 at +0xA.
- horizontalStride: folding reduces the frame from 20 to 12 at +0xA.
- screenAddress: folding increases the frame from 20 to 24 at +0xA.
- rowOffset: folding adds a store of r1 at +0xE.

alignmentMask is unk32; changing it from the initial s32 trial is byte-neutral.
The other retained locals represent the mutable source cursor, loop index,
and split width shared by the two transfers. No raw struct offsets, custom
hardware wrappers, forced registers, or artificial control flow are used.

After clang-format, sub_80594FC and sub_8059310 have no differing diff rows.
