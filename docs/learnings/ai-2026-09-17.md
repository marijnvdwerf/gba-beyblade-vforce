# AI matching learnings

## AiState layout (0x080575F4, 0x080576EC, 0x080577A0)

The contiguous management block begins at `GameData + 0xCBC` and ends at `0xEC0`. The measured layout is `LevelGeometryTable *table` at `0x00`, `LevelGeometryAddresses geometry` at `0x04`, `QuadTree quadTree` at `0x120`, `GeometryLine *lines[0x20]` at `0x178`, and `ActorCollisionFunctions callbacks` at `0x1F8`; `sizeof(AiState) == 0x204`. Removing the former separate `GameData` fields at `0xDDC`, `0xE34`, and `0xEB4` preserves all later offsets. The US ROM compare passes with the three management functions represented against this layout while `initAiManagement` remains in assembly.

## sub_80576EC (0x080576EC)

The exact sequence requires distinct `GameData *gameData`, `AiState *ai`, `QuadTree *quadTree`, `LevelGeometryAddresses *geometry`, `Actor *actor`, `QuadTreeNode *node`, and `ActorCollisionFunctions *callbacks` locals. Assigning `quadTree = &gameData->ai.quadTree` before the table guard and `geometry = &gameData->ai.geometry` produces the target literal offsets and address order. The resulting function is instruction-identical. Replacing the quadtree expression with a direct call argument adds an address calculation after the table load; using `&ai->quadTree` or hoisting extra aliases does not match.

## deallocateAiManagement (0x080577A0)

`_gameData->ai.table` and `&_gameData->ai.quadTree` are instruction-identical to the target. The function remains a direct conditional with no extra locals.

## initAiManagement (0x080575F4)

The best natural draft has the target control flow, literal pool, function size, line cursor (`line = ai->geometry.unkC`), and loop bound (`i < ai->geometry.unk0->lineCount`). Its only instruction differences are the allocator roles of `gameData` and `ai`: the draft assigns `gameData` to `r7` and `ai` to `r6`, while the target assigns `gameData` to `r6` and `ai` to `r7`; every dependent base register is consequently swapped. Declaration order and reversed assignment order do not change this. Directly spelling all fields through `gameData->ai` adds address materialization and changes the function size. A `GeometryLine **` alias flips the roles only with extra address materialization and was rejected as an artificial steering alias. The draft is parked in `#if 0` immediately above the assembly include.

The target `initAiManagement` reads `GeometryLine.unk16` with `ldrh` and unsigned range branches, while `sub_80561EC` reads the same storage with `ldrsh` and signed branches. Retyping the shared field from `s16` to `unk16` makes `sub_80561EC` four bytes shorter and shifts the ROM; the committed shared declaration remains `s16`. The unsigned init use remains part of the parked draft and needs a natural dual-view recovery before that function can be committed.

The three-argument `fn_aiStubFunc` declaration is retained. Its literal-pool `fn_aiStubFunc` versus target `fn_aiStubFunc1` spelling is relocation/symbol-format noise; the full ROM compare is authoritative.
