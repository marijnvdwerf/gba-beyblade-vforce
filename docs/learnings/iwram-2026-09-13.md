# fastMemoryCopy16ARM

`fastMemoryCopy16ARM` at IWRAM address `0x0300711C` remains parked in
`src/iwram.c`. The assembly dump is retained and the full ROM comparison passes.

The clean parked draft has `const unk16 *` and `unk16 *` cursor locals derived
from the two pointer parameters. It checks a zero byte count, reports an odd
byte count through the existing indirect `off_807D96C` callback, and otherwise
copies `byteCount >> 1` halfwords with post-incrementing cursors. No raw offset
access, artificial register binding, or volatile qualifier is used.

The target instruction sequence is:

- `mov ip, sp; push {r4, fp, ip, lr, pc}; sub fp, ip, #4`
- `subs ip, r2, #0; mov r4, r0; mov lr, r1`
- one shared epilogue after the zero-count, odd-count, and copy paths
- odd-count literal loads in string-then-callback order
- `lsr ip, ip, #1` followed by `ldrh [r4], #2`, `strh [lr], #2`, and `subs ip, ip, #1`

The natural typed draft instead emits `push {fp, ip, lr, pc}`, uses `cmp r2,
#0`, leaves the parameters in `r0`/`r1`/`r2`, emits separate early-return
epilogues, and places the callback pool word before the string pool word. The
copy loop's operation widths and post-increment shape are otherwise correct.

## Measured steps

| Source change | First divergence / result |
| --- | --- |
| Semantic loop with pointer parameters and direct cursor increments | Target first differs at the prologue: target saves `r4` and copies cursors to `r4`/`lr`; draft keeps `r0`/`r1`. |
| Explicit `const unk16 *source` and `unk16 *destination` cursor locals | Same first prologue divergence; aliases coalesce back into the incoming argument registers. |
| `if`/`else` control flow with no explicit odd-path return | Zero path still receives a direct epilogue and the odd path still receives its own epilogue; target's shared epilogue is not recovered. |
| Integer cursor locals with pointer-to-integer conversions | Same saved-register and epilogue divergence, with additional non-source pointer conversions; rejected in favor of the typed draft. |
| Signed count trial | Changes the target `lsr` to `asr`; unsigned `unk32` is required by the target's logical shift. |
| Public typed pointer prototype trial | Does not alter the prologue/register allocation and would unnecessarily change the shared header declaration; reverted. |

The first persistent mismatch is the saved-register mask at the function
prologue (`push {r4, fp, ip, lr, pc}` versus `push {fp, ip, lr, pc}`). The
remaining register, branch, and literal-pool differences follow from that
allocation/control-flow shape. The function is therefore kept as a typed
`#if 0` draft immediately above the untouched `INCLUDE_ASM` line.

ARM lowering was measured with `agbcc_arm -O2 -mthumb-interwork` and `-marm`.
The halfword cursor types select ARM `ldrh`/`strh` post-increment instructions;
the unsigned count selects `lsr`; and the function-pointer call lowers through

# fastMemoryClear16ARM

Parked as a typed draft in `src/iwram.c`; the original assembly include remains at 0x030070B8. The target region is 100 bytes and uses ARM code, not Thumb. The target's initial sequence is `subs r3, r2, #0`, `sub r11, r12, #4`, `mov lr, r0`, and `mov r12, r1`. Its loop uses `lsr r3, r3, #1`, `strh lr, [r12], #2`, and `subs r3, r3, #1`; an odd byte count loads `Str_8756748`, loads `off_807D96C`, and calls through the loaded pointer.

The best typed semantic draft uses `unk32` for fill, byteCount, count, and value, and `unk16*` for the halfword cursor. It checks zero, reports odd byte counts through `off_807D96C(Str_8756748)`, then stores the fill value with a halfword post-increment loop. It is kept under `#if 0` because it does not match the target register allocation.

First divergence in the draft build is at function offset +0x08: the draft emits `cmp r2, #0` while the target emits `subs r3, r2, #0`. The draft then keeps the incoming values in `r0`, `r1`, and `r2`; it does not emit the target's `mov lr, r0` and `mov r12, r1`. The callback literal loads, indirect call, halfword store width, post-increment, and decrementing loop shape are otherwise present, but use the draft's `r0`/`r1`/`r2` roles.

Measured source-shape trials all retained the draft allocation: local aliases, declaration and assignment order permutations, initialization before the zero test, pointer and integer destination views, signedness combinations, callback return prototypes, inverted/else control flow, and identity expressions using multiple fill aliases. A duplicated odd-bit test did produce a distinct `subs` destination and preserved argument copies, but also emitted extra tests, saved registers, and branches, so it was not the target shape. An aggregate local introduced stack traffic. No compliant natural C shape tested reproduced the target's `r3`/`lr`/`r12` roles without changing instructions or frame layout.

ARM-specific facts measured here: the standard frame is `mov ip, sp; stmfd sp!, {fp, ip, lr, pc}; sub fp, ip, #4`; the target has no local stack frame beyond that prologue; and the target's count/fill/destination register roles are explicit before the zero-count return.
