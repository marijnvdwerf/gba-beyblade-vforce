## Second session: residual isolated to one byte-zero reference

Setup: I moved the draft's fields into `RiderBase` (same offsets), turned the draft on, and compared with objdump instruction lists. Baseline: 471 vs 464 instructions. The actor pointer is stack-spilled (`sub sp,#4; str r1,[sp]`).

Allocation facts from `tools/asm-annotated.py --all-passes`:

- The `unk98 = 0` halfword store takes the bitfield store path, which leaves `(set (reg:HI 100) (const_int 0))`. CSE's wider-mode constant lookup then maps every later byte-zero store (unk8, unk9, unkD3, unk1C0, 0x103–0x100, unk1C2, unk1C3, unk1CF) to `(subreg:QI (reg:HI 100))`. Reg 100 is later spilled as an equivalent constant and rematerialized by reload (`movs rN,#0`).
- The target's unk100 store is `adds r1,r7,r2; movs r0,#0; strb r0,[r1]`. That is the same shape as the local constant at unk1CE (`movs r0,#1`, address in r1). So in the target, unk100's zero is its own short-lived local pseudo, not reg 100.

Controlled removals (probes only, not source candidates):

| Change | Result |
| --- | --- |
| Remove `unk9 = 0` | Actor spill gone. Only the missing store plus the unk100 residual remain (10 diff lines). |
| Remove `unkD3 = 0` | Same: missing store plus the unk100 residual (12 diff lines). |
| Remove unk1C2 or unk1C3 | Spill gone, 60 diff lines. |
| Remove unk1CF | Spill moves elsewhere (`sub sp,#4` stays), 209 diff lines. |
| Remove `unk98` or the whole F4..118 chain | Large changes. |

So the actor spill and the unk100 zero share one cause: in the target, reg 100 has one fewer reference, because unk100 gets its own zero. Fixing unk100's source form should fix both.

- `unk8 unk100[4]` indexed in the chain.

- Chain spellings `unk9 = unk8 = 0`, `flags = unk98 = 0`, `unk98 = unkDC = 0`, `unk140 = unkD3 = 0`, `unk1C3 = unk1C2 = 0`, `unk1C0 = unk1BC = 0`, `unk9 = unk8 = unk90 = 0`.

## Final: natural source with a dead debug read

The early F4/F8/FC address staging does not need an enclosing chain. An unused read of the three fields placed immediately before the clears creates the address pseudos, and CSE reuses them for the later stores. The shipped form, which passes the full-ROM SHA1 compare:

```c
unused = rider->unkF4 + rider->unkF8 + rider->unkFC;
rider->unk101 = ... = rider->unk118 = 0;
rider->unk100 >>= 8;
rider->unkF4 = rider->unkF8 = rider->unkFC = 0;
```

The dead read's placement is byte-required:

| Placement of the dead read | Differing instructions |
| --- | --- |
| Immediately before the clears | 0 |
| Before unk1C0 | 28 |
| Before unk1BC | 44 |
| Before unk1A0 | 64 |
| Earlier | 338 or more |

- `rider->unk100 >>= 8` is byte-required. `rider->unk100 = rider->unk100 >> 8`, `>>= 16` and `(rider->unk100 & 0xFF00) >> 8` also match. Plain `= 0` gives 187, `/= 256` 478, `&= 0xFF00` 187.
- Reading only F4+F8 gives 30.
- One local read three times (`x = F4; x = F8; x = FC;`), or `F4 | F8 | FC`, also matches. A local `s32 v[3]` array gives 219.
- Separate `unkFC = 0; unkF8 = 0; unkF4 = 0;` statements match.
- Fully plain descending stores for 0x118..0x101 match only with a second dead read of 108..118 (without it, 409). Rejected: `rider->unk100 /= 256` (478 lines), `&= ~0xFF` (187 lines), a `static inline` helper (246 lines), and chain terminals that read other fields.
