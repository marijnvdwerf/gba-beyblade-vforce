# math.c — 2026-09-21

## sub_805A00C (0x0805A00C) — MATCHED

Euler-to-quaternion builder over the s16 sin table `Unk_874CC3C`
(`cos = table[index + 0x40]`). Final shape:

```c
s32* sub_805A00C(s32 a, s32 b, s32 c, s32* out)
```

with six `s32` trig locals, two `s32` product locals, and the index expression
written inline at each of the six subscripts.

### What made it match

Three independent things, in the order they were found:

1. **`s32` trig locals, not `s16`.** With `s16 cosA … s16 sinC`, agbcc keeps
   HImode pseudos and must sign-extend at each use; combine then folds
   `sign_extend(mem)` back into a single `ldrsh` placed at the value's FIRST USE
   instead of at the assignment. Result: all six addresses computed up front,
   all six `ldrsh` sunk into the multiply block (diff showed `ldrsh` at the
   `out[3] = …` line). Declaring them `s32` makes the sign-extension part of the
   load, so each `ldrsh` stays at its assignment, matching the target's
   `add r4,r5 / mov r7,#0 / ldrsh r6,[r4,r7] / mov sl,r6` per value.
   Measured: `s16` locals → 216 bytes, first diff 0x0a; `s32` → correct
   instruction stream.

2. **Array subscript, not a `const s16* table` local.** The established
   `table = Unk_874CC3C;` idiom (gameloop.c:362, riderphysics.c:1058,
   packet.c:45) is wrong here. With a pointer local, `*(table + (a + 0x40))`
   goes through `fold`, which reassociates and collapses
   `((a >> 1) & 0xFF) * 2` into `a & 0x1FE`:
   `mov r6,#255 / lsl r6,#1 / and r6,r0 / add r6,r5` plus a `+ 0x80` for cos —
   192 bytes, wrong shape. `Unk_874CC3C[i]` expands as `*(&Unk_874CC3C[0] + i)`
   with base+const formed first, preserving the target's
   `mov r4,r0 / add r4,#64 / lsl r4,#1 / add r4,r5`.

3. **The index expression repeated at each subscript, not cached in a local.**
   This is what places the table-base `ldr` at 0x0a, before the first
   `asr r0,#1`. Writing `a = (unk8)(a >> 1);` (or `ia = (unk8)(a >> 1);`) as its
   own statement expands that statement first, so the pool load lands after the
   normalization (first diff 0x0a, 208 or 216 bytes). Repeating
   `Unk_874CC3C[(unk8)(a >> 1) + 0x40]` … `Unk_874CC3C[(unk8)(a >> 1)]` lets
   expand evaluate the ARRAY_REF base before the index, and CSE merges the two
   occurrences into one normalization — exactly the target.

   Reassigning the *parameter* (`a = (unk8)(a >> 1)`) additionally lengthens the
   parameter pseudo's live range enough that local_alloc gives `out` r0 and the
   table base r2, forcing four entry copies
   (`mov r4,r0 / mov r5,r1 / mov r7,r2 / mov r0,r3`) and losing the final
   `mov r0,r3` — 216 vs 208 bytes. A separate index local fixes the size but not
   the `ldr` position.

### Signedness / width evidence (each re-tested on the matching shape)

- Parameters `s32`: `asr r0, #1` at 0x0c. `unk32` params → `lsr`, first diff 0x0d.
- Trig locals `s32`: `unk32` → first diff 0x69; `s16` → 216 bytes, first diff 0x0a.
- Product locals `s32`: `unk32` → first diff 0x7b (the `asr #8`/`asr #16` chain).
- Table elements `s16`: `ldrsh` at 0x1c/0x30/0x44/0x4e/0x56/0x60.
- Return type non-void: `void` → 204 bytes, loses `mov r0,r3` at 0xba.
- `out` pointee signedness is NOT proven here — `unk32*` is byte-identical
  (`str` only). Kept `s32*` for consistency with the other matched consumers of
  the same 4-word quaternion buffer in this TU (sub_805A0DC does
  `(q[0] << 8) / length`, sub_805A148 does signed `>> 8`), which do prove signed.

### Fold results

- `cosBcosC` and `sinBsinC` are byte-required. Inlining both (each is used
  twice) keeps the size at 208 but diverges at 0x6a — the two `asr #8`
  reductions get recomputed per use instead of once.
- No index/alias/table temporary survives: every cached form diverges (see the
  matrix). The repeated `(unk8)(x >> 1)` expression is the byte-required shape.
