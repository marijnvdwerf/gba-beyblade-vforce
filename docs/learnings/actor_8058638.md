# actor_8058638

## Parked status

`actor_8058638` remains assembly-backed because the best natural C draft did not
match the target instruction stream. The assembly inclusion and dump remain in
`src/actor.c` and `asm/dump/8057b80-debug/8058638-actor_8058638.s`.

The first divergence in the best draft is at function offset `0x0C`:

```asm
 target: add r4, r3, r0
 draft:  add r5, r3, r0
```

This is the sequence-record pointer. The resulting allocation remains swapped
through the later sequence loads: the target loads the frame count into `r5`
from `[r4, #2]`, while the draft loads it into `r4` from `[r5, #2]`. A second
stable residual is the 16-bit truncation: the target emits `lsr r0, #16`
followed by `mov r1, r0`, while the natural draft emits `lsr r1, r0, #16`.

## Proven layout evidence not represented in the committed header

The temporary header extensions were reverted because they served only this
parked function. The committed `ActorFrameSequence` remains the ordinary
8-byte record with `unk0`, `unk2`, `unk4`, `unk6`, and `unk7`; `ActorConfig`
retains its existing padding through the sequence array; and `Actor` retains
its existing types and padding at `unk22`, `unk36`, and `unk60`.

The target nevertheless proves the following accesses for this function:

- The signed frame accumulator source is read with `ldsh r0, [r2, #0x36]` at
  offset `0x3A`, so the source at `Actor.unk36` is sign-extended here.
- The frame index is read with `ldsh r0, [r2, #0x22]` at offsets `0x20`,
  `0x58`, and `0x78`. The same storage is also read with `ldrh r1, [r2,
  #0x22]` at offset `0x40` and with `ldrh r0, [r2, #0x22]` at offsets `0x4C`
  and `0x54`, then written with `strh r0, [r2, #0x22]` at offsets `0x5C` and
  `0xB8`. Those instructions establish halfword storage and the signed
  consumer needed by the stepping comparisons, but the canonical header type
  was not changed for a parked function.
- The prior frame value is read with `ldrh r5, [r2, #0x34]` at offset `0x3C`,
  so `Actor.unk34` is a halfword source.
- The sequence record is read with `ldrh r3, [r4]` and `ldrh r5, [r4, #2]`
  at offsets `0x7C` and `0x7E`; these are the `unk0` and `unk2` halfword
  fields. The sequence flag storage at the record's first byte is read with
  `ldrb r1, [r4]` at offsets `0x90` and `0xC0`, modified with `eor`, and
  written with `strb r0, [r4]` at offsets `0x9C` and `0xCC`. This is the
  proven byte-level pun: the first two bytes are read as a halfword for the
  frame offset and independently read/written as a byte for the direction
  flag. The temporary union split was therefore an analysis model only, not a
  committed layout change.
- The sequence-state destination is written with `strh r1, [r0]` to
  `Actor.unk60` at offset `0x84`. It was not added to the committed header for
  this parked function.
- The optional frame-table setup reads `ldr r1, [r3, #8]` at offset `0x48`
  and `ldr r0, [r3, #0x18]` at offset `0x50`. The second load proves the
  end-offset word used by the runtime table comparison; it does not justify
  changing the committed `ActorConfig` layout solely for this parked draft.

## Best parked source shape

The draft immediately above the assembly inclusion is intentionally written
as source rather than compiler-oriented offset arithmetic. It uses
`&config->sequences[actor->unk20]`, a typed frame-value table, and a plain
`sequence->flag` field for the proven byte access. The field names
`frameValues`, `frameValuesEnd`, and `flag` describe the required source-level
layout but are not added to the committed header while this function remains
parked.
