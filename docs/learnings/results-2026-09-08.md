## Loop-rotation bisection

The target is a bottom-tested loop with a shared test. The target's body starts at `.L8052D50` with `VBlankIntrWait` and `sub_80627F0`. The final `done`-dependent target/fade update is inside the body at `.L8053202`. The false `done` path jumps directly to the body because `done == 0` already satisfies the short-circuit loop condition. The source-level semantic condition is:

```c
while (done == 0 || state->items->text.x != target) {
    /* body */
}
```

Testing `for (;;)` with an explicit break, `do`/`while`, and guarded `do`/`while` produced body-first control flow or duplicated tests rather than the target's shared entry and tail.

Deleting the sequence-timer block, networking block, fade block, mode-specific key update, resource updates, menu movement, sprite animation, or OAM/input block individually did not restore the target rotation. Heavily reduced bodies eventually produced a bottom-tested loop, demonstrating that the full body's combined liveness and control-flow interaction blocks the rotation. No single isolated statement or construct was proven to be the sole blocker before the coordinator ended matching experiments. The final source therefore retains the best natural typed draft rather than an artificial loop-shaping form.

Retaining both `menu` and `state` while changing the loop condition to `menu->items->text.x` produced the target-like initial branch shape, but expanded the frame to `0xD4` and moved the loop variables to incompatible stack offsets. These results show that the alias and lifetime choices affect both rotation and frame layout; the `0xD4` variants are not retained.

## Pointer and scratch-layout rulings

The result dump loads `GameData.unk42C` at `0x08052F62`, adds one `RiderBase` stride per loop iteration, and passes that rider address to `sub_804C0C0` at `0x08052F6E`. `GameData.unk42C` therefore remains the shared `RiderBase*` field; the existing owner declaration of `sub_804C0C0` takes `RiderTemp*`, and `RiderTemp` describes the tail view used by existing rider callers. The parked draft now passes the `RiderBase*` expression directly, without a cast or a second view struct. Resolving that owner-signature/layout mismatch is an active-match ruling and remains parked.

The removed `GameData` members at `0x870` and `0x8A0` are represented only by `ResultsGameDataScratch` and `_gameDataResultsScratch` inside the parked `#if 0` draft. They do not add fields to the shared fixed-layout `GameData` definition.

The remaining `s32` locals are `fade`, whose `asr` and signed branch occur from `0x08052E94` through `0x08052E9A`, and `i`, whose signed `blt` rider-count loop branch occurs at `0x08052F84`. The other 32-bit state and arithmetic locals use `unk32` because their accesses do not prove signedness.
