# geometry.c — 2026-09-21 (retry of the two parked endpoint-search functions)

## sub_805E528 (0x805E528) — matched

Searches `addresses->unkC[]` for a line of type `type` whose endpoints touch the
bounding box of `line`'s endpoints, with `flags` selecting which sides must be hit.

Four things had to be right; the parked draft had all four wrong.

### 1. `(ef & CONST) & flags` cannot be written as one expression

agbcc's `fold` unconditionally reassociates a three-operand AND chain that has a
literal in the left subtree:

    (endpointFlags & 0xC) & flags   ==>   endpointFlags & (flags & 0xC)

Verified in the `.rtl` dump (pre-optimisation, `--all-passes`): the front end
already emits `reg121 = reg29(flags) & 12` followed by `reg124 = reg38(ef) & reg121`.
This happens regardless of what is on the right of the `==` (checked with a
constant RHS), so it is fold, not CSE of the comparison operand.

Consequences of the reassociated form: `flags & CONST` becomes a *second*
loop-invariant pseudo, which is hoisted and eats a hard register, while `flags`
itself falls out to memory — that is the extra stack slot (20 vs 16) the draft
showed in the prologue.

The target computes `and rX,#CONST` then `and rX,flags`, i.e. the masking is a
statement of its own. Matching shape:

    if ((endpointFlags & 0xC) != 0) {
        endpointFlags &= 3;
        if ((endpointFlags & flags) == (flags & 3)) { ... }
    }

`(endpointFlags & flags & CONST)` (the other association) compiles to the same
two ANDs but in the opposite order, so it is not the source either.

### 2. Loop bound is the member expression, not a local

`while (index < addresses->unk0->lineCount)` — LICM hoists the two loads into the
preheader, so the spill store `str r0,[sp,#8]` lands *after* the copied entry
test. With a `lineCount` local the store sits *before* the guard (that is how you
tell the two apart in the listing). An explicit guarded `do {} while` (the
sub_805E77C shape) is worse here: only the first load gets hoisted, the
`->lineCount` load stays in the loop.

### 3. `current = addresses->unkC;` before the two min/max swaps

`ldr r4,[r5,#0xc]` sits between the `point1->y` load and the first `cmp`, i.e.
before the `if (minX > maxX)`.

### 4. The loop's two endpoint pointers are their own locals (the actual wall)

The prologue derives `point0`/`point1` from `line`; the loop derives the
candidate's endpoints. Reusing the same two locals for both gives each pseudo two
sets and a live range that straddles prologue and loop; local-alloc then burns
`r4` on the loop copy, and the global allocator has one register too few — it
spills `index` and keeps the `flags & 0xC` invariant in `r6` (142 insns, all four
bounds shifted up one register). With separate locals for the loop pair
(`currentPoint0`/`currentPoint1`) the allocation flips to the target's: `index`
in `sl`, the invariant spilled to `[sp,#12]`, `current` in `r4`, bounds in
`r8/ip/r7/r6` — byte identical.

Probe matrix run (swap form x `current=` position x bound form x split pointers,
24 builds); every non-split variant stayed at 142 insns regardless of the other
three axes, and only `temp-swap / current-before-swaps / member-bound / split`
reached 0.

### Byte-required temps

* `temp` for the two swaps: with the reload form
  (`minX = point1->x; maxX = point0->x;`) the point pointers stay live over the
  compare and the x-swap collapses to two `mov`s; the target's three-`mov` swap
  needs the temp.
* `currentPoint0`/`currentPoint1` (see 4).
* No `axisFlags` local: adding one puts `flags & 0xC` before the guard and costs
  a fifth stack slot.

### Widths / signedness

* `type`, `flags`, `index`: `unk16` (`lsl #16; lsr #16` at entry and on the
  increment; no `asr` anywhere).
* bounds: `s32` — `ble` on the swap compares, and `GeometryPoint.x/y` are `s32`.
* `endpointFlags`: `unk16` — the `orr #4` / `orr #8` are followed by
  `lsl #16; lsr #16`.

## sub_805E648 (0x805E648) — matched

Identical to sub_805E528 plus a fifth parameter and one extra guard; written by
copying the matched sibling and adding

    if (current->unkF == type && sideFlag == current->unk11_1) {

Everything else (temp swap, `current=` before the swaps, member expression as the
loop bound, split `currentPoint0`/`currentPoint1`, the `endpointFlags &= CONST`
statements) transferred unchanged and produced a byte match on the first build
except for the bit extraction.

### `GeometryLine.unk11` is a bitfield (shared-header change, proven)

The target extracts bit 1 with `ldrb r2,[r4,#0x11]; lsl r0,r2,#30; lsr r0,r0,#31`
— the canonical `extract_bit_field` expansion for a 1-bit field on a target
without `extzv`. No mask/shift spelling of a plain `unk8` reproduces it:

| source                              | emitted                             |
| ----------------------------------- | ----------------------------------- |
| `sideFlag == ((unk11 >> 1) & 1)`    | `lsr #1; movs #1; ands` (3 insns)   |
| `((unk11 >> 1) & 1) == sideFlag`    | same 3 insns                        |
| `sideFlag == ((unk11 & 2) >> 1)`    | 3 insns + knock-on regalloc shift   |
| `sideFlag == unk11_1` (1-bit field) | `lsl #30; lsr #31` — match          |

So `unk8 unk11` became `unk11_0..unk11_3 : 1` plus `unk11_4 : 4` (one byte,
struct still 0x20). The 14 existing mask users in geometry.c (2), collision.c
(11) and riderphysics.c (1) were rewritten as bitfield tests
(`(line->unk11 & 8) != 0` -> `line->unk11_3 != 0`, mask 4 -> `unk11_2`,
mask 2 -> `unk11_1`). agbcc's `optimize_bit_field_compare` turns a bitfield
compared against a constant back into the `ldrb` + mask test, so all 14 stayed
byte-identical: both `cmake --build --preset us --target compare` and
`cmake --build --preset eu --target compare` pass with the header change.

`sideFlag` is `unk8` (`ldr r0,[sp,#0x34]; lsl #24; lsr #24`), and the compare is
`cmp sideFlag, bit` — the parameter is the left operand.
