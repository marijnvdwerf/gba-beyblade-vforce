# sub_8055340

Matched at 0x08055340 in src/effects.c. ROM SHA1 compare passes.

The existing disabled draft incorrectly treated the window state as a bitfield and used MOSAIC register names. The target instead reads a word at +0x7C (0x0805555C), reads signed halfwords at +0x7C/+0x7E, and writes a halfword at +0x7C (0x0805557C). This proves the word/parts union. Its extent remains four bytes; subsequent +0x80, +0x84 and +0x88 accesses and all existing users match. The window writes target WININ and WINOUT.

Signed halfword declarations for +0x70/+0x72/+0x74/+0x76/+0x7A are proven by ldsh in the target. +0x7C/+0x7E also use ldsh for interpolation, and the window coordinate uses an arithmetic shift by four. +0x78 remains width-only. +0x88 is a RiderBase pointer, passed to rider helpers and used to address its embedded actor at +0x238. sub_804B7FC's declaration now returns that pointer.

sub_8051868 now has one shared s32 return type in gamestate.h and gamestate.c; effects.c includes that header and has no local declaration. Changing the definition from unk8 to s32 preserves its exact instructions and the full ROM SHA1. The previously retained TU-local wide caller view was therefore unnecessary. Using an unk8 caller declaration inserts lsl/lsr #24 pairs at function offsets 0xA0 and 0xE2, while the shared s32 declaration preserves the target signed switch comparison and forwards the first result directly into sub_804FC00. Both sub_8051868 and sub_8055340 remain exact with the unified type.

Temporary experiments: gameData and palette aliases folded with identical ROM bytes. Folding value into the palette call removed the final argument-order difference. Folding blend into the hardware stores recovered target address evaluation order. Folding the case-3 rider snapshot or the effect pointer failed SHA1, so both remain. The trigger flag preserves the separate increment/test control flow.

Instruction diffs are exact for sub_8055340, initProjectileSystem, sub_80555F4, sub_8055624, sub_805565C, sub_8055674, sub_805568C, sub_80556C4, and sub_80558E8. Formatting followed by the full ROM compare also passes.

Palette destination casts use (unk8*)PLTT, matching sub_80631EC's unk8* parameter. PLTT is a plain address constant; the cast is required for conversion to a pointer, not a struct-field typing workaround. Replacing all four (void*)PLTT casts with (unk8*)PLTT preserves the instruction diff and full ROM SHA1.

## Review measurements (2026-09-10)

### Shared return type and callers

`sub_8051868` is declared as `s32` in `src/gamestate.h` and defined as
`s32` in `src/gamestate.c`. `rg -n "sub_8051868" src` finds exactly two
call sites, both in `sub_8055340` (`effects.c:70` and `effects.c:82`); there
are no other callers in `src`. The function diff is exact. Its target body is
`push {lr}` at `+0x00`, calls at `+0x02` and `+0x06`, then the retained
`lsl r0, #24` at `+0x0A` and `lsr r0, #24` at `+0x0C`, followed by the return
at `+0x0E`/`+0x10`. Those shifts remain because `sub_805749C` returns `unk8`;
the public result is widened to `s32` only after that byte-valued call.

The two `sub_8051868` calls in `sub_8055340` are exact with the shared `s32`
declaration. In the prior `unk8` caller-view trial, the caller inserted
`lsl`/`lsr #24` normalization pairs at caller offsets `+0xA0` and `+0xE2`.
The shared declaration removes those caller conversions and matches the target
switch comparison and direct argument forwarding.

### Palette zero store

The `effect->unk70` fade branch stores zero into `effect->unk72`, not into
`effect->unk76`. In the target, `r0` is formed as `effect + 0x72` at `+0x1EA`
(`mov r0, r5`) and `+0x1EC` (`add r0, #114`), followed by
`strh r4, [r0, #0]` at `+0x1EE`. Here `r4` is the zero value established by
the preceding `effect->unk76` zero test (`ldrsh r4, [r3, r1]` at `+0x18C`,
`cmp r4, #0` at `+0x18E`, and the zero branch at `+0x190`). The target's
halfword store therefore lands at `+0x72`; the `effect->unk76` store is the
separate `strh r2, [r1, #0]` at `+0x1A8` in the other fade branch. The
`sub_8055340` diff is exact.
