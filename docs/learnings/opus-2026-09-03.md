# Session learnings — 2026-09-03

## initMultiPlayer (0x0805FED0)

### Forms that did not match

| Form | First divergence | Conclusion |
|---|---|---|
| `unk32 packetSize`, `headerSize = packetSize * 2` before `totalSize` | 0x0E: `adds r5, r1` (packetSize in r5, serialMode in r8 — swapped) | `headerSize` as a separate statement before `totalSize` gave packetSize higher allocator priority (more refs earlier), putting it in the cheaper r5 instead of r8 |
| `totalSize = totalPackets * 2 + packetSize * 2` with `unk32 packetSize` | 0x1C: `adds r0, r0, r5; lsls r0, #1` — compiler folded `a*2 + b*2` into `(a+b)*2` | Unsigned arithmetic allows algebraic simplification that merges the two shifts into one |
| `bufA = expr; state->unk24 = bufA` (separate statements) | 0x7E: `ldr r1, [r7]` — block->address loaded before state pointer | Compiler evaluates the pre-computed local first; the store target address (global pointer) loads second |
| `bufC = base + headerSize + 0x44` (left-to-right addition) | 0x8C: `ldr r0, [r7]; add r0, r9; add r0, #0x44` — 3 instructions, incremental adds | Without parentheses, pointer arithmetic proceeds left-to-right: base, then headerSize, then 0x44; target pre-computes `headerSize + 0x44` as one displacement |

### Change that matched

`s32 packetSize` prevents `(a+b)*2` folding. Single-expression `totalSize = totalPackets * 2 + packetSize * 2` lets the compiler CSE `packetSize * 2` into r9 for later bufC use while computing `totalPackets * 2` first. `state->unk24 = expr; bufA = state->unk24` forces the store target (global pointer) to load before the value expression. Parenthesized `base + (headerSize + 0x44)` pre-computes the displacement.

## sub_8049458 (0x08049458)

### Forms that did not match

| Form | First divergence | Conclusion |
|---|---|---|
| `(unk8)value == unk586` (cast on left operand) | 0x10E: `add r1, r5, r3` — &value in r1 instead of r2 | The `(unk8)` cast on the left operand produces an expression tree where the first address temporary gets r1; the target has r2 |
| `unk586 == (unk8)value` (swapped comparison) | 0x10C: `ldr r3, [pc, (0x586)]` — wrong literal loaded first | Swapping comparison direction reverses the literal-pool load order; target loads 0x584 first |
| Separate `unk8 val` / `unk8 target` locals | 0x10C: compiler optimized `r3 + 2` to derive second offset from first | Named byte locals caused the compiler to CSE the two offsets as `base` and `base+2` instead of two separate literal loads |

### Change that matched

Declaring both `value` and `unk586` as `s8` (same type) and comparing without casts: `value == unk586`. Both `s8` fields still load with `ldrb` (agbcc uses unsigned byte loads for `s8` in equality comparisons where sign doesn't matter). The same-type comparison produces the target's register allocation (r2 for &value, r1 for the unk586 offset), whereas mixed-type or cast-on-read forms produced r1/r2 swapped.

Also: `_unk3000BFD` was `unk16` but lives at odd address 0x3000BFD. The linker aligned it to 0x3000BFE, producing a wrong literal-pool value. Changed to `unk8`.

Also: `FrontendState.unk0`/`unk4` changed from `unk32` to `s32`, removing the `(unk32)-1` casts throughout frontend.c. Byte-neutral across all users (frontend, festate, background, credits, levelrow).

## Generic patterns

- `s32` vs `unk32` parameter type can block algebraic simplification: `a * 2 + b * 2` stays as two separate shifts with signed arithmetic but folds to `(a + b) * 2` with unsigned.
- A single expression `x = a * 2 + b * 2` lets the compiler CSE `b * 2` into a callee-saved register for later reuse, while a separate `h = b * 2; x = a * 2 + h` forces `h` to be computed first and changes the computation order.
- `target->field = expr; local = target->field` (store then read-back) forces the compiler to evaluate the store's base-address load before the value expression, matching codegen that loads the global pointer first.
- Parenthesized pointer arithmetic `base + (offset + constant)` pre-computes the displacement in a separate register, producing a 4-instruction sequence instead of 3 incremental adds — matching when the target stages the displacement.
- When two byte fields of different declared types are compared, the mixed-type promotion can change the expression tree and register allocation. Declaring both fields the same type (both `s8` or both `unk8`) and comparing without casts can produce a different — and sometimes correct — register assignment for the address temporaries.
- A `unk16` global at an odd byte address gets linker-aligned to the next even address; if the asm uses the raw odd address, declare it `unk8` to avoid a 1-byte address shift in the literal pool.
- Declaration order of locals does not reliably change `.greg` allocation priority in old agbcc; the allocator sorts by `refs / live_length` regardless.
- `|=` compound assignment on a volatile register and `= ... | volatile` are not interchangeable: `|=` can produce a different evaluation order (volatile read first vs constant materialization first) and may modify the source variable's pseudo, changing its set count.
- `count++` as an inline post-increment argument produces the increment before the next argument's materialization; a separate `count++` statement after the call places the increment after the call returns.
- When a zero value is needed after a call, the compiler can naturally materialize `mov r4, #0` before the call and keep it in a callee-saved register — no explicit `zero` local is needed.
- An `s8` field does not always emit `ldrsb`: in byte-to-byte equality comparisons and byte stores, agbcc can use `ldrb`/`strb` for `s8` fields. Declaring a field `s8` is safe when all accesses use `ldrb`/`strb` in the target; it only breaks if some access genuinely requires `ldrsb` sign-extension while others require `ldrb`.
- Changing a `unk32` field to `s32` is byte-neutral for loads (`ldr`), stores (`str`), adds, and comparisons against `-1`; it removes the need for `(unk32)-1` casts and is the correct declaration when the field is compared against `-1` in the target.
