# layer matching notes — 2026-09-17

## sub_8059CC8 (0x08059CC8)

- The function takes `(u8 layer, u8 mode)` and assigns `mode` to `GetBGLayerCntPtr(layer)->bits.unk0_0`; the existing `BGControl` bitfield emits the target low-byte read-modify-write and both byte argument normalizations.
- Explicitly masking `mode` before the bitfield assignment changed the target `mov #4; neg` mask construction into `sub #7`; leaving masking to the bitfield is required.
- A local `BGControl*` pointer temporary folded byte-identically, so the final source uses the direct accessor expression.
- `bun run tools/diff/diff.ts sub_8059CC8` reports every instruction equal.

## sub_8059DB8 (0x08059DB8)

- The function takes `(BGLayer* layer, unk32 index, unk32 value, unk16 data)` and writes `data` to the VRAM tile-map address formed from `layer->screenBaseBlock`, `value << layer->field_5F`, and `index`.
- A typed `unk16*` cursor initialized from `VRAM + (layer->screenBaseBlock << 11)` and indexed by `(value << layer->field_5F) + index` emits the target address calculation and halfword store without raw struct-offset access.
- Folding the cursor into a direct indexed VRAM store was not byte-identical: the first divergence was the prologue (`push {r4, r5, lr}` versus `push {r4, lr}`), followed by scaled-index evaluation before VRAM-base materialization. The cursor is required.
- `bun run tools/diff/diff.ts sub_8059DB8` reports every instruction equal with the cursor form.

## sub_8059EBC (0x08059EBC)

- The helper takes `(BGLayer*, unk8*, unk32 column, unk32 row)` and scans the string with an `unk32` index initialized to 1. Newlines advance the row by 2 and reset the column without incrementing it; non-newlines increment the column, and non-space characters call `sub_8059E5C` with the `GlyphIndexes` lookup.
- Initializing `currentColumn`, loading `string[0]`, then initializing `index` reproduces the target setup order. Keeping the cursor increment inside the non-newline arm reproduces the target branch directly to the next-character load.
- `bun run tools/diff/diff.ts sub_8059EBC` reports every instruction equal. No struct fields required extension.

## allocateActorMotionModifiers (0x08059058)

- The function takes `(BGLayer*, BGLayerCallback, unk32 value, unk32 duration, unk32 callbackValue)`. It allocates one 0x10-byte callback record when `field_80 == -1`, reports allocation failure through `nullsub_8(Str_872CC00)`, scans the existing records for an unused slot, writes the callback record, and increments the signed count.
- The shared `BGLayerCallbackData` layout and `BGLayer.field_80`/`field_84` types were sufficient; no new struct fields were required. The scan index is a signed `s32` because the target uses a signed `ble` loop test and `bge` sentinel test.
- A cursor-based scan (`data++`) reused the `field_80` address and first diverged at 0x54: it emitted `add r0, #4; ldr r2, [r0]; mov r4, r0` instead of the target `add r4, #132; ldr r2, [r4]`, shifting all following instructions by two bytes. Pointer-to-pointer and cached-base variants introduced additional moves or copies.
- Expressing the scan as an indexed access, `layer->field_84[i].unk0`, produced the target field-84 address materialization while retaining the natural selection and store logic. `bun run tools/diff/diff.ts allocateActorMotionModifiers` reports every instruction equal, and `cmake --build --preset us --target compare` passes with SHA1 `cd527c8c24e20e33913fc45199e64b3e6138a6e5`.
