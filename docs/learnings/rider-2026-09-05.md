The exact source shape stages both actor pointers and all six coordinates
before calculating deltas. The coordinate staging is required for the target
allocation: actor 0 coordinates occupy r3/r4/r5, actor 1 coordinates are
loaded through low temporaries, and the normalized deltas occupy r7/r9/r5.
Using only actor 0 coordinate locals or computing each delta directly changes
this allocation and diverges at the first actor-pointer or coordinate load.

The collision threshold and state comparisons use signed 32-bit fields. The
RiderBase layout therefore defines `unk208` as `s32`; `unk40` and `unk44` are
signed 32-bit fields accessed by the non-actor movement branches. Actor
position and separation coordinates are signed 32-bit fields.

The state update structure is significant. The first flag guard contains a
nested `unk208 > 0x1FF` check, but its `unk220 += 0xF0` update is after that
nested check. The second guard has the same shape, with the clamp nested only
under the `unk208 > 0x1FF` check and the `unk220` update after it. Keeping both
updates inside the threshold condition moves the branch targets and shortens
the function.

The `0x04000000` flag is written as a literal at each use rather than cached
in a local; this causes the target to rematerialize it before the second state
check. `RiderHasFlag` is compared directly; the `lsl #24` normalization is
compiler-generated from its `unk8` return type.
