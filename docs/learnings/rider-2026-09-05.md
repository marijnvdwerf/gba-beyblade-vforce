# Rider physics

## rider_vs_rider_collision_804DB94 (0x0804DB94)

Matched in `src/riderphysics.c` against the dump at
`asm/dump/804a388-tutorial/804db94-rider_vs_rider_collision_804DB94.s`.

The exact source shape stages both actor pointers and all six coordinates
before calculating deltas. The coordinate staging is required for the target
allocation: actor 0 coordinates occupy r3/r4/r5, actor 1 coordinates are
loaded through low temporaries, and the normalized deltas occupy r7/r9/r5.
Using only actor 0 coordinate locals or computing each delta directly changes
this allocation and diverges at the first actor-pointer or coordinate load.

The collision threshold and state comparisons use signed 32-bit fields. The
RiderBase layout therefore defines `unk208` as `s32`. The target's accesses to
`unk40` and `unk44` are plain word loads, stores, and arithmetic, so their
canonical fields remain `unk32`; this function does not prove signedness for
them. Actor position and separation coordinates are signed 32-bit fields.

Measured type sweep:

- Changing `unk40` and `unk44` from `s32` to `unk32` preserved the byte-identical collision output and removed the unproven signedness.
- Declaring `magnitude` as `u16` without another temporary changed the threshold branch from signed `ble` to unsigned `bls`, and `compare` failed.
- Replacing the comparison with `(s32)(unk32)magnitude <= 0x15` also failed to match.
- Keeping `magnitude` as `u16` and assigning it to a separate `s32 magnitudeSigned` before the threshold comparison restored the target `ble`; `compare` passed.
- Declaring the second BIOS square-root result `scale` as `u16` also passed `compare`.


The state update structure is significant. The first flag guard contains a
nested `unk208 > 0x1FF` check, but its `unk220 += 0xF0` update is after that
nested check. The second guard has the same shape, with the clamp nested only
under the `unk208 > 0x1FF` check and the `unk220` update after it. Keeping both
updates inside the threshold condition moves the branch targets and shortens
the function.

The `0x04000000` flag is written as a literal at each use rather than cached
in a local; this causes the target to rematerialize it before the second state
check. `RiderHasFlag` is compared directly; the `lsl #24` normalization is
compiler-generated from its `unk8` return type.

Measured verification:

- `bun run tools/diff/diff.ts rider_vs_rider_collision_804DB94`: no differing instructions.
- `cmake --build build --target compare`: passed.
- `uv run tools/lint.py src/*.c`: passed.
