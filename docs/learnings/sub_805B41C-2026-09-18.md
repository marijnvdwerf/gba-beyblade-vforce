# sub_805B41C — 2026-09-18

Matched 0x0805B41C in src/text.c (0x24C bytes including pools). US and EU full-ROM SHA1 comparisons pass.

The function measures and aligns text, allocates and clears background tiles, assigns palette bits to map entries, and draws each glyph tile. Its return is the updated horizontal coordinate.

## Types and interfaces

- The x coordinate and width computations use signed arithmetic: the target uses asr for horizontal tile positions and centered alignment, and bgt for the 239-pixel limit. The coordinate parameters in text.h are s32; the return remains the existing unk32 view used by callers.
- Read all three C callers: sub_805B668, sub_805B700, and sub_805B800. Each still has an exact function diff with the signed-coordinate declaration; the full ROM confirms call-site bytes remain unchanged.
- sub_805B7F0 now accepts const SpriteSheet* and returns const RiderTile*, exposing the existing 32-byte tile stride without a raw byte-step cursor. The helper still matches exactly. Its variable resource offset remains ordinary byte-addressed blob arithmetic before conversion to the tile pointer.
- The font dimensions, tile counts, allocation size, and character advance use unk32 where unsigned trials remained exact. firstTile uses unk16. Character and flags use unk8.
- The four post-decrement counters remain s32. Independently changing rows or row to unk32 changes the frame from 0x38 to 0x34 bytes at +0x0A. Changing column changes register allocation at +0x18; changing drawColumn changes the later loop and pool layout (first displayed difference +0xF8).

## Hardware read

GetBGLayerCntPtr returns REG_BG0CNT through REG_BG3CNT (verified in src/layer.c). The read therefore uses `*(vu16*)GetBGLayerCntPtr(...)`, a hardware-register access, not a volatile ordinary field or local.

A nonvolatile `.half` read, either direct or staged in an unk16 local, emits `mov r1,#128; ldrh r0,[r0]` at +0x56. The hardware read emits the target `ldrh r1,[r0]; mov r0,#128` and restores downstream register allocation. Mask operand reversal alone does not fix it.

## Address and lifetime experiments

- Use separate column counters for the allocation and glyph-drawing phases. Reusing one local across both loops changes flags/layer register allocation at +0x18 and the allocation-loop counter register.
- The tile-clear destination is `(RiderTile*)(VRAM + (renderer->layer->characterBaseBlock << 14)) + firstTile`. This and byte-pointer addition starting at `(unk8*)VRAM` match. An integer-only sum reassociates the additions and changes register allocation beginning at +0x78. Casting the already-offset firstTile address to a pointer instead moves its shift ahead of the layer load and makes the clear sequence two bytes shorter.
- The retained layer/font pointers preserve their snapshots across calls. Folding layer changes the stack frame at +0x0A; folding font changes registers at +0x1C.
- Folding tiles, tileWidth, tileHeight, or fontWidth changes the initial register choices at +0x1C and later loads. All four cached values are byte-required.
- Folding allocated into its test and clear-size argument changes the frame at +0x0A. Keep the allocation-delta local.
- Other locals represent evolving cursors, loop counters, a pre-allocation tile snapshot, measured text width, or separate x/y drawing coordinates; they are not single-use aliases.

No layout changes, artificial scopes, gotos, or raw struct-offset accesses were needed. The shared expected symlink already contains the original matching bytes and was not rewritten outside the worktree.
