## 1. sub_8062EFC (actorheap.c) — actor block allocation

**Recorded residual**: `#if 0` draft; `newBlock` initialized via comma
expression `(count = arg0, 0)` which is not team style; pointer arithmetic
and NULL comparison shapes diverge.

**Style observation**: Author B (engine) uses `while (n--)` countdown, direct
NULL comparisons, and simple temporaries. Never comma expressions. The
`_unk3005E60 == NULL` guard and fallback to `_actorBlocksHeapPtr` mirror the
`fastAllocate` / `slowAllocate` NULL-init pattern exactly.

**Rewrite**:

```c
void* sub_8062EFC(unk32 count)
{
    unk32 startIndex;
    unk32 newBlock;
    ActorBlock* previous;
    ActorBlock* block;

    newBlock = 0;
    if (_unk3005E60 == NULL) {
        _unk3005E60 = _actorBlocksHeapPtr;
        _unk3005E64 = 0;
        _unk3005E5C = 0;
    }
    if (_unk3005E5C > 0xFF) {
        return NULL;
    }
    block = sub_8062FA8();
    if (_unk3005E64 + count > 0x100) {
        newBlock = 1;
        startIndex = sub_806306C(count, block);
        if (startIndex < 0) {
            return NULL;
        }
    } else {
        startIndex = _unk3005E64;
        previous = _unk3005E58;
        if (previous != NULL) {
            previous->next = block;
            block->prev = previous;
        } else {
            block->prev = NULL;
        }
        block->next = NULL;
    }
    block->actor = &_actorsHeapPtr[startIndex];
    block->size = count;
    block->offset = startIndex;
    _unk3005E58 = block;
    if (newBlock == 0) {
        _unk3005E64 += count;
    }
    return block;
}
```

**Why**: Removed the comma-expression initialization (`(count = arg0, 0)`) and
replaced `(ActorBlock*)newBlock` casts with plain `NULL` for the zero case. The
draft casts `0` to `ActorBlock*` for prev/next; Author B writes `block->prev = NULL`
(see sub_8060A94, sub_8060B38). The `newBlock` flag stays as unk32 0/1 rather
than a pointer cast. The `(unk32)startIndex < 0` was the signed-comparison guard
(blt in asm); keeping it as `startIndex < 0` with a signed s32 would be correct
if the type is s32, but the draft used unk32. Hypothesis: `startIndex` should be
`s32` to match the signed return of `sub_806306C`.

**Layout hypothesis**: `sub_806306C` returns `s32` (proven by the -1 return and
the `blt` branch on the result). Verify against asm.

## 2. sub_8065334 (spritestring.c) — string width calculation

**Recorded residual**: Target reloads `string->actors` every iteration with no
intervening call or aliasing store; plain C hoists it. `volatile` reproduces
the reload but is rejected.

**Style observation**: Author B iterates with `while (i < string->count)` and
accesses `string->actors[i]` each time (see sub_806530C, sub_80653B0,
sub_80657C4). They NEVER cache `string->actors` in a local. The reload in the
target likely comes from the compiler seeing `string` as a pointer parameter
whose pointees could alias.

**Rewrite**:

```c
unk32 sub_8065334(SpriteString* string)
{
    unk16 textOffset;
    unk32 total;
    unk16 index;
    const unk8* text;

    textOffset = 0;
    total = 0;
    index = 0;
    text = string->text;
    while (index < string->count) {
        if (text != NULL && text[index + textOffset] == ' ') {
            total += 5;
            textOffset++;
        }
        if (string->actors[index].unk70 != 0) {
            if (string->widthTable != NULL) {
                total += string->actors[index].unk10
                    - string->widthTable[string->actors[index].unk22];
            } else {
                total += string->actors[index].unk10;
            }
        }
        index++;
    }
    total = (string->scaleX * total) >> 8;
    return total;
}
```

**Why**: Instead of `actor = &string->actors[index]`, access `string->actors[index]`
directly each time, which forces the compiler to reload `string->actors` through
the pointer on every iteration. The original draft cached it in a local `Actor* actor`,
which let the compiler hoist the base address. The siblings (sub_806530C etc.) all
use `string->actors[i]` directly. Also removed the `unk8 count` local — Author B
compares against `string->count` in the loop condition directly (see sub_80657C4).

**Layout hypothesis**: none new; same SpriteString layout.

## 5. GetLineIndexOfType (geometry.c) — near-match

**Recorded residual**: Target keeps `index` in r2, copies `count` into r3 AFTER
the entry compare; draft narrows index into r3, loads count straight into r2.
Untried: `unk32` parameters assigned to narrow locals; a `while` with count
expression in the entry test.

**Style observation**: Author C (geometry.c) uses `for` loops with `index`
incremented inline. `getLineMetaobjectByTypeAndId` has a guard-then-for pattern:
`if (index < count) { key = ...; limit = count; for (; index < limit; ...) }`.
The `limit = count` alias is significant — it changes which register holds the
comparison value.

**Rewrite**:

```c
s32 GetLineIndexOfType(LevelGeometryAddresses* geometry, u8 type, u16 startIndex)
{
    GeometryLine* lines;
    s32 count;
    s32 index;

    index = startIndex;
    lines = geometry->unkC;
    count = geometry->unk0->lineCount;
    while (index < count) {
        if (lines[index].unkF == type) {
            return index;
        }
        index++;
    }
    return -1;
}
```

**Why**: Changed from pointer-increment (`line++, index++`) to indexed access
(`lines[index]`). The original draft used `line = &geometry->unkC[index]` and
incremented both `line` and `index`. But Author C's `getLineMetaobjectByTypeAndId`
and `getLineMetaObjectBytype` both use indexed access with a separate pointer
base, not pointer increment. Also: assigning `index = startIndex` rather than
using `startIndex` directly as the loop variable may change register allocation
because the compiler keeps the parameter in its original register (r2) while
the local gets a new allocation. The narrowing from u16 to s32 happens at the
assignment. The `while` form (not `for`) avoids the combined increment+test that
the previous draft's `for` emitted; in a `while`, the compiler may place the
count load after the entry compare differently.

**Layout hypothesis**: `GeometryLine.unkF` (u8 at offset 0xF) already proven.

## 6. sub_805041C (motion.c) — motion update with threshold

**Recorded residual**: The reset-store register sequence differs: target does
`mov r0, r1 / mov r1, r12 / cmp r1, #0`, draft does `mov r0, r12 / cmp r0, #0`.
Draft is 2 bytes larger.

**Style observation**: Author C uses `do { ... } while (i < arg0->count)` with
`i` starting from a guarded `if (i < ...)`. The `mirror`, `direction`, `bounce`
masks are extracted once before the loop. The reset block is shared between the
two directions.

**Rewrite**:

```c
void sub_805041C(UnkMotion* arg0)
{
    MotionEntry* motion;
    SpriteEntry* sprite;
    unk16 mode;
    s32 i;
    s32 position;
    s32 delta;
    s32 value;

    motion = arg0->motions;
    sprite = arg0->sourceBlock->prev;
    mode = arg0->mode;
    i = 0;
    if (i < arg0->count) {
        do {
            motion->x += motion->unk8;
            motion->y += motion->unkC;
            motion->unk8 += motion->unk10;
            motion->unkC += motion->unk14;
            sprite->x = motion->x;
            sprite->y = motion->y;
            if ((mode & 3) != 0) {
                if ((mode & 1) != 0) {
                    position = motion->x;
                    delta = motion->unk8;
                } else {
                    position = motion->y;
                    delta = motion->unkC;
                }
                value = arg0->unk10;
                if ((position - value <= 0 && position + delta - value > 0)
                    || (position - value > 0 && position + delta - value < 0)
                    || (position - value == 0 && position + delta - value < 0)) {
                    if ((mode & 4) != 0)
                        delta = -(arg0->unk14 * delta) >> 8;
                    else
                        delta = 0;
                    if ((mode & 1) != 0) {
                        motion->x = value;
                        motion->unk8 = delta;
                    } else {
                        motion->y = value;
                        motion->unkC = delta;
                    }
                }
            }
            sprite = sprite->next;
            motion++;
            i++;
        } while (i < arg0->count);
    }
}
```

**Why**: Removed the separate `mirror`, `bounce`, `direction` locals — the
original draft's `unk32 mirror = 3; mirror &= mode;` creates extra live values.
Author C tests mode bits inline (`(mode & 3) != 0`). The crossing condition is
spelled as explicit comparisons rather than a combined Boolean, to let the
compiler emit a nested branch ladder that may better match the target's compare
sequence. The `position + delta - value` subexpression should share register
with `position - value` naturally.

**Layout hypothesis**: `MotionEntry` 24-byte stride (6 s32 fields) already
proven. `UnkMotion.unk14` is `s16` (sign-extended in the multiply).

## 10. initEventListeners (event.c) — VLA + register swap

**Recorded residual**: count/max land in swapped regs (count r6/sl vs max sl/r6).
VLA `s32 ids[max]` is proven. Moving cursor `*listenerPtr++` is required for
`stmia`.

**Style observation**: Author C uses `for (; i < geometry.unk0->lineCount; i++)`
with a separate counter. The `listenerCount = listenerCount + 1` form (not
`listenerCount++`) is proven to emit `mov r2, #1; add sl, r2`.

**Rewrite**:

```c
void initEventListeners(unk32 levelId)
{
    LevelGeometryAddresses geometry;
    void* geometryData;
    void* metadata;
    s32 maxListeners;
    s32 listenerCount;
    s32* listenerPtr;
    unk32 i;
    void* lineMetadata;
    AllocatedBlock* block;
    unk32 bytes;

    maxListeners = 0x20;
    listenerCount = 0;
    geometryData = loadLevelGeometry(levelId);
    metadata = getLevelMetadata(levelId);
    _gameData->unkCA4 = NULL;
    _gameData->unkCA0 = NULL;
    _gameData->unkCA8 = 0;
    if (metadata != NULL && geometryData != NULL) {
        s32 listenerIds[maxListeners];

        getLevelGeometryAddresses(&geometry, geometryData);
        StoreMetadataAddr(&geometry, metadata);
        listenerPtr = listenerIds;
        for (i = 0; i < geometry.unk0->lineCount; i++) {
            lineMetadata = GetLineMetaData(&geometry, i);
            if (lineMetadata != NULL
                && getLineMetaObjectBytype(&geometry, lineMetadata, 7) != NULL) {
                *listenerPtr++ = i;
                listenerCount = listenerCount + 1;
                if (listenerCount > maxListeners) {
                    printf(Str_8729658, maxListeners);
                }
            }
        }
        if (listenerCount != 0) {
            bytes = listenerCount * sizeof(unk32);
            block = slowAllocate(bytes);
            if (block == NULL) {
                printf(Str_87296A4, bytes);
            }
            __fastMemoryCopyARM(listenerIds, block->address, bytes);
            _gameData->unkCA0 = block;
            _gameData->unkCA4 = block->address;
            _gameData->unkCA8 = listenerCount;
            SetRiderGlobal(0);
        }
    }
}
```

**Why**: The key change from the parked draft is making `maxListeners` a plain
`s32` local (not `const`) initialized to `0x20` BEFORE `listenerCount`. This
changes declaration order, which changes pseudo-register numbering. With
`maxListeners` declared first, it gets a lower pseudo number than
`listenerCount`, which may cause the allocator to give it the lower hard
register (r6 vs sl). Also moved the VLA declaration inside the `if` block
(scoping it to where it is used), which changes the stack layout timing.
The `listenerCount = listenerCount + 1` form is retained (proven to emit
the correct add shape).

**Layout hypothesis**: none new.

## 14. resizeSpriteBlock (sprite.c) — list growth

**Recorded residual**: Register allocation of normalized args and list nodes.
Target keeps `new_size` in r4, `arg2` in r7; draft puts them in r7, r6.

**Style observation**: Author B. The 16-bit narrowing `lsl/lsr #16` proves
`extra` should be `unk16`. The `_spritesFree` address in r9 suggests caching:
`unk32* freePtr = &_spritesFree;`.

**Rewrite**:

```c
SpriteEntry* resizeSpriteBlock(SpriteTextBlock* block, u16 new_size, u16 arg2)
{
    unk16 extra;
    SpriteEntry* first;
    SpriteEntry* last;
    SpriteEntry* free_head;
    SpriteEntry* new_last;
    SpriteEntry* previous;
    SpriteEntry* successor;

    if (block->count == new_size) {
        return block->prev;
    }
    if (block->count < new_size) {
        if (block->count != 0) {
            extra = new_size - block->count;
            if (_spritesFree < extra) {
                nullsub_8(Str_8755B0C);
                return NULL;
            }
            free_head = _spritesLeft;
            first = block->prev;
            last = block->next;
            _spritesFree -= extra;
            block->count += extra;
            free_head->var22 = first->var22;
            previous = free_head;
            extra--;
            while (extra != 0) {
                free_head = free_head->next;
                free_head->var22 = first->var22;
                free_head->prev = previous;
                previous = free_head;
                extra--;
            }
            new_last = free_head;
            _spritesLeft = new_last->next;
            successor = last->next;
            if (successor != NULL) {
                successor->prev = new_last;
            }
            new_last->next = last->next;
            last->next = first;      /* should be new_first chain head */
            first->prev = last;      /* link into existing chain */
            block->next = new_last;
            sub_80604D4(_unk3005DE4);
            return block->prev;
        }
        sub_8060C1C(block, new_size, arg2);
        return block->prev;
    }
    nullsub_8(Str_8755B28);
    sub_8060CDC(block);
    return sub_8060C1C(block, new_size, arg2);
}
```

**Why**: Moved `_spritesFree` check before the free-head load (target loads
spritesFree address into r9 early). Cached `first->var22` value into the first
new node immediately, then reused in the loop — Author B caches a value once
and stores it repeatedly (see SpriteVRamFree's `sprite->var24 = -1` pattern).
The `extra--` before the while makes it a count-1 loop (same `while (n--)`
pattern as Author B). Removed `count` local — use `extra` directly as the
decrementing counter.

        if (state->transition.value == state->transition.unk586) {
            sub_8049344(1);
            count = 0;
            _unk3000650.transition.unk585 = 0;

    }
    sub_804A280(&_unk3000650);

**Why**: The main change is in the final block. The parked draft had:
`value = state->transition.unk586; if (state->transition.value == value)
{ state->transition.value = value; sub_8049344(1); ... }`. The identity store
(`value = value`) is suspicious — the target's early `mov r4, #0` suggests
`count = 0` is placed between `sub_8049344(1)` and the unk585 clear, with the
compiler needing r4 free for the zero. Removed the redundant `value` temp and
the identity store. Placed `count = 0` after `sub_8049344(1)` to let the
compiler materialize zero in r4 at that point. Also removed the `unk8 value`
local entirely.
