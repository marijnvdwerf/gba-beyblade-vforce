# Animation matching notes

## sub_805F0B4 (0x0805F0B4)

Matched. The function initializes an `AnimFrameState` from two relative-offset animation resource headers, releases an existing allocation, chooses fast or slow allocation based on the byte flag, initializes the frame buffers and state fields, reports allocation failure through `Str_875566C`, and calls `sub_805F378` with frame `-1`. The matched source required a conditional-expression overlay pointer, repeated inline allocation-size expressions, and the measured initialization store order. `AnimFrameData` was extended with the accessed header offsets and `AnimFrameState` gained the accessed pointer fields at `0x1C` and `0x64`.

## sub_805F910 (0x0805F910)

Matched. The function walks an 8-byte command table, selects the record with the smallest signed `unk4` among three indexed 16-byte records, converts the selected value with signed fixed-point scaling, bounds-checks it against the signed halfword at the visitor input, and invokes the callback at offset `0x10` with the input and command index. The first two-record selection is expressed as `selected = first->unk4 <= second->unk4 ? first : second`; this emits the target's `bgt` path retaining `second` and fall-through selecting `first`. The third-record comparison uses `if (selected->unk4 > third->unk4) selected = third`.

The live source uses a dedicated command layout and the shared `AnimFrameRecord` layout. Retyping `AnimFrameRecord.unk4` to `s32` is supported by the signed comparisons and fixed-point conversion; `sub_805F8D4` and `sub_805F8EC` remained byte-identical after the shared-field change. Correcting the prior draft's inverted first comparison changed the semantics to the target's minimum selection and, with the conditional expression, matched the complete function. `AnimFrameState->unk8` is now the typed `AnimFrameCommand*`; the offset-table initializers in `sub_805F0B4` and `sub_805F1EC` use the explicit cast at the relative-offset assignment, and `sub_805F1EC` takes the established `AnimFrameData*` header view. Both initializer functions remained byte-identical. The loop indexes `state->unk8[i]` and `state->unk10[...]` directly without cast-based second views.

### sub_805F0B4 shape audit

- Copying the allocation flag to a local was unnecessary: direct use of the `unk8` parameter matched all instructions. Retyping the parameter to `unk32` diverged first at target offset `0x08`: the target has `ldr r0, [sp, #20]; lsl r0, #24; lsr r7, r0, #24`, while the wide-parameter variant loads directly into `r7` without byte normalization.
- The direct overlay conditional assignment matched exactly; the temporary was not required. Replacing it with explicit `if/else` assignment diverged first at `0x24`; the target materializes `mov r1, #0` before `cmp r0, #0`, while the alternative reused `r0` and changed the branch/store sequence.
- Keeping the three `sharedData` tests separate is required. Merging the first two tests diverged first at `0x3c` when the target's `cmp r6, #0` / `beq 0x46` became a different shared branch. Merging all three tests likewise diverged first at `0x3c` and changed the allocation/control-flow layout.
- Hoisting the fast/slow allocation above the `sharedData == NULL` branch is rejected. It diverged first at `0x60`: the target compares `r6` (`cmp r6, #0`) for the branch, while the hoisted variant compares `r7` (`cmp r7, #0`) and emits a different branch layout. The duplicated allocation block was restored.
- Renaming the live parameters to `data`, `sharedData`, and `useSlowHeap` produced no instruction differences; `arg3` remains unnamed semantically because it is unused in this function.

## sub_805F3D8 (0x0805F3D8, src/anim.c) — matched 2026-09-20

Retry of a parked one-liner draft. The body is one SDK `DmaCopy(3, ..., 32)`
(the trailing `ldr r0, [r3, #8]` readback is the macro's, not source).

Two things were wrong in the parked draft.

**Size local must be signed.** The target divides by 4 with `lsl r0, r2, #1;
asr r0, r0, #2` — an `asr` with no rounding correction. `unk32 stride` makes
combine fold `*10 / 4` into a single `lsr r1, r1, #1` and shrinks the function
to 36 bytes; the field feeding it (`AnimFrameData::unk4`) stays `unk16` and is
still loaded with `ldrh`, so the signedness lives in the `s32` local only.
Passing the expression inline (no local at all) moves the whole stride
computation *after* the two register stores.

**Source and destination are locals, assigned before the call, destination
first.** Target order is `ldr r1, [r0, #4]` (dest), `ldr r0, [r0, #0x10]`
(src), then `ldr r3, =0x040000D4`. Passing `arg0->unk10` / `arg0->unk4`
directly as macro arguments materialises `DmaCntp` first (it is the macro's
first statement) and interleaves load/store pairs. Assigning src before dest
diverges at 0x08 (the two loads swap registers).

Probe matrix (scratch TU compiled through `tools/agbcc` with the build's exact
flags, symbol byte-compared against `expected/build/us/.../anim.c.o`):

| variant | shape | first divergence |
| --- | --- | --- |
| v1 | `DmaCopy(3, arg0->unk10, arg0->unk4, arg0->unk0->unk4 * 10, 32)` | 0x00 |
| v2 | `unk32 stride` local, fields inline | 0x00 (36 bytes) |
| v3 | `s32 stride` local, fields inline | 0x08 |
| v4 | `s32 stride`, `src` then `dest` locals | 0x08 |
| v5 | `s32 stride`, `dest` then `src` locals | match |
| v6 | v5 with the `data` local folded away | match |

Fold results: the `AnimFrameData* data` local that neighbours
`sub_805F378`/`sub_805F3A8` keep is *not* required here (only one use) and was
removed — v6 is what shipped. `stride`, `dest` and `src` are all byte-required.

## sub_805F27C (0x0805F27C, src/anim.c) — matched 2026-09-21

Retry of a parked draft. Three independent defects, found one at a time with a
scripted probe matrix (scratch copy of the TU compiled through `tools/agbcc`
with the build's exact flags, symbol bytes compared against
`expected/build/us/.../anim.c.o`).

### Semantic bug in the parked draft

The draft wrote the second VRAM term as `(block >> 13) << 9`. The target is
`asr r0, r2, #0x13` where `r2` holds `block << 16`, i.e. `(s16)block >> 3`,
not `>> 13`. Same for the destination base: the draft used `VRAM` where the
pool word is `0x06010000` (`VRAM + 0x10000`, OBJ VRAM).

### Widths and signedness

* `AnimFrameDrawInput::unk30` is `s16`: `ldrh` then `lsl #16; asr #22`, i.e.
  sign-extend-then-shift-6. An unsigned field would give a bare `lsr #6`.
* `offset` and `block` are both `s16` locals. Evidence: `asr r1, r0, #0x11`
  for `offset >> 1` (signed shift), the signed `cmp #3 / ble` on `block & 7`,
  and the `lsl #16; lsr #16` narrowing of both arms of the `block` rounding at
  their join. agbcc keeps HImode pseudos zero-extended and sign-extends on
  read, so every read is `lsl #16; asr #16`.
* The draft's `s32 block` loses the join narrowing.
* `rows` (the int staging temp) matches as `unk32` and as `s32` — unsigned
  wins by the project default. The callback's 6th/7th parameters match as
  `unk32` and as `s32`; `unk32` shipped.
* The `(unk32)arg4` cast in the draft is unnecessary once the callback's 4th
  parameter is typed as the input-struct pointer.

### Byte-required shapes

**1. `block += 8 - (block & 7);` not `block = block + 8 - (block & 7);`**
The target is `mov r0, r1; add r0, #8; sub r0, r2` — the literal
`(block + 8) - rem` tree. Written as `block = block + 8 - (block & 7)`, fold
reassociates `(A + C) - B` into `A - (B - C)` and emits `sub r0, #8;
sub r0, r1, r0`. The compound `+=` blocks that reassociation. (The draft
already used `+=` for the second rounding, which is why only the first one was
wrong.)

**2. The subtraction result must be staged in a wide temp: `offset -= block;
rows = offset;`** The target narrows the difference to `s16`
(`lsl #16; asr #16`) but never stores it — the single `lsl #16; lsr #16` store
into `r4` sits at the join after the rounding branch. Writing
`offset -= block; if (...) offset += ...;` (the draft) emits a second store
right after the subtraction, because `offset` is live on the fall-through
path: 12 instructions where the target has 11, first divergence 0x02 by way of
the changed frame. `rows = offset;` makes that first store dead (flow deletes
it) while keeping the `lsl; asr` narrowing that a plain `s32 rest = offset -
block;` would not produce at all.

**3. The rounding needs an explicit `else` arm that repeats the store.**

```c
    offset -= block;
    rows = offset;
    if ((rows & 7) != 0) {
        rows += 8 - (rows & 7);
        offset = rows;
    } else {
        offset = rows;
    }
```

Without the `else` (assigning `offset = rows;` once after the `if`), agbcc
globally CSEs `(s16)block` — the sign-extended copy computed for
`offset - block` gets kept alive and reused for both callback argument sites,
instead of being recomputed there as `asr r0, r2, #0x10`. That one extra
long-lived pseudo pushes the function from five saved registers to six: `arg4`
lands in `r8` (`mov r7, r8; push {r7}`, `mov r8, r0`) and `arg3` is copied out
of `r3`, where the target leaves it untouched for the whole body. With the
`else` present, both arms end in `lsl #16; lsr #16` and cross-jumping merges
them into the single join store, and the CSE does not happen.

The duplicated store is the only form found that produces both effects;
inverting the condition (`if ((rows & 7) == 0) offset = rows; else {...}`)
matches identically, as does spelling the first branch's early `return` with
or without a following blank line.

### Other notes

* The stack-argument layout confirms five parameters: `ldr r7, [sp, #0x24]`
  with five pushed registers and a 0x10-byte frame reads the first stack
  argument.
* `arg3` is never touched between entry and the argument moves — the allocator
  gives its pseudo `r3` itself, so no entry copy is emitted. That only happens
  at five saved registers.
* The destination expression `VRAM + 0x10000 + (arg0->unk4E << 5) +
  ((block >> 3) << 9)` reproduces the target's grouping
  (`((block >> 3) << 9) + const`, then `+ (unk4E << 5)`) without any manual
  reassociation.
* The two callback argument slots that receive a literal `0` reuse the
  register left holding the just-tested value (`(u16)(unk52 & 2)`, then the
  `ldrb` of `unk4D`); writing `0` in the source is correct.

- sub_805F27C round-up block (fold-check 2026-09-21): `offset = (offset + 7) & ~7;`, `rows = (offset + 7) & ~7; offset = rows;` and an in-place `if ((offset & 7) != 0) offset += 8 - (offset & 7);` on the s16 each first diverge at 0x02 (prologue save set); the `rows` staging block with the duplicated else-store stays, with its TODO. `OBJ_MODE0_VRAM` replaces `VRAM + 0x10000` byte-identically.
