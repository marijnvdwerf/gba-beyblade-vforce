Matched entirely in C (572 bytes). No inline asm, register declarations,

The previous parked analysis is superseded by the measurements below.

## Recovered behavior and types

The function uploads one sprite frame to OBJ VRAM. Uncompressed frames use
the indirect copy helper. Compressed frames use mask bits to choose between
copying source tiles and clearing destination tiles, with 32-byte or
64-byte tile sizes. The scanned zero-run path calls fastMemoryCopyARM
directly; it is not another indirect __fastMemoryCopyARM call.

SpriteSheet has a header-size byte at +0x0D and a tile-count halfword at
+0x0E, replacing its former three padding bytes without moving later fields.
The variable-size image header contains a word mask at +0 and an optional
second WORD at +4 (ldrhi, not ldrh). The old draft and note incorrectly
identified that second mask as a halfword. SpriteImageHeader supplies the
single shared record type; dynamic sheet offsets remain byte offsets into
the variable-size sheet blob.

The header tile count is loaded with ldrh, then held in signed s32 because
the target uses ble and signed comparison against 32. The mask remains
unsigned because its shifts are logical. The existing signature stays
s32 ARM_sub_8756A84(SpriteEntry*, unk16, s32); the caller normalizes the
byte-count argument to 16 bits, and the callee returns the original third
argument from its stack slot.

The zero-mask path computes count = tileCount - (tileCount > 32) * 32,
subtracts that count, and unconditionally restores the saved second mask.
The nonzero-mask paths share the tile-count subtraction and conditional
mask restoration after their clear/copy branches. Keeping that update
inside each branch duplicates instructions and changes register allocation.

The word incremented at 0x03005E70 is now _unk3005E70, declared in ram.h
and defined as unk32 in ram3.c. This replaces the same four bytes previously
named pad_3005E70. No IWRAM addresses or ROM bytes move.

The distinct source snapshot and compressed record pointer have real roles:
the former is computed before the compression test, while the latter points
to the mask header. Combining them changes pseudo lifetimes and early
register allocation. No inline asm was necessary to recover those roles.

## Cast cleanup at the sprite definitions

Removed the redundant cast on SpriteEntry.unk28: its canonical declaration
already is const unk8*. Moved SpriteImageHeader from iwram.h to sprite.h,
next to the sprite definitions, and introduced typed inline accessors:

- spriteSheetImageHeader resolves the relative offset table and frame header.
- spriteSheetImageData resolves the variable-size header's payload.

The function now contains only the two integer-to-pointer conversions for
OBJ VRAM addresses. The accessors retain the necessary byte-blob conversions;
the ROM stores relative integer offsets, so changing SpriteSheet.unk10 or
unk1C into pointer fields would be incorrect. A byte-base local in the
header accessor also avoids casting the sheet twice.

An initial payload helper taking the header-size scalar as an argument
added a reload and changed register allocation: 576 bytes (+4), first
difference +0x14 (frame loaded into lr instead of r4). Reading the size from
the typed sheet inside the helper instead preserves the original shared
load. The final accessors inline with identical output; full US and EU ROM
SHA1 checks pass after rebuilding all shared-header consumers.
