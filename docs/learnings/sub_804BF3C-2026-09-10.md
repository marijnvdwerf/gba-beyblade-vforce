# sub_804BF3C (0x0804BF3C, src/rider.c) — matched 2026-09-10

FX-sprite tile streamer (positions rider->unk3C0 on the 8x8 tile grid under
the rider sprite and refreshes up to 4 rows of tiles via sub_805EF18 /
__fastMemoryClearARM). Parked draft used scratch RiderDraft* structs; ~25
builds on real types.

Header / prototype changes:
- `RiderTileState` (common.h) embedded in RiderBase at 0x3D8
  {s32 unk0 (last tile x); s32 unk4 (last tile y); pad8[4]; s32 unkC (row
  count)}. Target keeps `&rider->unk3D8` in r6 from entry and addresses
  [r6,#0]/[#4]/[#0xC]; a record pointer `tiles = &rider->unk3D8` is
  byte-required (fold → 69 rows). unk3E0 (initRider draft only) stays pad.
  sub_804C098's `rider->unk3E4 = 0` → `rider->unk3D8.unkC = 0` (0 rows).
- RiderBase `unk16 unk3CA` (ldrh), `unk8* unk3D4` (VRAM tile buffer).
- BGLayer.field_C `unk32` → `s32` (`asr #11` of field_C and of
  `sprite->x + field_C`); matches field_10. Compiled users store only.
- sub_805EF18's destination and `__sub_87576D8`'s 5th parameter
  `unk32` → `unk8*` (so the same `rider->unk3D4 + (n << 7)` feeds both
  sub_805EF18 and __fastMemoryClearARM without a cast); sub_805EF18
  re-diffed 0 rows.
- The parked draft's `unk32 arg1` was already removed with renderRider.

## Review measurements (2026-09-10)

- Signedness sweep: changing `dx` from `s32` to `unk32` preserved the exact
  function and ROM; `unk32` is retained. Changing `dy` from `s32` to `unk32`
  also preserved the exact function and ROM; `unk32` is retained.
- Changing `clearCount` from `s32` to `unk32` failed the ROM compare. The first
  instruction divergence was at `sub_804BF3C+0xB6`: target `ble` versus the
  candidate `beq`. `s32` is retained, with the signed branch as evidence.
- Changing `newRows` from `s32` to `unk32` preserved the exact function and ROM;
  `unk32` is retained.
- Folding the `tiles` row storage to typed indexing was measured across
  `sub_804BF3C` and `sub_805EF18`. The final shape is a 0x20-byte `RiderTile`
  and four-element `RiderTileRow`, with `RiderBase.unk3D4` typed as
  `RiderTileRow*`; clear addresses use `&rider->unk3D4[rowCount]` and lengths
  use `sizeof(RiderTileRow)`. `sub_804BF3C` and `sub_805EF18` both diff exact and
  the full ROM compare passes. The initial struct spelling with an inline
  `tiles[4][0x20]` member first diverged in `sub_805EF18+0x0A` (target frame
  allocation 12 bytes, candidate 16 bytes), so it was replaced by the array
  typedef spelling.

## Follow-up measurement (2026-09-10)

- The callback fifth parameter was changed from the array-typedef form
  `RiderTile` to pointer form `RiderTile*`; `sub_805EF18` correspondingly
  passes `destination` rather than `*destination`. The full ROM compare passed,
  and `sub_805EF18` re-diffed exact (including its 12-byte frame and callback
  argument setup). The ARM-bank declaration in `src/iwram.h` was aligned to
  the same `RiderTile*` fifth parameter; this declaration-only change also
