# particle.c — sub_804EA88 (0x0804EA88, 352 B) — matched 2026-09-13

Unparked the `#if 0` draft in `src/particle.c`. The draft was wrong in two ways
(missing the `unk10/unk12/unk14` accumulation entirely, and it stored `0xA000`
to both sprite coordinates); everything below is measured against
`expected/CMakeFiles/rom.dir/src/particle.c.o`. Offsets are function-relative.

## Types proven by this function

`Particle` (common.h, 0x24, unchanged size):

- `unk10`, `unk12`, `unk14`: `unk16` → `s16`. `mov r0,#16 / ldrsh r2,[r3,r0]`
  at 0x66 (also #18 at 0x6E, #20 at 0x76).
- `0x16`/`0x18`: were inside `unk8 pad16[4]`; now `s16 unk16`, `s16 unk18`.

  `!= 0` test. The *same* field is also loaded `ldrh r4,[r3,#26]` at 0x40 —
  that is not a union: see "mixed-width read" below.

`ParticleSystem.unkC`: `unk32` → `BGLayer *`. Not from this function's asm
(which only needs a 4-byte field at +0x40/+0x44) but from the caller chain:
`initRider`'s `arg1` goes to `actor_8057C58(Actor*, ActorConfig*, BGLayer*, …)`
(src/actor.h:6) and to `allocateParticleSystem(…, arg1, 1)` (src/rider.c:95),

reads are `BGLayer.field_40` / `field_44` (`ldr r0,[r4,#64] / and r0,r1` at

## Local declarations — measured, one variant per compile

Every declared type below was re-tested by substituting the alternative and
comparing the whole function; "identical" means instruction-for-instruction
equal to the matching build.

| local | committed | alternative tested | result |
|---|---|---|---|
| `count` | `s32` | `unk32` | **differs** — see below |
| `x` | `s32` | `unk32` | **differs** — `asr r1,#1` → `lsr` at 0x9C |
| `y` | `s32` | `unk32` | **differs** — `asr r1,#1` → `lsr` at 0x9C |
| `z` | `unk32` | `s32` | identical → default `unk*` kept |
| `screenX` | `s32` | `unk32` | **differs** — function collapses 170 → 95 insns |
| `screenY` | `s32` | `unk32` | **differs** — `ble` → `bls` at 0xE2 |
| `timer` | `unk32` | `s32` | **differs** — `bls` → `ble` at 0x10C |
| `timer` | `unk32` | `unk16` | identical (width is free here; unsignedness is not) |

- **`count` must be signed.** `s32` gives the old-value countdown
  `mov r0,ip / mov r1,#1 / neg r1,r1 / add ip,r1 / cmp r0,#0 / beq` at
  0x13E..0x148. `unk32` instead emits `mov r0,#1 / neg r0,r0 / add ip,r0 /
  cmp ip,r0 / beq` — no old-value copy, and the *decremented* value compared
  against -1 — which is two insns shorter and also perturbs the loop-top
  register allocation (first divergence at 0x3C: `mov r2,#26` → `mov r1,#26`).
  This is the documented signed/unsigned post-decrement split, measured here.
- **`x` and `y` are signed because of the isometric halving.** `(x + y) >> 1`
  emits `asr r1,r1,#1` at 0x9C only when both operands are signed; making
  either one `unk32` makes the sum unsigned and emits `lsr`. That shift is the
  only signedness evidence for these two.
- **`z` has no signedness evidence** — it is only ever subtracted
  (`sub r1,r7` at 0x9E) — so it stays `unk32` even though it sits in the same
  coordinate triple as `x`/`y`. Both spellings are byte-identical.
- **`screenX`/`screenY` are signed** because the source bounds are negative:
  `screenX > -0x400` with an unsigned type is a different predicate and agbcc
  folds most of the guard away (95 insns).

## Byte-required shapes (measured, one change per build)

1. **`particle->unk1A--` with no temporary.** The target loads the field twice
   in the loop-top block: `ldrsh` (the `!= 0` test, s16 field) at 0x3E then
   `ldrh` + `mov r9,r4` at 0x40, *before* the `cmp/beq`. Reproducing that does
   **not** need a second local: agbcc hoists the `ldrh` of a plain
   `particle->unk1A--` written deep inside the two nested `if`s all the way up
   into the loop-top block, keeps the value in r9 across the whole body, and
   emits `mov r4,r9 / sub r4,#1 / strh r4,[r3,#26]` at 0xCE. The later
   `&& particle->unk1A != 0` reuses the stored value (`lsl r0,r4,#16 /
   cmp r0,#0` at 0xEA). The HImode read-modify-write is why the load is `ldrh`
   on an `s16` field: agbcc emits a plain `movhi` load there.
   - A `unk16 frames = particle->unk1A;` read *before* the `if` emits the
     `ldrh` first and the `ldrsh` second (loads swapped, r2/r4 swapped).
   - The same read as the *first statement inside* the `if` leaves the `ldrh`
     after the `beq` (2 insns late).
   - A diagnostic two-local version (`s32 life` + `unk16 frames`) also
     reproduces the target top, but the plain `--` does too, so no duplicate
     alias is needed.

2. **`SpriteEntry *sprite = particle->sprite;`** (record pointer, loop-body
   scope). Without it, `sprite->frame.word++`'s `strh` invalidates the CSE of
   `particle->sprite` and agbcc reloads `ldr r2,[r3,#0]` before the frame
   compare (extra insn at 0x13C in the draft), and the sprite/`z` register
   roles swap (r7/r6 instead of r6/r7, first visible at 0x60). Adding the
   local fixed both in one build.

3. **`unk32 timer = particle->unk20;`** is byte-required for `cmp r0,#16 /
   bls` at 0x114: `particle->unk20` is `unk16`, so testing the field directly
   promotes to `int` and yields the signed `ble` (measured: `timer` as `s32`
   gives `ble` at 0x10C).

4. **`particle->unk20 = timer + (particle->unk22 - 0x10);`** — the
   parenthesisation is load-bearing. agbcc's `fold` always re-pairs the
   constant with the operand *outside* the parentheses, and the whole RHS is
   narrowed to HImode, so `-0x10` materialises as the pool word `0xFFF0`:
   - `(timer - 0x10) + particle->unk22`, `particle->unk22 + (timer - 0x10)`
     and `timer + 0xFFF0 + particle->unk22` all compile to
     `ldrh unk22 / ldr =0xFFF0 / add r0,r2,r4 / add r0,r?,r0` — constant glued
     to `unk22` — and additionally force `add r0,r1,#0` (a copy of `timer`)
     in the *other* arm, because `timer` then dies last.
   - `particle->unk22 + timer - 0x10` keeps the constant last (`sub r0,#16`,
     no pool) — also wrong.
   - `timer + (particle->unk22 - 0x10)` gives the target
     `ldr r1,=0xFFF0 / add r0,r1 / ldrh r2,[r3,#34] / add r0,r2,r0` at
     0x11E..0x124: the `particle->unk22` operand stays a MEM through expand and
     is only forced into a register right before the add, which is why its load
     lands *after* the constant add and why it is `Rn` of the final `add`.
     `particle->unk20 -= 0x10;` / `particle->unk20 += particle->unk22 - 0x10;`
     is byte-identical; the `timer …` spelling was kept for symmetry.

5. **All six pre-loop locals are byte-required** (`systemX/Y/Z`, `dx/dy/dz`).
   Note each `systemN` has *two* consumers — its own delta and the coordinate
   sum — so they are not single-use. Folding any one of them into its use makes
   agbcc keep `arg0` live in a register across the whole loop
   (first divergence at 0xC: `mov r2,#4` → `mov ip,r0`) and grows the function
   from 170 to 176–178 insns. Measured individually for all six.

6. **`z` is byte-required as a temporary** even though it has one consumer: the
   target computes `add r7,r0,r1` at 0x88, before `cmp r5,#0`. Inlining it into
   the `aux != NULL` arm diverges at 0x18 (`ldr r5,[r0,#16]` → `ldr r6,…`) and
   fails `compare`.

7. **The two `if (aux != NULL)` blocks must stay split.** Merging the offset
   subtraction into the isometric arm (one conditional, offsets applied inside)
   diverges at 0x16 — `aux` moves from r8 to r9 — and reshapes the body.

8. **Loop-entry `b`**: the target's single `b 0x13E` into the bottom test is
   *not* an unrotated `while`. agbcc duplicates the exit test at the entry and
   then cross-jumps the two identical copies. Any register difference between
   the two copies blocks the merge and leaves 6 extra insns at the entry — in
   the intermediate candidates the bottom copy used `mov r5,#1 / neg r5,r5`
   while the entry copy used r1. Fixing the timer arm (item 4) moved the bottom
   test's constant back to r1, the copies became identical, and the entry
   collapsed to `b`. An unexplained entry-test duplication is a *downstream*
   symptom: fix the body's allocation first.

9. Coordinate range test: `screenX > -0x400 && screenX <= 0xF3FF &&
   screenY > -0x400 && screenY <= 0xA3FF && …` — agbcc folds only the first
   adjacent pair into the unsigned range check
   (`add r1,r5,#0x3FF / cmp 0xF7FE / bhi` at 0xD4) ; the `screenY` pair is no
   longer adjacent in the left-associated `&&` tree, so it stays as two signed
   compares (`ble` at 0xE2 / `bgt` at 0xE8). Writing the natural signed bounds
   is enough; no `(unk32)(v + K)` cast is needed.

10. The off-screen arm assigns **only** `sprite->y = 0xA000` (one
    `str [r6,#12]` at 0x110 in the target; the two arms' `y` stores are
    cross-jumped into one).
