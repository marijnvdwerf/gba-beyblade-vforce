Address: 0x08045CB4

Status: matching C implementation in `src/festate.c`; assembly dump removed.

## Matching details

- Keep distinct case-1 locals for the two font positions and scroll delta.
- Apply each horizontal animation expression directly with `sprite->x += ...`,
  including the final scroll adjustment. Staging the expression in an `offset`
  local reverses the sprite-pointer reload and scalar-global address load after
  `sub_8057C40()` in both animation blocks.
- The music helpers accept `unk32` arguments and narrow them into a `u16 volume`
  local. This preserves the helpers' original normalization instructions while
  allowing the frontend's shifted arguments to pass without caller narrowing.
  The existing restore call in `sub_804AD28` retains an explicit `u16` cast.
- The frontend globals use signed coordinates, typed sprite pointers, two
  `SpriteTextCleanup` objects, and a byte-sized selection at `_unk3000460`.
  `_unk30003F0` retains its eight-byte `FrontendScalarWithPad` layout.

## Fold-skill pass

command as the acceptance gate. Each experiment verified the matching baseline;
rejected candidates were restored automatically. No baseline was refreshed.

Accepted: substitute literal zero for the constant `zero` local; remove `frame`
and increment/decrement the sprite frame field directly. The decrement guard
excludes zero, and the increment guard limits the value to 9, so the 16-bit
store loses no information needed by the subsequent shifted argument. No call
intervenes between the field update and argument evaluation. Both changes keep
the function at 0x524 bytes and preserve the complete ROM SHA1.

## Music signature control experiment

Restored both helper declarations and definitions from `unk32` to `u16`,
leaving the helper bodies unchanged, then rebuilt with the authoritative ROM
compare command. The build succeeded but the ROM comparison failed (SHA1
`0b8e18a563c164b3a023fb6e48846f37e2aaad5d`). In `sub_8045CB4`, the target's
`lsl r0, #5` at offset `0x3C4` became `lsl r0, #21` followed by
`lsr r0, #16`; additional shifted calls also gained narrowing instructions.
Restoring the `unk32` signatures restored the passing original-ROM SHA1.
This establishes that the wider signatures are required by the tested source
form, rather than claiming that every alternative C formulation is excluded.

Music cast fallback test (2026-09-08):

Restoring the wide `unk32` helper prototypes and removing only the explicit `(u16)` cast at `sub_804AD28` changed the caller. The target uses `ldrh r0, [r0, #0]` at function offset `0x00000004`; the cast-free candidate uses `movs r1, #0` followed by `ldrsh r0, [r0, r1]`, and the caller symbol grows from `0x1c` to `0x20` bytes because the literal pool moves. The full candidate ROM SHA1 was `ec1dfe84b2648b58174aa2e4130d4c09880a910c` versus the baseline `cd527c8c24e20e33913fc45199e64b3e6138a6e5`. The explicit cast is retained.
