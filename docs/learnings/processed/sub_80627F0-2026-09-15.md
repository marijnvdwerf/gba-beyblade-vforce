## The dead computation: a clamp whose store flow deletes

```c
alignedFrameCount = (_unk3005E40.var08 + 1) & -2;
if (alignedFrameCount > 0x10000) {
    alignedFrameCount = 0x10000;
}
```

`alignedFrameCount` is never read. Flow deletes the dead store in the `if` body,
but not the compare/branch around the now-empty body. That branch survives until
the post-reload jump pass removes it, leaving the rounded load/add/and in the
code, and the compare had already made CSE create the 0x10000 pseudo early (the
target's `mov r3, #0x80; lsl r3, #9` before the TM1CNT load). Plain
`alignedFrameCount = …;` is fully deleted (22 rows), and dropping it entirely gives
20 rows. `== 0x10000 ? _unk3005E18`, `== 0x10000 → 0` and `min(…, 0x10000)` all
behave the same (24 rows before the next fix). `>= 0x10000` or `< 0x10000` change
the constant (43 rows). Reusing another variable instead of `alignedFrameCount`
makes no difference. Kept the plain clamp.

General lesson: a target-only dead computation followed by a missing branch can
be an `if` whose body is a dead store. The body is deleted, but the branch and its
operands outlive flow.
