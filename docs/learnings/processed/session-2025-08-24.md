# Session learnings 2024-08-24

## Switch dispatch: case 2 dummy for 3-case lowering

A 2-case switch (`case 0; case 1`) generates `cmp #0; beq; cmp #1; beq; b` — checks the lower case first, uses two separate `beq` branches.

Adding an empty `case 2: default: break;` triggers 3-case lowering: `cmp #1; beq; cmp #1; blo; b` — checks the MIDDLE value first, then uses carry flag (`blo` = unsigned lower = `bcc`) for case 0 in one comparison. This produces a more compact dispatch that checks case 1 first in the binary while placing case 0 code first in layout.

The case ordering in source doesn't change which case is checked first — the compiler always sorts numerically for switch. The 3-case threshold changes the lowering strategy.

## AllocatedBlock* type prevents global address CSE

When a global is typed `void*`, the compiler aggressively caches its address (`&global`) in a callee-saved register across function calls and loop bodies, producing save/restore `mov` pairs around code that clobbers that register.

Typing the global as `AllocatedBlock*` (a struct pointer) changes the aliasing analysis — the compiler treats struct-typed pointers differently and may reload from the literal pool instead of caching. This eliminated 2 extra `mov` instructions in creditsFrontendHandler.

## sub_80596AC implicit argument reuse

In a switch case 0 where `arg1 == 0`, calling `sub_80596AC(ptr, 0xFFFF0000, 0)` with a constant that was just stored to a global (`_3000004 = 0xFFFF0000`) lets the compiler reuse r1 which still holds the constant, avoiding an explicit `mov r1, #0`. Writing `sub_80596AC(ptr, 0, 0)` instead adds an extra instruction.

## _300000C increment/decrement: precompute pattern

The target precomputes one branch then conditionally overwrites:
```c
s32 next = _300000C - 1;
if (_3000010 > _300000C) {
    next = _300000C + 1;
}
_300000C = next;
```

This produces `sub r3, r1, #1; cmp r0, r1; ble skip; add r3, r1, #1; skip: str r3, [r2]` — a single store after the branch. The simpler `if/else { _300000C++; } else { _300000C--; }` produces different control flow with stores in each branch.

## Pre-decrement in array subscript prevents byte-clean optimization

`((unk32*)array)[--field]` uses the subtraction result directly for both the store and the index, producing `sub; strb; lsl #24; lsr #22` (combined byte-mask + multiply-by-4). Separating into `field--; array[field]` lets the compiler know the value is byte-clean from the `ldrb`, producing just `lsl #2` instead.

## ram.c global alignment matters

A global declared as `unk16` gets 2-byte aligned. If the original code accessed it at an odd byte address (e.g., `0x3000021`), the `unk16` declaration pushes it to `0x3000022`. Fix: declare as `unk8` for byte-addressed globals.

## sub_804ABFC: compiler tail-merging replaces goto

Inlining `sub_804AE34(X, 60)` in every switch case instead of using `goto play` with a shared tail — the compiler's own tail-merging pass recognizes the identical call pattern and emits a shared `mov r1, #60; bl sub_804AE34` block that multiple cases branch to. This produces identical codegen to the goto version without any non-standard C constructs, and also naturally prevents case merging for cases with the same value (both case 0 and case 3 assign 6).
