# agbcc learnings from `sub_806306C`

These observations are specific to matching `sub_806306C` at `0x0806306C`. The general agbcc guidance on signedness, liveness, loop shape, temporaries, and long-lived global addresses is already covered in `SKILL.md`; this note records the concrete source shapes that mattered here, including one case where a natural loop spelling did not reproduce the target's rotated CFG.

## Concrete rules

- **When a rotated list-search CFG is visible, a plain two-pointer `while (condition)` may be too high-level for agbcc.**
  - **Asm symptom:** The target was 0x88 bytes and had an entry path that loaded the first successor, then a shared loop block that moved the successor into the current pointer, tested `current == NULL` and `gap >= size`, loaded another successor, and repeated. The target's registers were `r5=size`, `r6=block`, `r7=atHead`, `r3=cur`, `r4=next`, and `r1=gap`.
  - **C change tried:** The natural form
    ```c
    while (next == NULL || gap < size) {
        cur = next;
        if (cur == NULL || gap >= size)
            break;
        next = cur->next;
        if (next != NULL)
            gap = next->offset - (cur->offset + cur->size);
    }
    ```
    was tested directly.
  - **Result:** It generated `block` in `r4` instead of `r6`, the list head value in `r2` instead of `r3`, `atHead` in `r6` instead of `r7`, and the global address in `r7` instead of `ip`. Its body was shorter (the function ended at about 0x7c bytes rather than the target's 0x88), with different branch targets and no target-equivalent rotated block.
  - **Why:** In this case, the desired rotated CFG was not recovered from the natural top-tested loop spelling. The target's loop rotation had to be represented explicitly in C (inferred from the controlled codegen experiments), even though that source looks less elegant.

- **Changing only `while` to `for (;;)` does not necessarily recover the rotated CFG.**
  - **Asm symptom:** The unconditional-loop variant still allocated `block` to `r4`, the head value to `r2`, `atHead` to `r6`, and the global address to `r7`; it also emitted an extra `mov`/`cmp`/branch sequence around the repeated successor value. The total length happened to return to 0x88 bytes, but instructions and control-flow targets still differed.
  - **C change:** The same loop body was placed under `for (;;)`, retaining the pre-loop `if (next == NULL || gap < size)` guard.
  - **Why:** Loop spelling and the number of live pointer pseudos jointly affect both CFG lowering and allocation. Matching size alone is not evidence of a match; compare every instruction and branch target.

- **A `candidate` temporary can preserve two distinct successor roles.**
  - **Asm symptom:** After `cur = next`, the target loaded `cur->next` into `r2`, copied it to `r4`, tested the original loaded value, and used it for the next gap calculation. The initial/moving successor role remained in `r4`, while the newly loaded candidate used `r2`.
  - **C change:** Keep both roles explicit:
    ```c
    candidate = cur->next;
    next = candidate;
    if (candidate != NULL) {
        gap = candidate->offset - (cur->offset + cur->size);
    }
    if (candidate != NULL && gap >= size)
        break;
    ```
  - **Why:** With only `cur` and `next`, agbcc coalesced the values and used the wrong pointer registers. The extra temporary is not a register pin; it preserves the target's live-range and use pattern.

- **The head-insertion flag is genuine source state, not an optimization artifact.**
  - **Asm symptom:** `r7` is cleared before the first offset is tested, set to one only when the first block can satisfy the request, and later tested separately with `cmp r7, #0` and `cmp r7, #1`.
  - **C change:** Retain an explicit `unk32 atHead` (or equivalent 0/1 flag), set it in the first-block branch, and use it in both post-search dispatch tests.
  - **Why:** Removing or folding the flag changes the fall-through and insertion-vs-head-dispatch CFG. The target uses the flag to distinguish head insertion from insertion after the current block.

- **Signed list offsets and requested sizes are proven by the branch family.**
  - **Asm symptom:** The comparisons use `blt`/`bge`, not unsigned branches, for the first offset, inter-block gaps, and final dispatch.
  - **C change:** Use `s32` for `ActorBlock.offset`, the `size` parameter, and `gap`.
  - **Why:** The signed conditional branches prove signed comparison at these operations. This is stronger evidence than the fact that the fields are plain 32-bit words.

- **A separate initial-distance pseudo is useful as a register-pressure diagnostic, not necessarily as final source.**
  - **Asm symptom:** Introducing a distinct `distance` value for the first-block test while keeping a separate `gap` reproduced the target's prologue pressure: `size` in `r5`, `block` in `r6`, the head flag in `r7`, and the address of `_unk3005E60` retained in `ip`.
  - **C change:** Temporarily split the initial value and the later gap during allocator experiments.
  - **Why:** The split changed live ranges in the same way as the target and showed that global/argument allocation was driven by source-level liveness. It did not by itself produce the correct `r1` gap and `r3`/`r4` pointer roles, so the final implementation uses the target-compatible gap/pointer structure rather than preserving an artificial distance variable.

- **The address of `_unk3005E60` can remain live in `ip` for the later head store.**
  - **Asm symptom:** The literal address is loaded at entry and copied to `ip`; the head-insertion path later does `mov r0, ip` before storing the new head pointer.
  - **C change:** Keep the direct initial `_unk3005E60` read and the later direct `_unk3005E60 = block` assignment in the same function; do not introduce a separate pointer-to-global alias as a source-level workaround.
  - **Why:** The compiler can retain the global's address across the search and reuse it for the later store. The exact mechanism is inferred from the live address and the matching direct-global source shape.

## Timeline of attempts

1. Read the caller in `sub_8062EFC`, the dump, and the surrounding `ActorBlock` users; established that the function searches an address-ordered block list and returns an insertion offset or `-1`.
2. Changed the relevant offset field and parameter to `s32` after confirming `blt`/`bge` in the target.
3. Tried a two-pointer implementation with separate distance/gap values. The prologue pressure was close, but `cur`, `next`, and `gap` landed in the wrong registers.
4. Added the separate successor roles and `candidate` temporary. The explicit rotated form matched every instruction and the 0x88-byte function layout.
5. Tested the proposed natural `while (next == NULL || gap < size)` form. It changed the register allocation and shortened the CFG.
6. Tested the same body under `for (;;)`. It still differed and added a repeated successor check despite matching the overall length.
7. Restored the explicit rotated form, renamed `ActorBlock` fields to `offset`, `size`, `actor`, `prev`, and `next`, and renamed parameters to `size` and `block`.
8. Verified the exact function diff and passed the full ROM compare.
