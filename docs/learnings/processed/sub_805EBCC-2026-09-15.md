# sub_805EBCC (0x0805EBCC, src/camera.c) — MATCHED

Previously parked (processed/sub_805EBCC.md). Two things unblocked it:

1. **Wrong field in the old draft.** Scale is loaded from `layout + 0x28 + i*0x18` =
   `layers[i].unk14` (layers start at 0x14), not `unkC`. With the correct field
   the typed `camera->unk220->layers[i].unk14` emits the target's separate
   `add #0x28; add r3; ldrh` exactly (the "packed table pointer arithmetic"
   hypothesis in the old note was wrong). `s16 scale` gives the deferred
   `lsl/asr #16` after the `record != state` test. Loop idiom copied from the
   matched sibling sub_80522D4 (`for` with s16 `i`, `record = &camera->records[i]`,
   `record != &state->records[0]`).

2. **Tree-level reassociation of the clamp assignments.** Any single-expression
   spelling of `(cols << 11) - (field_40 + 0xF000)` is folded by agbcc into
   `((cols << 11) - 0xF000) - field_40`: pooled `0xFFFF1000`, or CSE reuse of the
   compare's `(rows << 11) - 0xA000`. Measured in a scratch TU, all fold
   identically: `a - b - C`, `a - (b + (unk32)C)`, `-(b + C - a)`,
   `a - (C + b)`, `(240 << 8)`, `* 0x800`, `const s32` local, file-scope
   `static const s32`. Target keeps `mov #0xF0; lsl #8; add field_40; sub`.
   - Constant *locals* (`width = 0xF000; height = 0xA000;`) stop the fold, but
     whichever is assigned first stays live in r10 for the whole function
     (CSE merges repeated sets). That steals sl from the loop's
     `field_40 + field_14` pseudo, which then spills (frame 12 → 16). Best
     result was 186/199 rows.
   - `static inline` clamp helper (plain or with locals): worse, 137 and 158 rows.
   - **Match:** a short-lived edge temp inside each taken arm:
     `right = field_40 + 0xF000; field_14 = (cols << 11) - right;` (same for
     `bottom` with 0xA000). One reused `edge` local also matches; split
     `right`/`bottom` kept for readability (byte-identical).

Byte-required temps (fold-tested): `right`/`bottom` (see above), `actor` (24 rows),
`scale` (65 rows), `record` (126 rows). `state` is the distinct nullsub_12 result.

Asymmetry proven by the target, not a typo: the x upper bound compares against
`camera->unk360 << 8` but assigns with literal 0xF000; the y bound uses literal
0xA000 in both. The x lower bound compares against `camera->unk35C` but clamps to
`-field_40`. No dead code was needed.

Header change: none (camera.c now includes actor.h for the sub_8058754 prototype).
