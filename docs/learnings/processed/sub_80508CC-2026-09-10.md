# sub_80508CC (0x080508CC, src/display.c) — matched 2026-09-10

Previously parked draft (Sub80508CCDraftData / ScreenLayoutDraft views,
`layerIndexShifted = layerIndex << 24` choreography, `clear = 4; clear =
-clear`, hand-written unk74 shifts). Rewritten on real types; matched on
the first build.

Header changes:
- UnkStruct_sub1.var0C: `UnkFrontendTarget*` → `DisplayRecord*` (asm
  indexes it with the 0x88 BGLayer stride and passes it to
  sub_8058968(DisplayRecord*)). Its only other user, sub_8048FFC, read
  `var0C->unkEC` = `var0C[1].var64`; rewritten, 0 rows. UnkFrontendTarget
  (a 0xEC-pad view) deleted.
- ScreenLayout: `layers[4]` at 0x14 and four `unk8 : 2` bitfields at 0x74
  (unk74_0/2/4/6). Evidence: case 0..2 `ldrb; lsl #30/#28/#26; lsr #30`,
  case 3 `ldrb; lsr #6`.

Shapes that fell out naturally (no tricks):
- `layerIndex` (unk16) passed straight to both u8-parameter callees
  (sub_8058968, GetBGLayerCntPtr) produces the target's retained
  `lsl #24` in r10 plus per-call `lsr #24` — the draft's shift temps were
  transcription.
- `((BGControl*)GetBGLayerCntPtr(layerIndex))->unk0_0 = layerMode;` gives
  the `ldrb; and #~3; orr (mode & 3); strb` (precedent: layer.c:835).
- `colorMode != 0 ? 2 : 0` → branchless `neg; orr; asr #31; and #2`.
Byte-required (ROM compare fails without): `records = data->var0C` local,
`record = &records[data->var02 + i]` local.

Historical (resolved the same day by the type-cleanup commit, which unified
the two into `ScreenLayout`): at match time `ScreenLayout`
(display.h, `_806A828[]`) and `LevelDesign` (common.h, `LevelDesigns[]`)
now describe the same 0x84-byte layout — pad0[0x14], `LevelDesignLayer
layers[4]` at 0x14, the 0x74 byte (bitfields in ScreenLayout, plain unk8 in
LevelDesign), pointers at 0x78/0x7C (`unk16*` bgPalette/spritePalette vs
`void*` unk78/unk7C), then var80 vs `LevelGeometryTable* geometry`. Candidate
merge into one type touches camera.c, gameinit.c, background.c.
