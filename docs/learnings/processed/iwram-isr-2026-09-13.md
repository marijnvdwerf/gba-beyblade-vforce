# sub_8757CD0

Matched in `src/iwram.c`; ARM IWRAM ISR at 0x08757CD0 (84 bytes), installed through `_unk3000DF0[6]`. Full ROM compare passed.

The target uses the existing `MultiPlayerState` layout: `_unk3005DC4` is loaded once, `unk3C` is a halfword source cursor, and `unk0` is the byte counter. It performs a halfword post-increment load from `unk3C`, writes `REG_SIOMLT_SEND`, sets bit 7 in `REG_SIOCNT`, stores the incremented cursor back to `unk3C`, then increments `unk0`.

The matching source shape keeps two locals with separate lifetimes:

- `state = _unk3005DC4;`
- `src = state->unk3C;`
- `*(vu16*)REG_SIOMLT_SEND = *src++;`
- `*(vu16*)REG_SIOCNT |= 0x80;`
- `state->unk3C = src;`
- `state->unk0++;`

`src` is byte-required. It produces `ldr r12, [r0,#0x3C]` followed by `ldrh r2, [r12],#2`, with the `str r12, [r0,#0x3C]` delayed until after both volatile register accesses. The direct spelling `*state->unk3C++` was tested first and diverged: it emitted an early cursor store, used `ldrsh` for the source halfword, and shifted the value into `r12`; the explicit cursor local restored the target `ldrh`/register allocation and store order. No value temporary is needed.

ARM-specific lowering measured in the final build: the non-leaf function has the standard `mov ip,sp; stmdb sp!, {r11,r12,lr,pc}` prologue and `sub r11,r12,#4` frame setup; `REG_SIOMLT_SEND` and `REG_SIOCNT` lower through `mov r1,#0x128` plus ARM immediate `add` instructions; `|= 0x80` lowers to `ldrh; orr; strh`. The final body is instruction-identical to the dump, including the literal-pool `_unk3005DC4` word and `ldmdb r11, {r11,sp,lr}; bx lr` epilogue.

The residual-analysis file named by the task was not present under `docs/learnings`; the available ARM reference was the matched `ARM_sub_87569F4` implementation and its compiler output.

# sub_8757E4C

Parked in `src/iwram.c`; ARM IWRAM multiplayer/timer handler at 0x08757E4C (384 bytes). The active build retains the original assembly include and the dump remains present because the C draft was not instruction-identical. `cmake --build build --target compare` passed after restoring the target include.

The best typed semantic draft uses the existing `MultiPlayerState` layout. It caches `unk3` as an `unk8 count`, keeps a separate `unk16 index`, reads `REG_SIOMULTI0` as signed halfwords, writes each received value through a moving byte cursor at the stride in `unk18`, conditionally sets `unk14` bit 0x40 on the nonzero-index 0xFDD9 sentinel, conditionally calls `__fastMemoryCopyARM`, then unconditionally sends -551, sets `REG_SIOCNT` bit 0x80, conditionally sets `unk14` bit 0x80, clears `unk1`, and sets `unk14` bit 0x200.

The first divergence in the closest cached-count candidate is the prologue/register allocation. The target saves `{r4-r8,r11,r12,lr,pc}`; the candidate saves `{r4-r8,r10,r11,r12,lr,pc}`. Target roles are `r8` original count, `r5` loop-bound/count copy, `r0` loop index, `r1` signed received value, `r4` serial-register base, and `r6`/`r7` global-pointer address roles. The candidate instead allocated the count to `r10`, index to `r5`, received value to `r0`, count-copy temporary to `r2`, and the global address to `r8`.

Measured source-shape experiments were not byte-identical: rereading `unk3` directly in the loop moved global/count roles closer but emitted an extra `ldrb` reload; `unk16` and `unk32` count variants changed normalization or allocation; wide-index variants removed the target halfword normalization; explicit casts on the index changed arithmetic and branches; declaration order and initializer spelling did not recover the target allocation; state-pointer aliases and typed halfword cursor variants worsened the output. The target's receive normalization is `lsl #16; asr #16`, proving the signed halfword value path. The target's serial-marker sequence is unconditional after the optional copy. The remaining cast-shaped expression in the parked draft is `*(s16*)destination = value`, a local byte-cursor store; it is not raw struct-offset access but is flagged as a possible artificial shape under the project rules.

The required `docs/learnings/residual-analysis-2026-08-28.md` file was absent from the worktree. No headers were changed for this parked function.

# sub_8757FCC (parked draft)

Parked at ARM IWRAM address 0x08757FCC after the coordinator limit. The best
properly typed draft is retained in `src/iwram.c` immediately above the
unchanged `INCLUDE_ASM` line; the dump remains in the repository.

The draft's first measured divergence is after the matching prologue and the
first two instructions. The target emits `ldr r2, [lr,#0x18]` at offset 0x10,
then `sub r11, r12, #4`; the best draft emits the `sub` first and loads the
packet-size field afterward. The target then retains `unk0` in r4, initializes
its completion flag in r8, loads `unk14`, retains the global address in r6,
and loads the player count from `[lr,#3]` before normalizing the packet size.
The draft instead allocates the flag in r7, retains the normalized packet
half-size in r10, and reloads the player count during loop setup.

Measured ARM experiments, in order:

| change | first divergence / measured result |
| --- | --- |
| Separate player-count local as `unk32` | Added an r9 save and a packet-half stack spill; rejected. |
| Separate player-count local as `unk16` | Still added r9 pressure and did not recover the target early `ldrb`; rejected. |
| Separate player-count local as `unk8` | Recovered byte-width use in some expressions but still added an extra saved register and spill; rejected. |
| Remove the player-count local and read `_unk3005DC4->unk3` directly | Restored the exact target prologue save mask `{r4-r8,r10-r12,lr,pc}`; retained as the best draft. |
| Remove the cached flags local | Did not change the relevant allocation or first divergence; rejected. |
| Use `s16 packetHalf` | Preserved the target signed-halfword normalization `lsl #15` followed by `asr #16`, but did not recover target lifetimes or register roles. |
| Use `s32 packetHalf` | Removed the spill but changed the normalization to an ordinary `lsr #1`; rejected. |
| Split completion increment and status flow into separate statements | Added an unconditional branch where the target reuses the `cmp r8,#0` flags for `beq`; rejected. |

Other measured ARM facts: the target reads each serial word with `ldrh`,
normalizes it with `lsl #16` and `asr #16`, and uses the sentinel value
`0xFDD9`; the receive cursor advances by the even packet-size stride. The
completion arm swaps `unk3C` and `unk40`, clears `unk0` and `unk1`, computes
the copy length as player count times packet-half-size times two, and calls
`__fastMemoryCopyARM`. The final status test reads `REG_SIOCNT` and sets bit
0x80 in `unk14` when bit 0x40 is present. No header fields were added for the
parked draft, and no raw struct-offset dereferences or artificial register
controls were used.

# sub_8757D24

The ARM IWRAM serial receive handler at 0x08757D24 remains parked with its dump retained. The typed draft is inside `#if 0` immediately above the unchanged `INCLUDE_ASM`; it uses the existing `MultiPlayerState` layout and a scratch two-byte destination record local to the disabled draft. No shared header fields were added.

The strongest tested candidate matched the receive loop and post-loop sequence, including the normalized `unk16` index, signed halfword receive normalization, sentinel branch, masked destination stride, state counter increment, `sub_8757CD0` call, completion dispatch, literal pool, and epilogue. It did not match the setup lifetime/register schedule. The target setup is:

```text
ldr     r1, [pc, ...]
add     r3, r3, #67108864
ldrh    r2, [r3]
sub     r11, r12, #4
ldr     r0, [r1]
tst     r2, #64
ldrb    r2, [r0, #3]
mov     r7, r1
ldrne   r3, [r0, #20]
orrne   r3, r3, #128
strne   r3, [r0, #20]
ldr     r3, [r7]
mov     r0, #0
ldrb    r1, [r3, #1]
mov     r5, r2
ldr     r2, [r3, #52]
```

The strongest candidate instead moved `mov r7, r1` ahead of the count load, loaded the count into `r6`, and tested the serial status after that load. The first meaningful divergence was therefore in the setup at the status/count/global-pointer lifetime, before the loop.

Measured probe steps:

| Change | Result |
| --- | --- |
| Baseline typed candidate with state, serial-status, count, destination, and narrow index locals | Loop and post-loop matched; setup diverged at the status/count schedule, with the count in `r6` instead of target `r2`; target `mov r5, r2` was absent. |
| All declaration-order permutations of state, destination, count, index, and value | No permutation matched the target setup; best candidates only preserved the initial three target words. |
| Natural setup-statement permutations for count types `unk8`, `unk16`, and `unk32` | Best prefix was eight target words, but destination materialization occurred before the target status test; no exact setup. |
| Serial-status/count source-order permutations | No exact setup; best candidates again stopped after the first eight target words. |
| Removed the count temporary and used the field directly in the loop bound | Added an unwanted saved register (`r8`) and did not produce target count preservation. |
| Narrow count and halfword serial-status type sweeps | Changed allocation but never produced the target `ldrb r2` followed by `mov r5, r2`. |

The exact sentinel spelling that reproduced the target’s narrowed comparison in the strongest candidate was `(unk16)value == (unk16)-551`; the parked draft keeps the value as `s16` and uses the natural typed comparison `value == -551` rather than retaining a cast-only matching lever.
