# actor.c learnings (2026-09-15)

## actor_8058638 (frame-sequence animation step)

Measured, all byte-compared against the target:

- **Fold the `(s16)` read casts into the field types.** `Actor.unk22` (current
  frame) and `Actor.unk36` (delay adjust) are read with `ldrsh` in compares and
  as an index. Retyping both to `s16` is ROM-neutral for every other user, and
  it also changes how fold associates the frame arithmetic: with `(s16)` casts
  only the odd spelling `frameOffset - 2 + frameCount` matched, with `s16`
  fields the natural `frameOffset + (frameCount - 2)` / `(frameCount - 1)`
  matches. Casts are not neutral w.r.t. commutative operand order.
- **Commutative operand order of `offset + count ± k` is not steered by
  declaration order or local width** (grid over unk16/s16/unk32/s32 and swapped
  declarations: no change). It *is* steered by source parenthesization and by
  the signedness of the other side of the compare.
- **Empty-table test as if/else with the address spelled twice.** Target
  loads `unk8`, computes the scaled displacement, then materializes
  `config + unk18` *before* `config + displacement`. Assigning `frames` first
  and then comparing (either operand order), a separate end pointer, or a
  ternary all computed the start address first. The match is
  `else if (start == end) frames = NULL; else frames = start;`; `else if` and
  a nested `if` inside `else` compile identically. Merging the flag test into
  one `||` condition does not match.
- **No `config` local.** `config = actor->unk0; sequence = &config->...` loads
  `unk0` before the `unk20` index (2 rows off). Spelling `actor->unk0->`
  everywhere gives the target order (index first, one shared load via CSE).
- **Delay: wide staging temp plus a narrow ternary result.**
  `s32 baseDelay = unk34 + unk36; unk16 delay = frames ? frames[i] + baseDelay : baseDelay;`
  gives the target `lsl #16` in the frames arm, `lsl r0, r3, #16` in the other
  and the shared `lsr #16; mov r1, r0`. An if/else assigning `delay` in both
  arms loses the `mov` (5 rows); an `unk16 baseDelay` is far off (14 rows).
- Fold/shape table for the delay (from the matching source):
  | change | rows |
  |---|---|
  | fold `baseDelay` into both ternary arms | 33 |
  | `delay = unk34 + unk36; if (frames) delay += frames[i];` | 16 |
  | if/else storing `delay` per arm | 5 |
  | `unk16 baseDelay` | 14 |
- Retype audit (`Actor.unk22`, `Actor.unk36` → `s16`): C users sub_805000C,
  sub_80501F8, sub_8065334, sub_804D754, renderActor, actor_8057C58,
  ActorSetFrameSequence all diff 0 after the change; ROM compare passes.
  Evidence: actor_8058638 `mov r5,#0x22; ldsh` (index) and `mov r0,#0x22; ldsh`
  before `ble`/`bge`, `mov r3,#0x36; ldsh` for the delay adjust.
- **Blob casts (user decision: keep, with a one-line comment on the struct):**
  `SpriteSheet` (formerly `ActorConfig`) is a variable-length blob. The
  frame-delay table starts right after `sequences[unk8]`, and `unk18` is a
  blob-relative offset. The only matching form compares
  `(const unk16*)&actor->unk0->sequences[actor->unk0->unk8]` against
  `(const unk16*)((const unk8*)actor->unk0 + actor->unk0->unk18)`.
- The `sequence->flag` in the old draft was really `actor->unk33` (the flags
  byte `ActorSetFrameSequence` copies from the sequence data).

## renderActor

- **Duplicate layouts merged first (ROM-neutral commit).** `ActorConfig` was a
  second view of `SpriteSheet` (`extern ActorConfig SpriteSheet_86FAEAC`), and
  `SpriteTrailFrame` was the same 8-byte record as `ActorFrameSequence`.
  renderActor stores `actor->unk0` into `SpriteEntry.unk2C` (`const SpriteSheet*`),
  so merging them removed the need for a cast. `Actor.unk0` is now
  `const SpriteSheet*`.
- Signedness evidence (separate commit, all C users diff 0): `unkA0` read with
  `mov #0; ldsh` → `s16`; `unkA4`, `unkA5`, `unk3B` read as `ldrb; lsl #24; asr #24`
  → `s8`.
- **Constant placement in OR chains comes from fold's `associate`.** For
  `ARG0 | ARG1` where ARG0 splits as `VAR | CON`, agbcc builds
  `VAR | (ARG1 | CON)`. Where ARG1 splits, it builds `(ARG0 | CON) | VAR`. So
  the target's `orr (c, #0x1000)` followed by `orr` into the accumulator comes
  from the plain left-to-right `a | b | 0x1000 | c | d`. Likewise
  `(unk10 & 0xC1FFFFFF) | 0x100 | (index << 20)` gives `(index | 0x100)`
  computed after the masked load. The parenthesized `a | b | (c | 0x1000) | d`
  and `mask | ((index << 20) | 0x100)` both hoist the constant into the left
  group (39–45 rows). Splitting into `&=` then `|=` keeps both stores (42).
- The multiplies are source order `unk10 * unk12` and `unk11 * unk14` (swapping
  gives `ldrb` before `ldrh`).
- The trailing `sprite = actor->unkB8` temp folds byte-identically and was
  removed. Introducing `sprite` before the allocation test costs 36 rows.
- `var20 = 0` and `unk30 = NULL` compile to `strh/str r8` (CSE reuses the
  register known to be zero after `cmp; bne`). No `oldSprite` alias is needed.

## Controlled fold pass (2026-09-15)

All entries below were tested one change at a time with `agbcc -O2` for
`actor.c`, rebuilt, diffed, and checked with the ROM compare target. The source
line numbers in the diff move as locals are removed; addresses identify the
functions.

- `actor_80580C0`: folding the single-use `config` alias into
  `(const unk8*)actor->unk0 + actor->unk0->unk18` is exact. The alias was
  removed.
- `sub_80581B8`: folding the single-use `config` alias into the frame-table
  expression is exact. The alias was removed.
- `sub_80581B8`: folding `frameCount = frameTable[2] - 1` into
  `currentFrame >= frameTable[2] - 1` is exact. The `frameCount` local was
  removed.
- `sub_80581B8`: folding `currentFrame` into the comparison is not exact. The
  first divergence is the load order at the function entry: the target loads
  `actor->unk1E` before `frameTable[2]`, while the folded form loads
  `frameTable[2]` first and loses the target's `r5` lifetime. The local remains.
- `sub_80581B8`: folding `nextFrame` into direct stores and indexing is not
  exact. The first changed region is the boundary arm: the target computes the
  zero/increment value in a register and stores it after the callback test;
  direct stores introduce an extra store/reload and change the frame-table
  pointer register. The local remains.
- `sub_80581B8`: folding the callback `frame = actor->unk1A` snapshot into
  `callback(actor, actor->unk1A)` is not exact. The target keeps the value in
  the saved `r5` register across `actor_80580C0`; the folded form reloads the
  halfword after the callback and drops the saved register. The local remains.
- `ActorSetFrameSequence`: folding the single-use `configFlags` alias into
  `(config->unk7 & 0x10)` is exact. The alias was removed.
- `ActorSetFrameSequence`: folding `endFrame = frameCount + 0xFFFF` into
  `actor->unk22 = frameCount + 0xFFFF + frameOffset` is exact. The alias was
  removed.
- `sub_8058390`: folding the single-use `config` alias into the cursor base is
  exact. The alias was removed.
- `sub_8058390`: folding the single-use `entry` alias into
  `((const ActorSequenceEntry*)cursor)->frames` is exact. The alias was
  removed.
- `sub_8058390`: folding the single-use `frames` alias into the
  `ActorSetFrameSequence` argument is not exact. The folded form changes
  parameter/register lifetimes and adds a callee-saved register; the local
  remains.
- `actor_8058638`: folding `baseDelay` into both ternary arms is not exact.
  The existing wide temporary plus narrow ternary is retained; the prior
  measured first divergence is in the empty/non-empty delay-arm setup.
- `actor_8058638`: changing the two separate upper/lower boundary checks to an
  `else if` is not exact. The first divergence is in the frame-table/sequence
  register allocation and the factored form shortens the function by 0x12
  bytes. The duplicated arms remain.
- `renderActor`: a canonical whole-word `oamAttr` temporary around the existing
  `unk10` OR chain is not exact. It changes the early `Actor*` register from
  `r5` to `r4` and shifts the later OAM stores. The existing scalar whole-word
  expression remains. `SpriteEntry` has no canonical bitfield view of this
  storage; no duplicate overlay view was introduced.
- `renderActor`: replacing decimal screen bounds `239`/`159` with `0xEF`/`0x9F`
  is byte-neutral. The hexadecimal spellings are retained.
- `actor_8058638`: the existing frame-table pointer-view comparison and use
  remains exact. Tested typed cursor and `sizeof` offset alternatives were
  rejected in the earlier pass; the address order and casts are byte-required
  for this target.
