## Source facts the old draft got wrong

- Init stores are direct `_currentGameState->` accesses in the order unk0, 0x6E8
  (halfword), unk6AB, **unk6C0**, unk6BC, unk6EA. The draft missed unk6C0. The
  target reloads the global after each byte store; that is ordinary byte-store
  aliasing, so no scoped `state`/`zero` block is needed.
- The table scan is `for (j = 0; _80788cc[j] >= 0; j++) if (_80788cc[j] == index)
  { found = 1; break; }`. Loop rotation copies the entry test with j = 0, which
  folds `_80788cc[0]` into a direct symbol load at the loop top, while the body
  uses `r6 + j*4`. The draft's `value < 0 || value == index` sets `found` on a
  sentinel exit; the target does not (`blt` skips `mov r1, #1`).
- `&_807582c[index * 0x50]`: loop strength reduction produces the `+0x50` giv (r4);
  the draft's explicit `offset` is unnecessary.

## Debugging leftover

`if (index < 0) found = 1;` is impossible (index runs 0..0x6C), but it is the target's
`cmp r5, #0; bge; mov r1, #1` after the scan. Removing it: 6 rows.

## 0x6E8 width pun: no union needed

`CurrentGameState` 0x6E8 is written with `strh` here (0x08051112) and read with `ldrb`
in sub_805176C. The first commit modelled it as a packed `word`/`b[2]` union. The
follow-up change declares it as a plain `unk16 unk6E8`: sub_805176C returns `u8`,
and agbcc narrows `return _currentGameState->unk6E8;` to a single `ldrb` (no
`ldrh` plus mask). Both functions are at 0 rows, and `u16` and `unk16` both match.
Earlier sessions had split it into `u8 unk6E8; unk8 unk6E9;` for that reader, but the
wide field plus the narrow return reproduces both accesses.
