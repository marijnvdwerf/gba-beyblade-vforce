## Signature and layout facts established

- ABI unchanged: `(LevelGeometryAddresses*, GeometryLine*, Actor*, CollisionResult*)`.
- Accesses this function proves: result `unk0`(s32), `unk4`(s32), `unk8`(s32),
  `unkC`, `unkD`, `unkE`, `unkF` (bytes); line `+0x11` byte, `+0x12` `s16`
  (`ldsh`), `+0x18` (`ldrb`, stored into byte fields — width not proven here);
  actor `x`,`y`,`unk40`,`unk44`,`unk9A`,`unk9C`.
- `CollisionResult.unkC` behaves as **`s8`**: with `unk8 unkC`,
  `result->unkC &= ~1` narrows the constant and emits `mov r0, #0xfe`;
  the target materialises `mov r0, #2; neg r0, r0` (-2), and `mov r0,#3; neg`
  (-3) for `&= ~2`. Measured on isolated probes: `s8` field → negative
  constant (match); `unk8` field → 0xFE/0xFD (mismatch); a wider local
  (`s32 f = r->unkC; r->unkC = f & ~1;`) also yields the negative constant but
  hoists the `ldrb` out of the tail's two arms, which the target does not do
  (it re-loads `unkC` inside each arm). So the field is `s8`, not a temp.
- No field was added to any shared header for this parked draft; the
  `s16 unk12` needed by the draft lives in the draft's scratch struct.

## Three mechanisms found (each measured)

1. **The dead endpoint loads.** The target computes `point0Other`/`point1Other`
   (the *other* axis, `<<5`) into `sl`/`r9` in both arms and never reads them.
   A plain dead assignment is deleted (previous pass's finding, reproduced).
   They survive only when a **comparison of the two values** exists later —
   any of `if (a > b) {swap}`, `if (a > b) b = a;`, `if (a != b) t = a;` keeps
   both loads *and* produces the target's `mov sl,…` / `mov r9,…` form, because
   the compare makes them live at `flow` and everything downstream dies after.
   A swap *inside* the Z-selection else-arm does **not** work (its only use is
   itself dead, so the whole chain goes). Same lesson as sub_8055F04: agbcc
   keeps dead values that were live when `flow` ran.
2. **The `+0x11` test.** The target reads the whole byte and masks:
   `mov r0,#2; ldrb r1,[line,#0x11]; and r0,r0,r1; lsl #24; lsr r3,#24; cmp r3,#0`.
   With the shared bitfield declaration, `direction = line->unk11_1;` emits the
   extraction `lsl #0x1e; lsr #0x1f` (mismatch). `line->unk11_1 * 2` collapses
   to `and #2` in combine but loses the `lsl/lsr #24` pair (145 insns).
   Only `unk8 direction = line->unk11 & 2;` over a **plain byte** at 0x11
   reproduces mask + u8 truncation exactly.
   All six real users of the 0x11 bitfields (`geometry.c` ×2, `collision.c` ×3,
   `riderphysics.c` ×1) are pure `!= 0`/`== 0` tests, and an isolated probe
   shows a 1-bit bitfield *test* compiles to the same `ldrb; and #mask; cmp` as
   a byte mask test — so converting `GeometryLine`'s 0x11 to `unk8 unk11` and
   rewriting those six sites as mask tests is plausibly byte-identical. That is
   a header change across matched functions in three files; not taken
   unilaterally. **Manager decision needed.**
3. **`result->unkD = 0` in the Y arm.** The target's `strb r3, [r5, #0xd]`
   reuses the register that holds `direction` because cse knows it is 0 on that
   edge. Writing `result->unkD = direction;` is byte-identical here.

## Remaining divergence (identical for every variant below)

Instruction 58/147, the Y arm's line-pointer copy:

    target   strb r3,[r5,#0xd] / mov r1, r8 / ldrb r0,[r1,#0x18]
    draft    strb r3,[r5,#0xd] / mov r3, r8 / ldrb r0,[r3,#0x18]

and the knock-on permutation: X arm materialises `mov r1,#0` at the top of the
block instead of after the `ldrb` (so its scratch also becomes r3);
`point1Z` gets r4 instead of r7 (with the else-arm's two `ldr/lsl` pairs in the
opposite order); `range` gets r7 instead of r4; the interpolation index
constant lands in r4 instead of r6. Everything else — all 147 opcodes, all
offsets, both `mov sl`/`mov r9` dead stores, the whole flag logic — matches.

Working hypothesis: agbcc joins the three `mov rX, r8` line copies into one
allocation quantity; in the target the X arm's zero is materialised late so r1
is free for that quantity, in the draft the zero is hoisted to the top of the X
arm and occupies r1, pushing the quantity to r3. The hoist is a scheduling
choice; no source shape tried moved it.

## Rule-conflicting shapes in the parked draft (manager decision)

- The keeper `if (point0Other > point1Other) { swap }` is dead code whose only
  purpose is to keep two dead loads alive. Some comparison of that pair is
  *required* by the target's codegen, but its exact source form is unknowable
  from the binary; every form measured is equivalent.
- The draft reads `line->unk11` as a whole byte, which the shared
  `GeometryLine` does not expose (bitfields `unk11_0..unk11_4`). See
  mechanism 2 for the measured evidence and the proposed header change.

## Method

Variants were compiled straight through `tools/agbcc` in a scratch TU that
includes the project headers (same flags as the build: `-mthumb-interwork -O2
-fhex-asm`), 3–6 full-function variants per compile, and compared against the
dump with a small normalising differ. 20 compiles total, one ROM build to
verify `compare` after parking.
