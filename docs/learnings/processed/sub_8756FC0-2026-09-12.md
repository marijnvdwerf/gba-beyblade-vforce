# sub_8756FC0 — 2026-09-12

## Target and semantics

ARM routine at ROM 0x08756FC0, 0x3C0 bytes, hosted in src/iwram.c. Reachable through the __sub_8756FC0 data pointer from mainLoop. Compiled callers are the assembly sub_8059310 and sub_8059188; the disabled C draft of sub_8059310 also shows the seven-argument copy interface. Arguments are layer, map x/y, destination x/y, width, height.

The target performs direct or compressed tile-row copies into background screen memory. It wraps vertical source rows when field_7C bit 2 is enabled, otherwise checks row bounds before choosing decode or fill. Destination x wraps at 1 << field_5F. Destination y is masked by (1 << field_60) - 1.

Two non-obvious behaviors are present in the target and preserved in the draft: row-offset lookup occurs even on the invalid-row path, and the second direct-copy source address adds split without doubling it (sub_8756FC0+0x2F8), while the byte count is doubled. No attempt was made to repair these behaviors.

## Draft generation and type evidence

The required m2c invocation first failed because the IDA-style loc_/off_ names were treated as separate functions. A temporary copy with .L-prefixed labels parses. ARM frame-pointer stack arguments and indirect BX calls remain incompletely reconstructed by m2c, so its output is only a semantic aid.

Row indices and row count use signed BGE/BLT/BMI tests. Horizontal wrapping uses BLS and a wide unsigned screen-width/masked-destination expression. The header halfword at offset 0x1A supplies the fill value. The row table contains 32-bit relative offsets; each row stream begins two bytes after its row record base and the decoder reads signed halfword run counts.

Using an unk16 final parameter on __sub_8757494 with a wide fill local produces the separate loop-invariant copy stored at fp-0x54; an unk32 final parameter omits it and reduces the frame by four bytes. Narrowing the fill local itself produces additional differences. The decoder's own assembly reads the argument with LDRSH; the caller-visible unsigned halfword view is the measured form here, not a claim about the eventual decoder definition.

## Initial experiments

Temporary aliases for stride, initial offset, and header do not by themselves solve the first difference. A void source pointer and a numeric source-address experiment likewise did not help; the draft retains a typed byte pointer.

For/while/do-while spelling, cached loop end, a next-row local, and swapping source advancement with row increment change stack slots and loop-tail reload combining but have not resolved the mismatch. Independent initialization ordering recovered the exact prologue and initial address calculation; detailed final results will be recorded when the draft is finalized.

## Later loop recovery

Staging the non-wrapping validity test in a local (`valid = row < rows; if (row < 0) valid = 0;`) preserves the target CMP/MOVGE/MOVLT sequence. The conjunction can instead become MVN plus LSR #31 followed by a comparison after initialization order changes.

Moving the row declaration after destinationRow fixes the loop-invariant spill assignment: row stride is fp-0x60 and next row is fp-0x64. This removes the combined LDM reload at the loop tail. With that declaration order, every instruction from function offset 0xD0 to the end matches; the draft and target are both 0x3C0 bytes. The residual starts at +0x3C: two conditional flag MOVs are scheduled ahead of the source/destination/column setup instead of at +0x60/+0x64.

The independent-initialization search tested 180 orderings before the row-declaration fix and 66 afterward; the latter found no improvement to the 34 differing setup rows. Folding columns, rows, compressed, fill, rowMask, rowData, destinationRow, split, rowOffsets, and screenWidth individually did not improve the match. Explicit if/else and preinitialized flag forms did not solve flag scheduling. A halfword source pointer with a byte cast for the split copy is byte-equivalent to the retained byte pointer and offers no benefit.

## Final status: parked

An additional 111 independent initialization orderings (including source and destination setup) did not improve the 34-row residual. A separate screen-width snapshot regressed the prologue. Narrow flags did not match either. No rule-breaking exact match was found.
