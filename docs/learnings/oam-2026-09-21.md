# oam_8756CC0 — 2026-09-21

Matched the 768-byte ARM function at US 0x08756CC0 entirely in C in
`src/iwram.c`. No inline assembly, register declarations, or flag changes.

## Layout and semantics

- Eight-byte OAM entries contain a packed word at +0 and attr2 at +4.
  The old parked draft incorrectly placed attr2 at +6 instead of +4.
- Affine matrices occupy four OAM entries: halfword coefficients at +6,
  +0xE, +0x16, and +0x1E. `OamAffine` models this 32-byte hardware block.
- `SpriteRotationScaleEntry.oamAddr` remains an `unk32`; `SpriteVRamFree`
  walks the hardware addresses as an integer from `OAM` in 0x20-byte steps.
  The five address-to-integer casts in `renderActor`, `sub_8060F64`,
  `showString`, and `sub_8061684` therefore remain absent. In `oam_8756CC0`,
  converting once to a local `OamAffine*` before the four stores remains
  byte-identical. All consumer changes are covered by the full ROM checks.
- `_unk3005DE4` is now also a `SpriteEntry*` at its definition in ram3.c.
- The low-VRAM warning is followed by an unconditional image upload. The
  parked draft incorrectly skipped the upload in that branch.
- After freeing old VRAM, the frame number is reloaded from the sprite.
  The target likewise reloads the character number before writing attr2.
- Signed x/y comparisons and ASR establish signed coordinates. The size
  products also use ASR. The local `flags` supplies the unsigned view for
  LSR #30 while the existing shared sprite field remains signed.

## Measured source shapes

- Two products staged before their adjustments initially recovered the target
  MUL/RSB order. They both folded away once the surrounding function matched.
- The first culling pair is a bitwise OR of comparisons, followed by a logical
  OR with the upper y bound. Operand order selects the target condition codes.
- `while (count-- != 0)` for hiding unused OAM entries recovers the decrement
  hoisted before the upload loop and the counter spill at fp-48. An explicit
  predecrement followed by a do/while instead kept the count in a register and
  spilled the upload flag.
- One shared local initialized to 1 supplies both tile-size shifts. Replacing
  it with literal 1u removes four bytes and changes the upload argument from
  variable shift plus LSL/LSR normalization to a shift of 0x10000.
- Writing affine coefficients through four indexed `OamEntry` elements made
  this ARM compiler retain separate offset registers. Named fields in the
  complete affine-block type recover direct halfword stores.

## Variable folding

Each accepted candidate was tested with the full US SHA1 compare. Removed:
frame, oldFrame, uploadSize, affine pointer, rotationScale pointer, xMask,
adjustedHigh, adjustedLow, attr, character, tableValue, and the first-pass
assignment to attribute2. The second-pass attribute2 alias remains.

Retained after measured rejection (offsets relative to oam_8756CC0):

| Candidate | Size | First differing instruction |
| --- | ---: | ---: |
| Replace shared one with 1u | 764 (-4) | +0x8, changed pool displacement |
| Read sprite->unk10 directly instead of unsigned flags | 768 | +0x34 |
| Fold second-pass attribute2 to oam->attr2 | 764 (-4) | +0x8 |
| Fold first-pass destination to oam fields | 756 (-12) | +0x8 |
| Keep destination alias but make it OamEntry* | 768 | +0x104 |

The typed destination trial differs in exactly two instruction words:
STR loses postincrement and STRH gains the +4 offset. Thus the retained
first-pass form is `*destination++ = packed; *(unk16*)destination = attr2;`.
This is the explicit exception to the ordinary struct-only access convention:
it walks the hardware record as a word cursor, then casts to halfword width.
No integer byte-offset dereference or inline assembly is used.

An initial attr-fold trial was invalid after xMask had already folded; it was
corrected and rerun successfully. Failed experiments were rolled back.

## Validation

US and EU full-ROM SHA1 comparisons both passed after formatting and
removing the assembly inclusion. `tools/update-expected us` correctly skipped
the shared baseline symlink.
