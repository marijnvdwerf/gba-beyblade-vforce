### `done` is a genuine flag, not a constant (2026-09-18)

- Replacing `return;` in the `case 0`/`case 0xFF` arm with `done = 1; break;` is byte-identical. agbcc dead-stores the `done = 1` (the break leaves the loop, so the value is never read) but keeps `while (done == 0)` as a real `mov r0, r10`/`cmp`/`beq` bottom test, because the only initialization dominating the loop sits *before* the `arg3` guard.
- Placement of `done = 0` is load-bearing. Moving it inside the guarded block (immediately before `ptr = buffer`) lets agbcc prove the flag constant and fold the loop to an infinite one: 96 instructions / 192 bytes instead of 98 / 194, and the surviving `movs r0, #0` is shared with the hoisted terminator zero.

### `unk8 zero` could not be removed (18 variants measured, 2026-09-18)

- Target preheader, between the guard's `beq` and the loop top, is exactly `movs r0, #0` / `mov r8, r0` / `add r2, sp, #4`. The zero register is materialized *before* the buffer-cursor initialization.
- With `*ptr = '\0'` written directly, agbcc still creates the same zero pseudo in the same register (r8) and still emits 98 instructions / 194 bytes, but places it *after* `add r2, sp, #4`. First divergence is that two-instruction swap; everything else is equal.
- Cause: the zero becomes a loop movable, and gcc 2.9's `move_movables` inserts hoisted insns immediately before the `NOTE_INSN_LOOP_BEG`, i.e. always after every source statement in the preheader. Nothing expressible in source can push a hoisted insn ahead of `ptr = buffer`.
- Variants that all reproduce the identical two-instruction swap (same size, same instruction count, same register allocation): `do`/`while`-top/`for (; done == 0;)`/`for (ptr = buffer; done == 0;)`/`for (;;)` with a tail `if (done != 0) break;`; `return;` versus `done = 1; break;`; `if (a && b) { … }` versus `if (a == NULL || *a == 0) return;`; `*ptr = '\0'` versus `ptr[0] = '\0'`; declaring `done` last.
- Variants that diverge further: `*ptr = done` reusing the flag as the terminator collapses both high registers into one (186 bytes, 94 instructions); `case 0xFF: ch = 0;` falling through to `case 0` and storing `ch` does the same (186 bytes); `buffer[0] = '\0';` as the first guarded statement adds a live `strb` (200 bytes); `unk8* ptr = buffer;` as a declaration initializer moves `add r3, sp, #4` into the prologue and changes the cursor register.
- Swapping the roles (`zero` initialized before the guard, `done` inside it) keeps size, instruction count and shape exact but exchanges `r8` and `r10`: high-register assignment follows declaration order, not assignment order, so the first-declared of the two gets `r8`.
- Conclusion: the only accesses to the r8 pseudo are the three `*ptr = <var>` stores and its single `= 0`, so any matching form necessarily contains a variable agbcc can prove constant. `unk8 zero` stays, flagged.
