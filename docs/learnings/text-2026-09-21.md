# src/text.c — 2026-09-21

## sub_805B280 (0x0805B280) — matched

Glyph-row blitter: ORs one 8x8 glyph tile's rows into up to four destination
tiles (the 2x2 tile neighbourhood the glyph can straddle), shifted horizontally
by `x & 7` pixels and vertically by `y & 7` rows.

### What made it match

Four things, all lifetime/liveness shaping; the parked draft already had the
loops and the argument setup right and diverged at 0x12.

1. **Both parameters are reused as working variables.** `x &= 7; ... x <<= 2;`
   and `y &= 7;`. Evidence in the target:
   - `mov r1,r9 / and r1,r0 / mov r9,r1` then later
     `mov r0,r9 / lsl r0,#2 / mov r9,r0` — the AND result is written *back* into
     x's register and the `lsl` is a separate statement several instructions
     later (a single `xShift = (x & 7) << 2` emits `and`+`lsl` adjacently, 4
     insns, and gives the shift its own allocno).
   - A separate `xShift` local (`split_xShift`) spills `x` to a third frame slot
     (`sub sp,#12`); a separate `yOffset` local (`split_yOffset`) keeps xTile in
     a register and reloads y from `[sp,#0x28]` twice.
2. **`xTile = x >> 3` is computed before the bounds check**, because `x` is
   destroyed later. The store `str r1,[sp,#4]` sits in the entry block ahead of
   `cmp r0,#0x98`, which no pass can produce from a later statement.
3. **Both loop counters are computed before the first loop**
   (`topCount = 8 - y; bottomCount = y;`). This is what makes `y` win a callee
   saved register (sl) and `xTile` spill — the intended allocation. Reason
   (from `.greg`): priority is `floor_log2(n_refs) * n_refs / live_length`.
   With `bottomCount = y` *after* loop 1, y's allocno is refs=7,
   live_length=66 → 0.212, below xTile's refs=9, live_length=90 → 0.30, so
   xTile takes the register. Hoisting the assignment shortens y's live range to
   ~45 insns (7 refs) → 0.31, just above xTile, flipping both. Moving it back
   (`move_bottomCount`) diverges at insn #5 (frame size).
4. **The right half is computed in place on `pixels`**
   (`left = pixels << x; pixels >>= invShift;`). The target's
   `mov r1,r2 / lsl r1,r0 / lsr r2,r0` reuses the `pixels` register for the
   shifted-right value. A third `right` local (`unfold_right`) makes the ldmia
   load into r0 and steals r7 for a scratch, which spills `bottomRight`.

`invShift = 0x20 - x` must be its own local: inlined, loop-invariant motion
computes it once per loop preheader (2 extra insns, `fold_invShift`, len 131).

### Signedness evidence

- `x` is `s32`: `asr r1,r1,#3` for `x >> 3` and `blt` for `xTile >= 0`.
- `y` is unsigned (`unk32`): `cmp r0,#0x98 / bhi`.
- `(unk32)(x + 7) > 0xF6` — `bhi` on the sum, i.e. the single unsigned test for
  `-7 <= x < 240`.
- `xTile` is `s32`: `blt` (>= 0) and `bgt` (<= 0x1C) are signed.

### Header change: `Tile4bpp`

`typedef unk8 Tile4bpp[0x20]` → `typedef unk32 Tile4bpp[8]` in `src/common.h`.
Same size (0x20) and same pointer stride, so every user (`RiderTile`,
`RiderTileRow`, camera/gameloop/rider) is byte-identical — the full US compare
passes with all 88 objects rebuilt. It is what the matched code proves: the
blitter's third parameter must be the word cursor *itself* (see below), and
`sub_805B270`'s result is used as a `unk32*` row pointer. With the array
element typed as `unk32`, `*sub_805B270(...)` and `*data` decay to `unk32*`,
removing five casts (four in this function, one at the call site in the already
matched `sub_805B41C`).

The third parameter cannot be `const Tile4bpp*` with a cast to a local word
cursor inside: any copy (`data = (const unk32*)glyph;`) moves the spill store
`str r2,[sp,#0]` out of the parameter-setup block (target has it at insn #8,
between `adds r7,r1,#0` and `mov r9,r3`), so the spilled pseudo has to be the
incoming parameter.

### Tooling note

A scripted probe (splice a candidate body into `src/text.c` in a temp dir,
compile with the project's agbcc flags, disassemble both objects and compare
instruction lists, plus a register-normalised "shape" distance) made a
40-variant matrix cheap; `tools/asm-annotated.py`'s `.greg` "Registers to be
allocated in sorted order" block gave the refs/live_length numbers that
explained the spill choice and pointed at change 3 above.
