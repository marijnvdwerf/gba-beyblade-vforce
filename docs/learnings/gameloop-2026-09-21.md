## sub_8052180 (0x8052180)

### The second parameter is `Sub8052140Data*`, not `Actor*`

The previous park typed it as an ad-hoc `ActorEffectActorDraft` "view" of
`Actor` because `Actor` has no named fields at 0x24/0x26/0x34. Checking what
`Actor` actually holds there shows the `Actor` reading is impossible:

* `strb` at +0x24 and +0x26 (`add r1, r1, #0x24` / `#0x26`, both > the 5-bit
  `strb` immediate range, hence the separate `add`).
* `sub_805A1DC(tmp2, arg1 + 0x34)` writes **nine** words, i.e. 0x34..0x57.
  In `Actor` that range is `unk34`(u16 anim delay, set in actor.c:381/499),
  `unk36`, `unk38`/`unk39`/`unk3A`/`unk3B` (sprite flags, actor.c:61/142),
  `unk3C` (`BGLayer*`, written in gameloop.c:614/667 and collision.c:529) and
  `unk40`..`unk54` (velocity/acceleration, actor.c:40-45, 544-583). A 3×3
  matrix there would destroy all of them.

`Sub8052140Data` (src/ram.h) matches exactly and with no conflicts:
`unk8 unk24` @0x24, `unk8 unk26` @0x26, and `unk8 pad34[0x24]` @0x34 — a
36-byte hole that is precisely nine `s32`. `sub_8052140` initialises the same
two bytes (`unk24 = 0x81`, `unk26 = 0`), and `sub_80520F4`'s `arg3->unk1A`
store lands on `unk16 unk1A` @0x1A. So `sub_80520F4`'s `arg3` and
`sub_8052180`'s second parameter are both `Sub8052140Data*`.

Header changes this implies (reverted with the park, per the
"no header field for a parked draft" rule; re-apply when it matches):
* `src/ram.h`: `unk8 pad34[0x24]` → `s32 unk34[9]`.
* `src/common.h`: `RiderBase.unk6C` `unk32` → `s32`.
* `src/gameloop.c`: `sub_80520F4`'s `arg3` and `ActorEffectCallbacks.unk34`/

### Byte-required source shapes found this session

1. **`index = phase - 1;` as its own statement.** Written as one expression,
   `(angle - (phase - 1)) & 0xFF` is folded by gcc to `(angle + 1) - phase`
   and emits `add r0,r6,#1 / sub r7,r0,r2`. Split across two statements it
   emits the target's `sub r0,r3,#1 / sub r0,r2,r0`. The value `phase`
   (`unk16C`) stays live for the fourth lookup (`and r3,r5`), so it is one
   load, not two.
2. **`index += 0x40;` between the sin and the cos read.** A direct
   `table[index + 0x40]` folds the scale into the constant and emits
   `lsl #1 / add #0x80`; the target recomputes `add #0x40 / lsl #1 / add r4`.
3. **`angle = (unk8)~angle;`** — three instructions (`mvn`, `lsl #24`,
   `lsr #24`). `~angle & 0xFF` would be `mvn` + `and` (two), and `angle ^ 0xFF`
   would be `eor`.
4. The initial mask is `~(...) & 0xFF` (emits `mov #0xff` + `add rX,r5,#0` +
   `bic`), not a `(unk8)` cast (which would be `lsl/lsr`).

### First divergence and what remains

With the draft in place the diff is: `sub sp,#128` vs `sub sp,#132` at offset
0x0a, then `mov sl, r1` vs `str r1,[sp,#124]`. Every *instruction shape* after
that is identical; the whole delta is:

| target | draft |
|---|---|
| parameter spilled to `sp+0x7c`, reloaded 3× | parameter in `r10` |
| `sin1` spilled to `sp+0x80` (`str r6` / `ldr r7`) | `sin1` in `r4` |
| `cos1` in `r8` (`mov r2,r8` before the store) | `cos1` in `r5` |
| `tmp1` address in `r6` across the calls | `tmp1` address spilled to `sp+0x7c` |

Net: target 162 instructions / 5 spill slots, draft 160 / 4.

Root cause, from the `.greg` dump (`uv run tools/asm-annotated.py`): the target
holds `table` in `r4` and the `0xFF` mask in `r5`, so when `gameData` dies at
the `unk6C` load neither `r4` nor `r5` is free and both `sin1`/`cos1` become
homeless — that forces a fourth sin/cos value into the high registers
(`r8/r9/r10/r12` all taken by `cos2`/`cos1`/`sin3`/`cos3`), which in turn
leaves no call-saved register for the parameter. The draft's allocator puts
`table` in `r3` and the mask in `r1`, `gameData` in `r4`; `r4`/`r5` free up and
absorb `sin1`/`cos1`, leaving `r10` for the parameter. Same number of
long-lived values on both sides (5 low-reg residents + 3 scratch) — the target
simply needs one more simultaneously-live value than any natural spelling of
this source produces.

### Changes that recovered the frame and allocation

1. Use separate `unk32` indices for the first three sine/cosine pairs; mutate
   `phase` directly for the fourth pair. Sharing any two of the three indices
   changes allocation (20 differing rows in each measured pairwise merge).
2. Keep the original wide `angle` unchanged. Narrow its complement at the two
   final lookups with `(unk8)~angle`, instead of assigning the narrowed result
   back to `angle`. Combined with the separate indices, this recovers the exact
   132-byte frame, the argument spill at sp+124, the sine spill at sp+128, and
   the target table/mask registers. That candidate had 28 differing rows.
3. Stage `phase - 1` in `index`, then calculate the first lookup index in a
   different local. This fixes the first lookup's r0/r1 allocation and leaves
   17 differing rows, all starting at offset 0xF8 in quaternion-buffer allocation.
4. Initialize the last quaternion with `s32 q3[4] = { 0, sin3, 0, cos3 };`
   inside a late C90 block containing the helper calls. This recovers the target
   q2/q3 buffer register order (r5/r4) and gives zero differing instructions.
   Initializing all four quaternions with aggregate initializers instead leaves
   six register/spill differences, starting at 0x46.

The scoped initializer is the retained source-shape compromise under the user's
permission for light rule breaking. It is marked `// TODO: fakematch?` above the
function. No `register`, inline assembly, volatile tricks, forced registers, or
compiler flag changes were used. The scope permits a runtime array initializer
at its required position while keeping declarations C90-compatible.
