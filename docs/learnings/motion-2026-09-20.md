# motion.c — sub_80502A4 (0x80502A4) retry

Matched. ROM SHA1 `cd527c8c24e20e33913fc45199e64b3e6138a6e5`.

## The parameter type was wrong, not the field width

`sub_80502A4` was declared `void sub_80502A4(FrontendMotionData*)`. That is a
different struct. Proof from the two disjoint layouts:

- `FrontendMotionData` (the const ROM parameter tables `_8068840`, `_8068890`
  and `FrontendSubobjectData.unk24/unk28`): frontend.c/menuobject.c feed
  `unk0..unkC` to `sub_80504E4`, `unk10..unk1C` to `sub_805052C`,
  `unk20` (word) + `unk26` (s16) to `sub_8050578(MotionGroup*, unk32, s16)`,
  and `unk24` (unk16) to `newMotionGroup` as the mode. So in that struct
  0x20 is a word boundary, 0x24 the mode, 0x26 the restitution.
- The struct `sub_80502A4` walks is the single-object motion state:
  0x00/0x04 position, 0x08/0x0C velocity, 0x10/0x14 acceleration,
  0x18 boundary, 0x1C restitution, 0x20 mode flags read with `ldrh`.

The already-decompiled constructors in the same TU pin that second layout
exactly: `sub_8050284` writes `arg0[6]=0` (boundary), `arg0[7]=0x80`
(restitution, same default `newMotionGroup` gives `UnkMotion.unk14`) and
`*(unk16 *)&arg0[8]` (the mode halfword at 0x20). `sub_8050340(arg0, unk32,
s16)` is the per-object twin of `sub_8050578`. So the `ldrh` at 0x20 needed
no union and no halfword-pair split: the field simply *is* `unk16` in a
struct that was never declared.

New `Motion` typedef added to `src/motion.h`; `packet.c:sub_80439F4` retyped
to `Motion*` (its only field read, `unkC`, stays `unk32` → byte-identical;
full-ROM compare confirms every other TU unchanged). `FrontendMotionData`
itself was left untouched.

## Field signedness (measured)

- `unk1C` is `s32`. With `unk32 unk1C` the restitution line emits
  `lsr r3, r0, #8`; the target has `asr r3, r0, #8` at 0x68. Everything else
  in the function was byte-identical between the two builds, so this is a
  clean one-instruction signedness probe. Mirrors `UnkMotion.unk14` (`s32`).
- `unk20` is `unk16`: both reads are `ldrh` (0x20, 0x56), and it is only ever
  mask-tested.
- `unk0/unk4/unk8/unkC/unk10/unk14/unk18` stay `unk32`; the signed compares
  (`bgt`/`blt`/`bge` on `before`/`after`) come from the `s32` locals, as in
  the already-matched `sub_805041C`.

## What made it match

Starting shape (direct field access, no `mode` cache, `s32 position/velocity/
before/after`) reproduced everything except the last block:

```
target 0x5c  mov r4, r1      (missing)
target 0x6e  mov r1, r5      (missing)
target 0x72  and r0, r4      vs base  and r0, r1
target 0x78  str r1, [r2,#0] vs base  str r5, [r2,#0]
```

Cause: with `position = arg0->unk18;` hoisted above the restitution
`if`/`else`, CSE folds it onto the boundary pseudo already in r5 and copy
propagation puts r5 straight into the stores — one pseudo where the target
has two. Writing `position = arg0->unk18;` *inside both arms* (the exact
shape the matched sibling `sub_805041C` already uses) gives the join block a
real phi: cross-jumping merges the duplicated assignment into `mov r1, r5` at
0x6e, which forces the reloaded flags out of r1 into r4 (`mov r4, r1`) and
makes the final `and`/`str` use r4/r1. Full match, first try after that
change.

Step table:

| change | first divergence | delta |
|---|---|---|
| direct fields, hoisted `position = arg0->unk18` | 0x5c missing `mov r4, r1` | -4 bytes |
| same, `position = arg0->unk18` duplicated in both arms | none | match |
| `unk32 unk1C` (probe) | 0x68 `lsr` vs `asr` | same size |
| `before`/`after` folded into the `if` condition (probe) | compare fails | — |

## Folds tested

- No `mode`/`axisMask`/`collisionMode` locals: the target re-loads `ldrh
  [r2,#0x20]` at 0x56 because 0x56 is a join of two predecessors, so CSE
  cannot carry the first load across. Direct `arg0->unk20` at all four test
  sites is what matches; the parked draft's cached `mode` local was wrong.
- No `boundary` local: `add r5, r0, #0` at 0x44 is produced by plain CSE of
  `arg0->unk18`, no source local needed.
- No `x/y/xVelocity/yVelocity` locals: plain `arg0->unk0 += arg0->unk8;` etc.
  leaves the four updated values in r7/r6/r5/r4 by store-register
  equivalence, which is exactly the target.
- `before`/`after` are byte-required (two uses each). Inlining both
  expressions into the condition fails compare.
